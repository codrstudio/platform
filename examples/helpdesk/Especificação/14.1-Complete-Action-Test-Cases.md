## 🔐 Autenticação e Controle de Acesso

### Entidade: `usuario`

#### select
```json
{ "schema": "sac", "select": "usuario" }
```
→ `200` `JResult<Usuario[]>`

#### select (filtrado)
```json
{
  "schema": "sac",
  "select": "usuario",
  "where": { "ativo": { "eq": true } }
}
```
→ `200` `JResult<Usuario[]>` (todos com `ativo === true`)

#### mutate:criar
```json
{
  "schema": "sac",
  "mutate": "usuario",
  "action": "criar",
  "values": {
    "email": "usuario@test.com",
    "nome_completo": "Usuario Teste",
    "senha": "SenhaTest123!",
    "ativo": true

}
```
→ `201` `JResult<Usuario[]>`

```json
{

```
→ `200` `JResult<Usuario[]>`

## 📝 Notas

### Códigos de Resposta Comuns

- `200` - Operação bem-sucedida (SELECT, UPDATE, DELETE)
- `201` - Criação bem-sucedida (CREATE)
- `207` - Multi-status (operações em lote com resultados mistos)
- `400+` - Erro de validação ou operação inválida
- `404` - Registro não encontrado
- `409` - Conflito (duplicação, já existe, etc.)

### Convenções de Teste

- Payloads utilizam timestamps (`Date.now()`) para evitar duplicações
- Testes sempre limpam ou revertem alterações quando possível
- Operações de leitura não modificam o banco
- Operações múltiplas aceitam códigos variados: `200|201|404|409`
