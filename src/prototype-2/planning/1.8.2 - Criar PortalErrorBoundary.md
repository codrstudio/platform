# Task Plan: 1.8.2 - Criar PortalErrorBoundary

## Context and Objective

This task implements **Portal-Level Error Boundaries**, the second tier in the three-tier error boundary system (Global → Portal → Module). Portal error boundaries isolate errors within individual portals, preventing one portal's failure from affecting others or the global application.

**What will be implemented:**
- Create a specialized `PortalErrorFallback` UI component
- Integrate error boundary at the portal loading level
- Add recovery actions specific to portal errors (go home, reload portal)
- Ensure portal isolation is maintained during errors

**Why it's needed:**
- SPEC-ERR-BOUND-005: Each portal MUST have its own error boundary
- SPEC-ERR-BOUND-006: Error in one portal MUST NOT affect other portals
- SPEC-ERR-BOUND-007: Must display portal-specific fallback UI
- Portal isolation is core to the platform's architecture
- Allows partial recovery without full app reload

**How it integrates:**
- Wraps portal content in `PortalLoader.tsx` (already implemented)
- Sits between global boundary (App.tsx) and module boundaries (future)
- Uses existing ErrorBoundary component with `level="portal"`
- Integrates with existing error logging

**Business value:**
- Improved resilience - one portal failure doesn't crash entire app
- Better user experience - users can navigate to other portals
- Enables multi-tenant scenarios where portal errors are isolated
- Reduces impact radius of bugs

**User impact:**
- Users see portal-specific error page instead of global error
- Can navigate back to home portal without losing work in other portals
- Can reload just the failing portal without reloading entire app
- Clear actionable options for recovery

## Critical Context

### Documentation

**React Router Navigation:**
- [useNavigate Hook](https://reactrouter.com/en/main/hooks/use-navigate)
  - Returns navigate function for programmatic navigation
  - Can navigate to absolute paths: `navigate('/')`
  - Can navigate to relative paths: `navigate('../')`
  - Can replace history: `navigate('/', { replace: true })`

**Error Boundary Best Practices:**
- [Error Boundaries - React Docs](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)
  - Strategic placement: one per major feature/route
  - Portal boundaries prevent error propagation
  - Fallback UI should offer recovery options

### Gotchas and Pitfalls

**Portal Isolation:**
- ⚠️ Portal boundary MUST wrap the entire portal router, not individual routes
- ⚠️ Error in one portal should NOT affect navigation state of other portals
- ⚠️ PortalLoader already has correct boundary placement (lines 70, 78)

**Navigation in Error Boundaries:**
- ⚠️ Cannot use hooks in class components (ErrorBoundary is class-based)
- ⚠️ Must use hooks in functional fallback components (PortalErrorFallback)
- ⚠️ Navigation works because fallback is rendered inside Router context

**Recovery Actions:**
- ⚠️ "Try Again" (resetError) may not fix the issue if error persists
- ⚠️ "Go Home" is safer - navigates away from problem
- ⚠️ "Reload Portal" requires full page reload (same as global)
- ⚠️ Consider showing both "Try Again" and "Go Home" for flexibility

**Portal-Specific Errors:**
- ⚠️ Portal not found errors are NOT caught by error boundary (handled by PortalLoader)
- ⚠️ Module loading errors are NOT caught by error boundary (handled by PortalLoader)
- ⚠️ Only rendering errors in portal components are caught

**Accessibility:**
- ⚠️ Navigation buttons must have clear labels
- ⚠️ "Go Home" might be ambiguous - use "Go to Main Portal" or similar
- ⚠️ Focus management after navigation is handled by React Router

### Error Handling Strategy

**Error Types:**
- **Portal rendering errors:** Caught by ErrorBoundary
  - Display PortalErrorFallback
  - Log with category 'error-boundary', portalId in context

- **Portal loading errors:** NOT caught by boundary (handled in PortalLoader)
  - Portal not found → ErrorState component (lines 36-44)
  - Module loading errors → ErrorState component (lines 57-65)

- **Navigation errors:** Handled by React Router
  - 404 routes → Route-level handling
  - Not error boundary responsibility

**Error Display Pattern:**
```typescript
// Pattern: PortalErrorFallback.tsx
import { useNavigate } from 'react-router-dom';
import type { FallbackProps } from '../../types/errorBoundary';

export function PortalErrorFallback({ error, resetError }: FallbackProps) {
  const navigate = useNavigate();

  const handleRetry = () => {
    resetError();
  };

  const handleGoHome = () => {
    navigate('/');
  };

  return (
    <div
      className="flex items-center justify-center min-h-screen"
      role="alert"
      aria-live="assertive"
    >
      <div className="text-center max-w-md px-4">
        {/* Error Icon - Same as global */}
        <div className="mx-auto mb-4 text-destructive">
          <svg width="64" height="64" /* ... */ />
        </div>

        {/* Title */}
        <h2 className="text-xl font-semibold mb-2">
          Portal Error
        </h2>

        {/* Message */}
        <p className="text-muted-foreground mb-4">
          This portal encountered an error. Try reloading or go back to home.
        </p>

        {/* Actions - Two buttons side-by-side */}
        <div className="flex gap-2 justify-center">
          <button
            onClick={handleRetry}
            className="inline-flex items-center justify-center rounded-md bg-primary px-4 py-2 text-sm font-medium text-primary-foreground hover:bg-primary/90 focus:outline-none focus:ring-2 focus:ring-primary focus:ring-offset-2"
          >
            Try Again
          </button>

          <button
            onClick={handleGoHome}
            className="inline-flex items-center justify-center rounded-md border border-input bg-background px-4 py-2 text-sm font-medium hover:bg-accent hover:text-accent-foreground focus:outline-none focus:ring-2 focus:ring-primary focus:ring-offset-2"
          >
            Go Home
          </button>
        </div>

        {/* Dev Details - Same as global */}
        {import.meta.env.DEV && (
          <details className="mt-6 text-left">
            <summary className="cursor-pointer text-sm text-muted-foreground hover:text-foreground">
              Error Details (Development Only)
            </summary>
            <pre className="mt-2 text-xs bg-muted p-4 rounded-md overflow-auto max-h-64">
              {error.stack || error.message}
            </pre>
          </details>
        )}
      </div>
    </div>
  );
}
```
