# Task Plan: 1.4.8 - Criar hooks useJQELMutation

## Context and Objective

**What will be implemented:**
This task creates React hooks for JQEL mutations (INSERT, UPDATE, DELETE operations) using TanStack Query's `useMutation`. The hooks will provide a type-safe, declarative interface for data modifications with built-in support for optimistic updates, cache invalidation, and error handling.

**Why it's needed:**
While Task 1.4.7 provides hooks for SELECT queries (data fetching), mutations are required for all data modification operations in the platform. These hooks enable:
- Type-safe mutation operations (insert, update, delete)
- Automatic cache invalidation after successful mutations
- Optimistic UI updates for better UX
- Consistent error handling across all mutations
- Integration with TanStack Query's mutation lifecycle

**How it integrates:**
- **Frontend Components**: Use mutation hooks to create, update, and delete data
- **TanStack Query**: Manages mutation state, retries, and callbacks
- **JQEL Client**: Sends mutation queries to `/api/jqel` endpoint
- **Cache Invalidation**: Automatically refreshes related queries after mutations
- **SSE Events** (Future - Task 1.5): Will trigger invalidations from server-side changes

**Business value:**
- Simplified data modification operations for developers
- Consistent UX patterns across all forms and actions
- Reduced boilerplate code in components
- Built-in loading, error, and success states
- Type safety prevents runtime errors

**User impact:**
Users will experience faster, more responsive interactions with:
- Optimistic updates showing changes immediately
- Clear loading states during operations
- Consistent error messaging
- Automatic data refresh after modifications

// File: frontend/src/services/jqel/client.ts (lines 8-28)
export async function jqelQuery<T>(query: JQELQuery): Promise<T> {
  const response = await fetch(`${API_BASE_URL}/api/jqel`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(query),
  });

  if (!response.ok) {
    throw new Error(`JQEL request failed: ${response.statusText}`);
  }

  const result: JResult<T> = await response.json();

  if (!result.success || !result.data) {
    throw new Error(result.error?.message || 'JQEL query failed');
  }

  return result.data;
}
```

### Gotchas and Pitfalls

**TanStack Query v5 Changes**
- `cacheTime` renamed to `gcTime` in v5
- `onSuccess`, `onError`, `onSettled` moved from `useMutation` to `mutate()`/`mutateAsync()`
- Must use callbacks on individual mutation calls, not in hook options
- Breaking change from v4 - affects callback placement

**JResult Data Structure**
- `data` field is ALWAYS an array, even for single record mutations
- For INSERT: `data[0]` contains the created record
- For UPDATE: `data[0]` contains the updated record
- For DELETE: `data` may be empty or contain deleted record info
- Frontend should unwrap array when returning single record

**Mutation Variables Type Safety**
- TypeScript generics needed for type-safe mutation variables
- Variables structure differs by action (insert vs update vs delete)
- WHERE clause required for UPDATE and DELETE
- VALUES required for INSERT, UPDATE, UPSERT

**Cache Invalidation Strategy**
- Too broad: Invalidates unnecessary queries (performance hit)
- Too narrow: Misses related queries (stale data)
- Best: Use query key factory pattern for consistent invalidation
- Example: Invalidate `['backend', 'portal']` after portal mutation

**Optimistic Updates Cleanup**
- MUST return previous data from `onMutate` for rollback
- MUST cancel in-flight queries before optimistic update
- MUST restore previous data in `onError`
- MUST refetch in `onSettled` to sync with server

**Async Error Handling**
- `mutate()` doesn't return Promise (fire-and-forget)
- `mutateAsync()` returns Promise (can await)
- Use `mutateAsync()` for form submissions (need to wait)
- Use `mutate()` for background operations (don't block UI)

### State Management

**TanStack Query Mutation State:**
- `isIdle`: No mutation has been triggered
- `isPending`: Mutation is executing
- `isError`: Mutation failed
- `isSuccess`: Mutation succeeded
- `data`: Mutation result data
- `error`: Mutation error object

**Cache Management:**
- No mutation state persisted across component unmounts
- Query cache invalidated via `queryClient.invalidateQueries()`
- Related queries automatically refetch after invalidation
- Optimistic updates temporarily modify cache (rolled back on error)

#### Step 2: Create Mutation Functions
**File**: `frontend/src/services/jqel/mutations.ts`

**Details**: Create core mutation functions that build JQEL mutation queries and call the JQEL client.

**Implementation**:
```typescript
// File: frontend/src/services/jqel/mutations.ts
// CREATE NEW FILE

import { jqelQuery } from './client';
import type {
  JQELQuery,
  MutationQueryOptions,
  WhereClause,
} from '../../types/jqel';

/**
 * Insert a new record
 *
 * SPEC References:
 * - SPEC-JQEL-MUT-001:003: MUTATE structure
 * - SPEC-JQEL-MUT-004: INSERT action
 * - SPEC-DA-MU-001:004: Mutation function structure
 *
 * @param schema - Schema name (e.g., "backend", "sac")
 * @param entity - Entity name (e.g., "portal", "usuario")
 * @param values - Data to insert
 * @param options - Query options (output projection)
 * @returns Created record
 */
export async function insertRecord<T = unknown>(
  schema: string,
  entity: string,
  values: Record<string, unknown>,
  options?: MutationQueryOptions
): Promise<T> {
  const query: JQELQuery = {
    schema,
    mutate: entity,
    action: 'insert',
    values,
    ...options,
  };

  // SPEC-JQEL-RES-013: data is always array
  const data = await jqelQuery<T>(query);

  // Return first item (single insert)
  return Array.isArray(data) ? data[0] : data;
}

/**
 * Update existing record(s)
 *
 * SPEC References:
 * - SPEC-JQEL-MUT-004: UPDATE action requires WHERE
 * - SPEC-DA-MU-001:004: Mutation function structure
 *
 * @param schema - Schema name
 * @param entity - Entity name
 * @param where - WHERE clause to identify record(s)
 * @param values - Data to update
 * @param options - Query options (output projection)
 * @returns Updated record(s)
 */
export async function updateRecord<T = unknown>(
  schema: string,
  entity: string,
  where: WhereClause,
  values: Record<string, unknown>,
  options?: MutationQueryOptions
): Promise<T> {
  const query: JQELQuery = {
    schema,
    mutate: entity,
    action: 'update',
    where,
    values,
    ...options,
  };

  const data = await jqelQuery<T>(query);

  // Return first item (single update) or all items (bulk update)
  return Array.isArray(data) ? data[0] : data;
}

/**
 * Delete existing record(s)
 *
 * SPEC References:
 * - SPEC-JQEL-MUT-004: DELETE action requires WHERE
 * - SPEC-DA-MU-001:004: Mutation function structure
 *
 * @param schema - Schema name
 * @param entity - Entity name
 * @param where - WHERE clause to identify record(s)
 * @param options - Query options (output projection)
 * @returns Deleted record(s) info
 */
export async function deleteRecord<T = unknown>(
  schema: string,
  entity: string,
  where: WhereClause,
  options?: MutationQueryOptions
): Promise<T> {
  const query: JQELQuery = {
    schema,
    mutate: entity,
    action: 'delete',
    where,
    ...options,
  };

  const data = await jqelQuery<T>(query);

  return Array.isArray(data) ? data[0] : data;
}

/**
 * Upsert record (update or insert)
 *
 * SPEC References:
 * - SPEC-JQEL-MUT-004: UPSERT action
 * - SPEC-DA-MU-001:004: Mutation function structure
 *
 * @param schema - Schema name
 * @param entity - Entity name
 * @param values - Data to insert/update
 * @param where - Optional WHERE clause for update matching
 * @param options - Query options (output projection)
 * @returns Upserted record
 */
export async function upsertRecord<T = unknown>(
  schema: string,
  entity: string,
  values: Record<string, unknown>,
  where?: WhereClause,
  options?: MutationQueryOptions
): Promise<T> {
  const query: JQELQuery = {
    schema,
    mutate: entity,
    action: 'upsert',
    values,
    ...(where && { where }),
    ...options,
  };

  const data = await jqelQuery<T>(query);

  return Array.isArray(data) ? data[0] : data;
}
```

// CREATE NEW FILE

import { useMutation, useQueryClient, type UseMutationResult } from '@tanstack/react-query';
import { jqelQuery } from '../client';
import type { JQELQuery, UseMutationOptions } from '../../../types/jqel';

/**
 * Generic JQEL Mutation Hook
 *
 * For custom actions beyond insert/update/delete.
 * Use specialized hooks (useInsert, useUpdate, useDelete) for standard operations.
 *
 * SPEC References:
 * - SPEC-DA-MU-001:004: useMutation integration
 * - SPEC-JQEL-MUT-006:007: Custom actions
 *
 * @example
 * ```typescript
 * const activateUser = useJQELMutation<User, { userId: number }>({
 *   buildQuery: (vars) => ({
 *     schema: 'sac',
 *     mutate: 'usuario',
 *     action: 'activate',
 *     where: { id_usuario: { $eq: vars.userId } }
 *   })
 * });
 *
 * activateUser.mutate({ userId: 123 });
 * ```
 */
export function useJQELMutation<TData = unknown, TVariables = void>(
  options: {
    buildQuery: (variables: TVariables) => JQELQuery;
    invalidateKeys?: (data: TData, variables: TVariables) => unknown[][];
  }
): UseMutationResult<TData, Error, TVariables> {
  const queryClient = useQueryClient();

  return useMutation<TData, Error, TVariables>({
    mutationFn: async (variables: TVariables) => {
      const query = options.buildQuery(variables);
      const data = await jqelQuery<TData>(query);
      return Array.isArray(data) ? data[0] : data;
    },
    onSuccess: (data, variables) => {
      // SPEC-DA-MU-005:008: Invalidate cache after mutation
      if (options.invalidateKeys) {
        const keys = options.invalidateKeys(data, variables);
        keys.forEach(key => {
          queryClient.invalidateQueries({ queryKey: key });
        });
      }
    },
  });
}
```

**Pattern**: Follows TanStack Query v5 mutation pattern

### Error Handling Strategy

**Error Types:**

**1. Validation Errors (400)**
- Missing required fields (WHERE for UPDATE/DELETE)
- Invalid query structure
- **Handling**: Caught by mutation function, wrapped in Error object
- **Display**: Show in form validation or toast message
- **Example**:
  ```typescript
  {
    code: 400,
    message: "Field 'where' is required for UPDATE",
    field: "where"
  }
  ```

**2. Authorization Errors (401/403)**
- User not authenticated (401)
- User lacks permission (403)
- **Handling**: Returned by backend, mutation fails
- **Display**: Redirect to login (401) or show permission error (403)

**3. Conflict Errors (409)**
- Unique constraint violation
- Duplicate key error
- **Handling**: Backend returns 409, mutation fails
- **Display**: Show error message with field highlighting
- **Example**: "Portal with ID 'main' already exists"

**4. Business Logic Errors (422)**
- Validation rules violated
- Invalid state transition
- **Handling**: Backend/n8n returns 422 with details
- **Display**: Show inline error next to relevant field

**5. Network Errors (503)**
- Backend unreachable
- n8n timeout
- **Handling**: Mutation function throws, TanStack Query retries
- **Display**: Show generic "Service unavailable" message
- **Retry**: Auto-retry with exponential backoff

**Error Display Pattern:**
```typescript

      </Alert>
    )}

  </form>

```
