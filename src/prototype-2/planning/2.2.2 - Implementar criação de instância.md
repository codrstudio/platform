# Task Plan: 2.2.2 - Implementar criação de instância

## Context and Objective

Implement the Instance creation functionality for the Setup Module, allowing administrators to create new module instances with custom configurations. This task provides a form-based interface for defining instance IDs, selecting modules, and configuring instance-specific parameters according to each module's schema.

**Business Value:** Enables administrators to activate and configure multiple instances of the same module with different settings, supporting multi-tenant scenarios and flexible module reuse.

**User Impact:** Users can create custom-configured instances of modules, defining unique IDs and settings for each use case (e.g., "sales-chat" and "support-chat" instances of the chat module).

### Reusable Code Examples

**Mutation Pattern from useInstanceMutations.ts:**
```typescript
// File: src/prototype-2/frontend/src/hooks/jqel/useInstanceMutations.ts
export function useCreateInstance() {
  const queryClient = useQueryClient();
  return useOptimisticMutation<Instance, Instance>({
    mutationFn: async (instance: Instance) => {
      return insertRecord<Instance>('backend', 'instance', instance as unknown as Record<string, unknown>);
    },
    onSuccess: (data) => {
      // Invalidate instance list + portal instances
      queryClient.invalidateQueries({ queryKey: queryKeys.backend.instances() });
      if (data?.portalId) {
        queryClient.invalidateQueries({ queryKey: queryKeys.backend.instances(data.portalId) });
        queryClient.invalidateQueries({ queryKey: queryKeys.backend.portal(data.portalId) });
      }
    },
  });
}
```

**Form Validation Pattern:**
```typescript
// Zod schema for instance creation
const instanceSchema = z.object({
  instanceId: z.string()
    .min(1, 'Instance ID is required')
    .regex(/^[a-z0-9-]+$/, 'Only lowercase letters, numbers, and hyphens'),
  portalId: z.string().min(1, 'Portal is required'),
  moduleId: z.string().min(1, 'Module is required'),
  config: z.record(z.unknown()).default({}),
  active: z.boolean().default(true),
});
```

### Gotchas and Pitfalls

- ⚠️ **Instance ID uniqueness**: `instanceId` must be unique **within the portal**, not globally. Validate against existing portal instances.
- ⚠️ **Module must be active**: Only allow creating instances for modules that are active in the selected portal.
- ⚠️ **Config schema validation**: The `config` field should be validated against the module's schema (task 2.2.5), but for now accept any valid JSON object.
- ⚠️ **Automatic timestamps**: Backend should auto-generate `createdAt` and `updatedAt`, don't send from frontend.
- ⚠️ **Optimistic updates**: The mutation hook uses optimistic updates, so the UI updates immediately while the request is in flight.
- ⚠️ **Toast timing**: Success toast should appear after navigation, not before, to avoid toast being lost during route change.

### Existing Patterns to Follow

- **Form validation**: See SPEC-MS-UI-028:030 - Use React Hook Form + Zod with inline errors
- **Success feedback**: See SPEC-MS-FB-005:007 - Show toast, auto-dismiss after 3-5 seconds
- **Error feedback**: See SPEC-MS-FB-008:011 - Clear errors, field-specific, with suggested solutions
- **Loading states**: See SPEC-MS-LO-002:003 - Disable inputs during save, show spinner on button
- **Navigation**: After successful save, navigate back to instance list for that module

## Technical Specification

### Architecture

```
src/prototype-2/frontend/src/modules/setup/
├── pages/
│   └── CreateInstance.tsx           (Page component: form submission, navigation)
├── components/
│   └── InstanceForm.tsx             (Form component: fields, validation, layout)
├── validation/
│   └── instanceSchema.ts            (Zod schema for validation)
└── routes.ts                        (Route definition)

Data Flow:
User navigates to: /setup/portals/:portalId/modules/:moduleId/instances/new

CreateInstance.tsx:
  1. Extract portalId, moduleId from URL params
  2. Fetch active modules to validate moduleId
  3. Render InstanceForm with initial values
  4. On submit: call useCreateInstance mutation
  5. On success: navigate back to instance list + show toast

InstanceForm.tsx:
  1. Initialize React Hook Form with Zod schema
  2. Render form fields (instanceId, config textarea)
  3. Validate on blur and submit
  4. Display inline errors via FormFieldError
  5. Emit onSubmit event with validated data
```

### Data Flow

```
User fills form → Submit button clicked

1. React Hook Form validates (client-side via Zod)
   - If invalid: Show field errors, prevent submit
   - If valid: Continue to step 2

2. Call useCreateInstance().mutate(data)
   - TanStack Query mutation starts
   - UI: Button shows spinner, form disabled

3. JQEL mutation sent to backend
   POST /api/jqel
   {
     schema: "backend",
     mutate: "instance",
     action: "insert",
     values: { instanceId, portalId, moduleId, config, active: true }
   }

4. Backend processes mutation
   - Validates data
   - Writes to instances.json
   - Returns created instance

5. Mutation onSuccess callback
   - Invalidate instance queries (cache refresh)
   - Navigate to instance list
   - Show success toast

6. If mutation fails
   - Show error toast with message
   - Re-enable form
   - Keep user on page to fix errors
```

### Error Handling Strategy

**Error Types:**
- **Validation errors** (client-side):
  - Display: Inline via FormFieldError below each field
  - Recovery: User fixes field and resubmits

- **Duplicate Instance ID**:
  - Display: Inline error on instanceId field
  - Recovery: User chooses different ID

- **Invalid JSON** (in config field):
  - Display: Inline error on config field
  - Recovery: User fixes JSON syntax

- **Network errors**:
  - Display: Toast notification "Failed to create instance. Check your connection."
  - Recovery: User clicks "Retry" or resubmits form

- **Permission errors**:
  - Display: Toast notification "You don't have permission to create instances."
  - Recovery: User contacts admin or logs in with different account

- **Server validation errors**:
  - Display: Toast notification with server error message
  - Recovery: User fixes data based on message and resubmits

**Error Display Pattern:**
```typescript
// Field-level errors (React Hook Form)
<FormField
  control={form.control}
  name="instanceId"
  render={({ field, fieldState }) => (
    <FormItem>
      <FormLabel>Instance ID</FormLabel>
      <FormControl>
        <Input {...field} />
      </FormControl>
      <FormMessage>{fieldState.error?.message}</FormMessage>
    </FormItem>
  )}
/>

// Form-level errors (toast)
if (createInstance.isError) {
  toast({
    title: 'Error',
    description: createInstance.error.message,
    variant: 'destructive',
  });
}
```
