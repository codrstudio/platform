# Task Plan: 1.6.6 - Gerar cores semânticas (success, warning, error, info)

## Context and Objective

This task implements the semantic color system that provides standardized, accessible colors for success, warning, error, and info states across the platform. Unlike brand colors (which are customizable), semantic colors are fixed platform-level colors that ensure consistent visual communication.

**What will be implemented:**
- Semantic color definitions for both light and dark themes
- Success (green), Warning (yellow/orange), Error (red), Info (blue) color palettes
- Foreground colors for each semantic background
- WCAG AA validated color pairs
- CSS custom property generation for shadcn/ui integration

**Why it's needed:**
- Consistent visual language: Users learn that green = success, red = error everywhere
- Accessibility: Ensures semantic states are always readable
- Design system: Provides ready-to-use colors for alerts, toasts, badges, etc.
- Cross-portal consistency: All portals use same semantic colors regardless of brand

**How it integrates:**
- Used by error boundaries (Task 1.4.12) to display errors
- Used by toast/notification system (Task 1.5.7) for alerts
- Used by Setup module for validation feedback
- Feeds into CSS custom properties alongside brand colors

**Business value:**
- Professional appearance through consistent color usage
- Reduced cognitive load (users don't need to learn different error colors per portal)
- Accessibility compliance (all semantic colors pass WCAG AA)

**User impact:**
- Clear visual feedback for actions (green = success, red = error)
- Color-blind friendly (paired with icons from Lucide)
- Works in both light and dark modes without configuration

## Critical Context

### Documentation

**WCAG Semantic Color Guidance:**
- [W3C: Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html) - Don't rely on color alone
- Key: Always pair semantic colors with icons or text labels
- SPEC-TH-IC-004:008 specifies Lucide icons for each semantic state

**Color Psychology:**
- Green: Success, positive, completion (universally recognized)
- Yellow/Orange: Warning, caution, attention needed
- Red: Error, danger, critical action
- Blue: Information, neutral, help

**Color Blindness Considerations:**
- Red-Green color blindness affects ~8% of males
- Blue-Yellow color blindness is rare (~0.01%)
- Icons are essential for accessibility (don't rely on color alone)

**shadcn/ui Semantic Colors:**
- [shadcn/ui Theming](https://ui.shadcn.com/docs/theming) - Shows destructive color pattern
- Example: `--destructive: 0 84% 60%; --destructive-foreground: 0 0% 98%;`
- We'll extend with success, warning, info

### Gotchas and Pitfalls

**Avoid Pure Hues:**
- Pure red (H=0, S=100%, L=50%) is too vibrant
- Pure green (H=120, S=100%, L=50%) is too bright
- Reduce saturation (60-85%) for professional appearance

**Light vs Dark Mode:**
- Light mode: Use darker, more saturated semantic colors (L=40-60%)
- Dark mode: Use lighter, slightly less saturated colors (L=50-70%)
- Don't just invert lightness (causes wrong saturation perception)

**Foreground Colors:**
- Always validate with WCAG AA (use Task 1.6.5 utilities)
- Light mode: Dark text on colored background
- Dark mode: Light text on colored background
- Can reuse `generateForeground()` from paletteGenerator

**Color Overlap:**
- Ensure semantic colors are visually distinct from each other
- Success green should not be confused with info blue
- Warning yellow should be distinct from error red

**Hue Selection:**
- Success: H=140-160 (green, slightly blue-shifted)
- Warning: H=30-45 (orange, not pure yellow)
- Error: H=0-10 (red)
- Info: H=200-220 (blue)

**Testing with Color Blindness Simulators:**
- Protanopia (red-blind): Can confuse red/green
- Deuteranopia (green-blind): Can confuse red/green
- Tritanopia (blue-blind): Can confuse blue/yellow
- Icons mitigate this (SPEC-TH-IC-005:008)

#### Step 3: Implement Semantic Color Generator

**File:** `src/frontend/src/services/theming/semanticColors.ts` (continued)

**Details:** Generate complete palette with validated foregrounds

```typescript
/**
 * Get semantic color for a specific state and mode
 *
 * @param name - Semantic color name
 * @param mode - Theme mode
 * @returns ColorHSL for the semantic color
 */
export function getSemanticColor(
  name: SemanticColorName,
  mode: ThemeMode
): ColorHSL {
  switch (name) {
    case 'success':
      return mode === 'light' ? SUCCESS_COLOR_LIGHT : SUCCESS_COLOR_DARK;
    case 'warning':
      return mode === 'light' ? WARNING_COLOR_LIGHT : WARNING_COLOR_DARK;
    case 'error':
      return mode === 'light' ? ERROR_COLOR_LIGHT : ERROR_COLOR_DARK;
    case 'info':
      return mode === 'light' ? INFO_COLOR_LIGHT : INFO_COLOR_DARK;
  }
}

/**
 * Generate complete semantic color palette
 * SPEC-TH-CS-001:020: All semantic colors with validated contrast
 *
 * @param mode - Theme mode (light or dark)
 * @returns Complete semantic color palette as CSS custom property values
 *
 * @example
 * const semanticColors = generateSemanticColors('light');
 * // {
 * //   success: "142 76% 36%",
 * //   successForeground: "0 0% 100%",
 * //   warning: "38 92% 50%",
 * //   ...
 * // }
 */
export function generateSemanticColors(mode: ThemeMode): SemanticColorPalette {
  // Generate each semantic color with validated foreground
  const success = getSemanticColor('success', mode);
  const successFg = generateValidatedForeground(success, mode);

  const warning = getSemanticColor('warning', mode);
  const warningFg = generateValidatedForeground(warning, mode);

  const error = getSemanticColor('error', mode);
  const errorFg = generateValidatedForeground(error, mode);

  const info = getSemanticColor('info', mode);
  const infoFg = generateValidatedForeground(info, mode);

  return {
    // Success
    success: hslToString(success),
    successForeground: hslToString(successFg),

    // Warning
    warning: hslToString(warning),
    warningForeground: hslToString(warningFg),

    // Error/Destructive
    error: hslToString(error),
    errorForeground: hslToString(errorFg),
    destructive: hslToString(error),         // Alias for shadcn/ui
    destructiveForeground: hslToString(errorFg),

    // Info
    info: hslToString(info),
    infoForeground: hslToString(infoFg)
  };
}

/**
 * Generate foreground color with WCAG AA validation
 * Internal helper function
 *
 * @param background - Semantic background color
 * @param mode - Theme mode
 * @returns Validated foreground color
 */
function generateValidatedForeground(
  background: ColorHSL,
  mode: ThemeMode
): ColorHSL {
  // Generate initial foreground (from Task 1.6.4)
  let foreground = generateForeground(background, mode);

  // Validate WCAG AA compliance (from Task 1.6.5)
  const validation = validateContrast(background, foreground, 'AA-normal');

  // Auto-adjust if fails (should rarely happen with our chosen colors)
  if (!validation.passes) {
    foreground = adjustToMeetContrast(background, foreground, 'AA-normal');
  }

  return foreground;
}

/**
 * Get recommended Lucide icon for semantic state
 * SPEC-TH-IC-004:008: Icons reinforce semantic colors
 *
 * @param name - Semantic color name
 * @returns Recommended icon name from lucide-react
 *
 * @example
 * import { CheckCircle } from 'lucide-react';
 * const iconName = getSemanticIcon('success'); // "CheckCircle"
 */
export function getSemanticIcon(name: SemanticColorName): string {
  switch (name) {
    case 'success':
      return 'CheckCircle'; // or 'Check', 'ThumbsUp'
    case 'warning':
      return 'AlertTriangle'; // or 'AlertCircle'
    case 'error':
      return 'XCircle'; // or 'AlertOctagon'
    case 'info':
      return 'Info'; // or 'HelpCircle'
  }
}
```
