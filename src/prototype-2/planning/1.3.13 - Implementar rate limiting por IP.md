# Task Plan: 1.3.13 - Implementar rate limiting por IP

## Context and Objective

This task implements IP-based rate limiting for authentication endpoints to protect against brute force attacks and DoS attempts. The rate limiter will track authentication requests per IP address, enforce configurable limits, and return standardized HTTP 429 responses when thresholds are exceeded.

**Business Value**: Prevents malicious actors from overwhelming the authentication system with credential guessing or denial-of-service attacks, ensuring service availability and security for legitimate users.

**Integration**: This middleware sits between the CORS/security middleware and the authentication routes, intercepting requests before they reach the auth handlers. It uses Redis for distributed rate limit state, ensuring consistent enforcement across multiple backend instances.

**User Impact**: Legitimate users experience no degradation. Attackers hitting limits receive clear error messages and appropriate retry-after headers. The system remains responsive under attack scenarios.

### Gotchas and Pitfalls

⚠️ **express-rate-limit v7.x Breaking Changes**
- Built-in `MemoryStore` and `RedisStore` removed in v7
- Must implement custom store interface: `increment()`, `decrement()`, `resetKey()`
- See example: https://github.com/express-rate-limit/express-rate-limit#custom-stores

⚠️ **IP Address Extraction**
- `req.ip` may be undefined or `::1` (localhost) in development
- Behind proxy: Use `req.headers['x-forwarded-for']` or `req.socket.remoteAddress`
- Express `trust proxy` setting affects `req.ip` value
- **Solution**: Create utility to extract IP with fallbacks

⚠️ **Redis Connection Failures**
- Rate limiter MUST fail open (allow requests) if Redis is unavailable
- Do NOT block legitimate traffic due to infrastructure issues
- Log errors but gracefully degrade

⚠️ **Race Conditions**
- Multiple requests from same IP can arrive simultaneously
- Use Redis INCR (atomic) or MULTI/EXEC (transaction) for increment
- Pattern from tokenRotation.service.ts: `redisService.multi()`

⚠️ **Fixed Window vs Sliding Window**
- **Fixed Window**: Simple but allows burst at window boundaries (100 reqs at 11:59:59, 100 at 12:00:00)
- **Sliding Window**: More accurate, prevents boundary bursts, slightly more complex
- **Recommendation**: Use sliding window for auth endpoints (security critical)

⚠️ **429 Response Headers**
- MUST include `Retry-After` header (seconds or HTTP date)
- SHOULD include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`
- express-rate-limit v7 handles this automatically via `standardHeaders: 'draft-7'`

⚠️ **Development Experience**
- Strict limits frustrate developers testing locally
- Use lenient limits in development, strict in production
- Pattern: Environment-aware configuration (like security.middleware.ts)

**Sliding Window Algorithm:**
```typescript
// Pseudo-code
const now = Date.now();
const windowMs = 60000; // 1 minute

// Get stored data
const data = await redis.get(`rate_limit:auth:${ip}`);
let windowStart = data?.windowStart || now;
let requestCount = data?.requestCount || 0;

// Check if window has shifted
if (now - windowStart >= windowMs) {
  // New window - reset
  windowStart = now;
  requestCount = 0;
}

// Increment count
requestCount++;

// Check limit
if (requestCount > maxRequests) {
  return { allowed: false, remaining: 0 };
}

// Store updated data
await redis.set(
  `rate_limit:auth:${ip}`,
  JSON.stringify({ windowStart, requestCount }),
  windowMs / 1000 // TTL in seconds
);

return {
  allowed: true,
  remaining: maxRequests - requestCount,
  resetAt: windowStart + windowMs
};
```

#### 2. Create Rate Limiter Service

**Create:** `src/services/rateLimiter.service.ts`

**Details:**
- Implement sliding window algorithm with Redis
- Provide `checkLimit()` method returning `RateLimitResult`
- Use atomic operations (INCR or MULTI/EXEC) to prevent race conditions
- Handle Redis errors gracefully (fail open - allow requests)
- Use TTL for automatic cleanup

**Pattern:** Follow `tokenRotation.service.ts` structure (singleton, Redis operations, error handling)

```typescript
import { redisService } from './redis.service.js';
import { config } from '../config/env.js';

export interface RateLimitResult {
  allowed: boolean;
  limit: number;
  remaining: number;
  resetAt: number; // Unix timestamp in milliseconds
}

export class RateLimiterService {
  private getKey(identifier: string): string {
    return `rate_limit:auth:${identifier}`;
  }

  async checkLimit(identifier: string): Promise<RateLimitResult> {
    const key = this.getKey(identifier);
    const now = Date.now();
    const windowMs = config.rateLimitWindowMs;
    const maxRequests = config.rateLimitMaxRequests;

    try {
      // Get current data
      const dataStr = await redisService.get(key);
      let windowStart: number;
      let requestCount: number;

      if (!dataStr) {
        // First request in window
        windowStart = now;
        requestCount = 0;
      } else {
        const data = JSON.parse(dataStr);
        windowStart = data.windowStart;
        requestCount = data.requestCount;

        // Check if window has expired (sliding)
        if (now - windowStart >= windowMs) {
          // Reset window
          windowStart = now;
          requestCount = 0;
        }
      }

      // Increment count
      requestCount++;

      // Check limit
      const allowed = requestCount <= maxRequests;
      const remaining = Math.max(0, maxRequests - requestCount);
      const resetAt = windowStart + windowMs;

      // Store updated data (only if allowed or within grace)
      if (allowed || requestCount <= maxRequests + 5) {
        await redisService.set(
          key,
          JSON.stringify({ windowStart, requestCount }),
          Math.ceil(windowMs / 1000) // TTL in seconds
        );
      }

      return {
        allowed,
        limit: maxRequests,
        remaining,
        resetAt,
      };
    } catch (error) {
      console.error('❌ Rate limiter Redis error:', error);
      // Fail open - allow request on Redis errors
      return {
        allowed: true,
        limit: maxRequests,
        remaining: maxRequests,
        resetAt: now + windowMs,
      };
    }
  }

  async resetLimit(identifier: string): Promise<void> {
    const key = this.getKey(identifier);
    await redisService.delete(key);
  }
}

export const rateLimiterService = new RateLimiterService();
```

```typescript
import { Request, Response, NextFunction, RequestHandler } from 'express';
import { rateLimiterService } from '../services/rateLimiter.service.js';
import { config } from '../config/env.js';

/**
 * Extract IP address from request
 * Handles proxies and localhost scenarios
 */
function getClientIp(req: Request): string {
  // Priority 1: X-Forwarded-For header (behind proxy)
  const forwarded = req.headers['x-forwarded-for'];
  if (forwarded) {
    const ips = Array.isArray(forwarded) ? forwarded[0] : forwarded;
    return ips.split(',')[0].trim();
  }

  // Priority 2: req.ip (Express built-in)
  if (req.ip) {
    return req.ip;
  }

  // Priority 3: Socket remote address
  if (req.socket?.remoteAddress) {
    return req.socket.remoteAddress;
  }

  // Fallback
  return 'unknown';
}

/**
 * Create authentication rate limiter middleware
 *
 * Implements SPEC-AU-SG-004 to SPEC-AU-SG-006:
 * - Limit authentication requests per IP
 * - Block temporarily after exceeding limit
 * - Return 429 Too Many Requests
 */
export function createAuthRateLimiter(): RequestHandler {
  return async (req: Request, res: Response, next: NextFunction): Promise<void> => {
    try {
      const ip = getClientIp(req);

      // Check rate limit
      const result = await rateLimiterService.checkLimit(ip);

      // Set rate limit headers (draft-7 standard)
      res.setHeader('X-RateLimit-Limit', result.limit.toString());
      res.setHeader('X-RateLimit-Remaining', result.remaining.toString());
      res.setHeader('X-RateLimit-Reset', Math.ceil(result.resetAt / 1000).toString());

      if (!result.allowed) {
        // Calculate retry-after in seconds
        const retryAfterSeconds = Math.ceil((result.resetAt - Date.now()) / 1000);

        res.setHeader('Retry-After', retryAfterSeconds.toString());

        // Log rate limit violation
        console.warn('⚠️ Rate limit exceeded:', {
          ip,
          timestamp: new Date().toISOString(),
          limit: result.limit,
          resetAt: new Date(result.resetAt).toISOString(),
        });

        res.status(429).json({
          code: 'rate_limit_exceeded',
          message: 'Too many authentication requests. Please try again later.',
          retryAfter: retryAfterSeconds,
        });
        return;
      }

      // Within limit - continue
      next();
    } catch (error) {
      console.error('❌ Error in rate limit middleware:', error);
      // Fail open - don't block requests on errors
      next();
    }
  };
}

/**
 * Pre-configured rate limiter for authentication routes
 */
export const authRateLimiter = createAuthRateLimiter();
```

# Send 15 requests (exceeds limit of 10)

done

# Expected: First 10 return 401, next 5 return 429

**Test 3: Window Reset**
```bash
# Exceed limit
for i in {1..11}; do curl -X POST http://localhost:3000/api/1/auth/login \

# Wait 61 seconds (window + 1s)
sleep 61

# Try again
curl -X POST http://localhost:3000/api/1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"wrong"}' \
  -i

# Expected: Returns 401 (not 429), X-RateLimit-Remaining: 9 (reset)
```
