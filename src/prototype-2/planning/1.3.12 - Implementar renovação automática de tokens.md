# Task Plan: 1.3.12 - Implementar renovação automática de tokens

## Context and Objective

### What will be implemented
This task implements automatic access token renewal in the Frontend AuthProvider to maintain user sessions transparently. The system will monitor token expiration and proactively refresh tokens before they expire, preventing authentication failures and ensuring seamless user experience.

### Why it's needed
Access tokens have short lifespans (default: 15 minutes) for security. Without automatic renewal, users would be logged out frequently, creating a poor experience. Automatic renewal keeps sessions alive while maintaining security through short-lived access tokens and secure refresh token rotation.

### How it integrates
The AuthProvider (already implemented in task 1.3.10) manages authentication state in memory. This task adds:
1. Token expiration monitoring using setTimeout
2. Proactive refresh 1 minute before expiration
3. Background renewal without user interaction
4. Graceful failure handling (logout on refresh failure)
5. Prevention of concurrent refresh requests
6. Automatic retry with exponential backoff

### Business value
- Seamless user experience - no unexpected logouts
- Maintains security posture with short-lived access tokens
- Reduces support burden from session timeout complaints
- Enables long-running sessions for productivity

### User impact
Users will remain authenticated indefinitely (within refresh token lifetime of 7 days) without manual re-login. The renewal happens transparently in the background. Only if the refresh token expires or is revoked will they need to log in again.

### Gotchas and Pitfalls

**Timer Precision:**
- JavaScript timers are not precise - they execute when the event loop is free
- Don't rely on exact timing; add buffer (renew 1 minute early, not 1 second)
- Background tabs may have throttled timers (browsers limit setTimeout in inactive tabs)
- Use visibility API if precise timing is critical when tab is hidden

**Memory Leaks:**
- ALWAYS clear timers in useEffect cleanup
- Cancel ongoing renewal requests when component unmounts
- Clear refs to prevent stale closures

**Race Conditions:**
- User manually logs out while renewal is in progress
- Multiple renewal attempts if expiration calculation is wrong
- Concurrent requests if timer fires twice (use isRenewingRef guard)
- Tab visibility changes during renewal

**Edge Cases:**
- expires_in = 0 or negative (invalid token from server)
- expires_in < 60 (less than buffer time - renew immediately)
- Refresh token expires during access token lifetime
- Network offline during renewal
- Backend returns different refresh token (rotation)

**State Management:**
- Don't trigger unnecessary re-renders (use useRef for non-UI state)
- Ensure updateAuthState updates both access AND refresh tokens
- Clear renewal timer when user logs out manually
- Reset retry counter on successful renewal

**Error Handling:**
- 401 from /refresh means refresh token expired/revoked - must logout
- Network errors should retry with exponential backoff
- After max retries, logout user and clear state
- Log errors for debugging but don't expose tokens in logs

```typescript
  // Clear existing timer
  cancelRenewal();

  // Calculate renewal time (1 minute before expiration)
  let renewalDelayMs = (expiresInSeconds - RENEWAL_BUFFER_SECONDS) * 1000;

  renewalTimerRef.current = setTimeout(() => {
    performRenewal();
```

#### Step 4: Create handleRenewalFailure function
**File:** `src/prototype-2/frontend/src/providers/AuthProvider.tsx`

**Location:** After scheduleRenewal function

**Add:**
```typescript
// Handle renewal failure with retry or logout
const handleRenewalFailure = useCallback((error: Error) => {
  renewalAttemptsRef.current += 1;

  console.error(`Token renewal failed (attempt ${renewalAttemptsRef.current}/${MAX_RENEWAL_ATTEMPTS}):`, error);

  // Check if error is fatal (refresh token expired/revoked)
  if (error.message.includes('invalid') || error.message.includes('expired') || error.message.includes('revoked')) {
    console.error('Refresh token is invalid, logging out user');
    clearAuthState();
    cancelRenewal();
    return;
  }

  // Check if max retries reached
  if (renewalAttemptsRef.current >= MAX_RENEWAL_ATTEMPTS) {
    console.error('Max renewal attempts reached, logging out user');
    clearAuthState();
    cancelRenewal();
    return;
  }

  // Calculate exponential backoff delay
  const retryDelay = RETRY_BASE_DELAY_MS * Math.pow(2, renewalAttemptsRef.current - 1);
  console.log(`Retrying renewal in ${retryDelay}ms`);

  // Schedule retry
  renewalTimerRef.current = setTimeout(() => {
    performRenewal();
  }, retryDelay);
}, [clearAuthState, cancelRenewal]); // Include performRenewal in deps after defining it
```

**Pattern:** Exponential backoff with max retries

```typescript
// Perform token renewal
const performRenewal = useCallback(async () => {
  // Prevent concurrent renewals
  if (isRenewingRef.current) {
    console.warn('Renewal already in progress, skipping');
    return;
  }

  // Check if we have a refresh token
  if (!refreshToken) {
    console.warn('No refresh token available for renewal');
    return;
  }

  isRenewingRef.current = true;

  try {
    console.log('Performing automatic token renewal');
    const response = await authClient.refreshTokens(refreshToken);

    // Success - update state and schedule next renewal
    updateAuthState(response);
    scheduleRenewal(response.expires_in);
    renewalAttemptsRef.current = 0; // Reset retry counter

    console.log('Token renewal successful');
  } catch (error) {
    handleRenewalFailure(error as Error);
  } finally {
    isRenewingRef.current = false;
  }
}, [refreshToken, updateAuthState, scheduleRenewal, handleRenewalFailure]);
```

**Pattern:** Async operation with concurrent request prevention

### Error Handling Strategy

**Error Types and Handling:**

1. **Invalid/Expired Refresh Token (401):**
   - Response: `{ code: 'invalid_token', message: '...' }`
   - Action: Immediate logout, clear state, cancel timers
   - User impact: Redirected to login page

2. **Token Reuse Detected (401):**
   - Response: `{ code: 'token_reused', message: '...' }`
   - Action: Immediate logout (family revoked by backend)
   - User impact: All sessions invalidated, must re-login

3. **Network Errors (fetch failure):**
   - Error: `TypeError: Failed to fetch` or timeout
   - Action: Retry with exponential backoff (max 3 attempts)
   - User impact: Transparent if retry succeeds, logout if fails

4. **Server Errors (500):**
   - Response: `{ code: 'internal_error', message: '...' }`
   - Action: Retry with exponential backoff
   - User impact: Transparent if retry succeeds

5. **Concurrent Renewal Prevention:**
   - Check: `isRenewingRef.current === true`
   - Action: Skip renewal, log warning
   - User impact: None (first request handles it)

**Error Display Pattern:**
```typescript
// Logged to console only - renewal is transparent to user
console.error('Token renewal failed:', error);

// UI feedback only on final failure (logout)
// Login page will show "Session expired" message
```
