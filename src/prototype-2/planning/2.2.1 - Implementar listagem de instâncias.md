# Task Plan: 2.2.1 - Implementar listagem de instâncias

## Context and Objective

Implement the Instance listing functionality for the Setup Module, enabling users to view all instances of activated modules within a specific portal. This task provides the foundation for instance management by displaying instance metadata, configuration summaries, and status information in a clear, accessible interface.

**Business Value:** Allows administrators to understand which module instances are active in each portal, facilitating configuration management and troubleshooting.

**User Impact:** Users can see at a glance all configured instances for a module, their status, and basic configuration details before performing edit/delete operations.

### Gotchas and Pitfalls

- ⚠️ **Instance scope is portal-specific**: Two portals can have instances with the same `instanceId`, so always filter by `portalId`
- ⚠️ **Module must be active**: Only show instances for modules that are active in the current portal
- ⚠️ **Config summary truncation**: The `config` field can be large JSON; display truncated/formatted summary only
- ⚠️ **Empty state messaging**: Per SPEC-MS-LO-005:006, empty states must have helpful messages like "No instances created yet. Click 'New Instance' to configure this module."
- ⚠️ **TanStack Query caching**: The hooks use hierarchical query keys (e.g., `['backend', 'instance', portalId]`), so invalidation happens automatically on mutations

### Existing Patterns to Follow

- **Loading states**: See SPEC-MS-LO-001 - Use skeleton loaders during initial fetch
- **Empty states**: See SPEC-MS-LO-005:006 - Clear messaging with call-to-action
- **Error states**: Use FormFieldError component pattern for inline errors
- **Responsive design**: See SPEC-MS-RE-001:006 - Mobile-first, vertical stacking on small screens
- **Accessibility**: See SPEC-MS-AC-001:007 - WCAG 2.1 AA compliance, keyboard navigation, focus management

## Technical Specification

### Architecture

```
src/prototype-2/frontend/src/modules/setup/
├── pages/
│   └── InstanceManager.tsx           (Page component: routing, context, layout)
├── components/
│   ├── InstanceList.tsx              (List component: filtering, sorting, empty state)
│   └── InstanceCard.tsx              (Card component: display single instance)
└── routes.ts                         (Route definition with params)

Data Flow:
URL params (portalId, moduleId)
  → InstanceManager page
  → usePortalInstances(portalId) hook
  → JQEL query (schema: backend, entity: instance)
  → Backend JSON file (instances.json)
  → Filter by moduleId in UI
  → InstanceList → InstanceCard (render)
```

### Data Flow

```
User navigates to: /setup/portals/:portalId/modules/:moduleId/instances

InstanceManager.tsx:
  1. Extract portalId, moduleId from useParams()
  2. Call usePortalInstances(portalId) → TanStack Query
  3. Filter instances by moduleId
  4. Pass filtered data to InstanceList

InstanceList.tsx:
  1. Receives instances array
  2. Applies local filtering/sorting (if any)
  3. Handles loading/error/empty states
  4. Maps instances to InstanceCard components

InstanceCard.tsx:
  1. Receives single instance data
  2. Displays: instanceId, status badge, config summary
  3. Provides action buttons: Edit, Delete
  4. Links to edit page
```

### Error Handling Strategy

**Error Types:**
- **Network errors**: Failed to fetch from backend
  - Display: Alert with "Failed to load instances. Please check your connection."
  - Recovery: "Retry" button that calls `queryClient.invalidateQueries()`

- **Permission errors**: User lacks permission to view instances
  - Display: Alert with "You don't have permission to view instances."
  - Recovery: Link to login or contact admin

- **Invalid data errors**: Malformed response from backend
  - Display: Alert with "Received invalid data. Please contact support."
  - Recovery: None (requires backend fix)

**Error Display Pattern:**
```typescript
// In InstanceList.tsx
if (error) {
  return (
    <Alert variant="destructive">
      <AlertCircle className="h-4 w-4" />
      <AlertDescription>
        Failed to load instances: {error.message}
        <Button variant="outline" onClick={() => queryClient.invalidateQueries(queryKey)}>
          Retry
        </Button>
      </AlertDescription>
    </Alert>
  );
}
```
