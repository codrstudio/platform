# Task Plan: 1.2.4 - Criar função registerRoutes()

## Context and Objective

This task involves creating the `registerRoutes()` function that enables dynamic registration of module routes into the React Router system. This is a critical piece of the platform's modular architecture, allowing modules to be loaded and their routes injected at runtime without requiring page reloads.

### What Will Be Implemented
A flexible route registration system that:
- Accepts route definitions from modules
- Prefixes routes with portal paths automatically
- Manages a registry of active routes per portal
- Supports dynamic route addition when modules are activated at runtime
- Integrates with React Router's state-driven rendering model

### Why It's Needed
- **Modularity**: Modules define their own routes without knowing portal context
- **Dynamic Loading**: Routes can be added/removed as modules activate/deactivate
- **Portal Isolation**: Each portal maintains its own route registry
- **Lazy Loading**: Supports React.lazy() for route components to enable code splitting

### How It Integrates
- Called by Portal loader when modules are loaded (System 1.2)
- Receives route definitions from module exports (SPEC-module-loading.md)
- Updates React state to trigger router re-render
- Works with ProtectedRoute wrapper for authentication (System 1.2)
- Foundation for module system (System 2.1)

### Business Value
- **Extensibility**: New modules can be added without modifying core routing code
- **Performance**: Only active modules' routes are registered
- **Maintainability**: Centralized route management simplifies debugging
- **User Experience**: Seamless module activation without page reloads

### User Impact
- Users experience instant availability of new features when modules are activated
- No page refresh required when activating/deactivating modules
- Fast navigation with lazy-loaded route components

## Critical Context

### Documentation

**React Router v7 - Dynamic Route Registration:**
- [Data Routers - createBrowserRouter](https://reactrouter.com/en/main/routers/create-browser-router)
- [Route Object Type](https://reactrouter.com/en/main/route/route)
- Note: React Router v7 prefers `createBrowserRouter` with route objects over `<Routes>` component for complex routing scenarios

**React Router v7 - State-Based Routing:**
React Router v7 supports dynamic routes through state-driven rendering. Routes can be updated by changing the routes array passed to the router.

```typescript
// Pattern: State-driven routes
const [routes, setRoutes] = useState<RouteObject[]>(initialRoutes);

// Update routes dynamically
const addRoute = (newRoute: RouteObject) => {
  setRoutes(prev => [...prev, newRoute]);
};
```

**SPEC Requirements:**
- **SPEC-R-RD-001 to 004:** Routes MUST be state-driven, updating when modules activate/deactivate
- **SPEC-LOAD-R-001 to 002:** Routes injected dynamically via registerRoutes function
- **SPEC-R-RM-011 to 013:** Portal MUST prefix routes with portal path

### Gotchas and Pitfalls

**⚠️ React Router v7 Breaking Changes:**
- Removed `<Routes>` children API in favor of route objects
- `element` prop expects React element, not lazy component directly
- Must wrap lazy components in `<Suspense>` at router level or route level

**⚠️ Route Object vs JSX Routes:**
React Router v7 has two APIs:
1. **JSX API** (`<Routes><Route /></Routes>`) - Simpler, less flexible
2. **Route Objects API** (`createBrowserRouter([...])`) - More powerful, supports loaders/actions

For this platform, **Route Objects API** is preferred because:
- Supports dynamic route updates
- Better TypeScript support
- More explicit about route structure
- Required for advanced features (loaders, actions)

**⚠️ Portal Path Prefixing:**
Portal "main" has path `/`, others have `/:portalId/*`. Module routes are relative.
- Module route: `/chat/:id`
- Portal "main" → Final route: `/chat/:id`
- Portal "app" → Final route: `/app/chat/:id`

**⚠️ React.lazy() and Suspense:**
Lazy components MUST be wrapped in Suspense. This can be done:
1. At route level (each route has Suspense)
2. At router level (single Suspense wraps all routes)
3. At portal level (portal component wraps routes)

**Option 3 (portal level)** is recommended for this platform.

**⚠️ Route Priority:**
- SPEC-R-PR-001: Portal "main" has absolute priority
- Routes are matched in order registered
- More specific routes should be registered before generic ones

### State Management

**Registry State (React Context + Hook):**

```typescript
// Context for route registry
const RouteRegistryContext = createContext<RouteRegistryContextValue | null>(null);

// Provider wraps App
function RouteRegistryProvider({ children }) {
  const [registry, setRegistry] = useState<Map<string, RouteObject[]>>(new Map());

  const registerRoutes = useCallback((portalId: string, routes: RouteObject[]) => {
    setRegistry(prev => {
      const next = new Map(prev);
      const existing = next.get(portalId) || [];
      next.set(portalId, [...existing, ...routes]);
      return next;
    });
  }, []);

  const getRoutes = useCallback((portalId: string) => {
    return registry.get(portalId) || [];
  }, [registry]);

  return (
    <RouteRegistryContext.Provider value={{ registry, registerRoutes, getRoutes }}>
      {children}
    </RouteRegistryContext.Provider>
  );
}

// Hook to access registry
function useRouteRegistry() {
  const context = useContext(RouteRegistryContext);
  if (!context) throw new Error('useRouteRegistry must be used within RouteRegistryProvider');
  return context;
}
```

```typescript
// routeRegistry.ts
const registry = new Map<string, RouteObject[]>();
const listeners = new Set<() => void>();

export function registerRoutes(portalId: string, routes: RouteObject[]) {
  const existing = registry.get(portalId) || [];
  registry.set(portalId, [...existing, ...routes]);
  notifyListeners();

export function usePortalRoutes(portalId: string) {
  const [routes, setRoutes] = useState(() => registry.get(portalId) || []);

  useEffect(() => {
    const listener = () => setRoutes(registry.get(portalId) || []);
```

```typescript
import { RegisteredRoute, RouteRegistryMap } from './types';

// Module-level state
const registry: RouteRegistryMap = new Map();
const listeners = new Set<() => void>();

// Get routes for portal
export function getPortalRoutes(portalId: string): RegisteredRoute[] {
  return registry.get(portalId) || [];
}

// Set routes for portal (replaces existing)
export function setPortalRoutes(portalId: string, routes: RegisteredRoute[]): void {
  registry.set(portalId, routes);
  notifyListeners();
}

// Add routes to portal (appends)
export function addPortalRoutes(portalId: string, routes: RegisteredRoute[]): void {
  const existing = registry.get(portalId) || [];
  registry.set(portalId, [...existing, ...routes]);
  notifyListeners();
}

// Remove all routes for portal
export function clearPortalRoutes(portalId: string): void {
  registry.delete(portalId);
  notifyListeners();
}

// Get all portals with routes
export function getRegisteredPortals(): string[] {
  return Array.from(registry.keys());
}

// Subscribe to registry changes
export function subscribe(listener: () => void): () => void {
  listeners.add(listener);
  return () => listeners.delete(listener);
}

// Notify all listeners
function notifyListeners(): void {
  listeners.forEach(fn => fn());
}

// Debug helper (dev only)
export function debugRegistry(): void {
  if (import.meta.env.DEV) {
    console.log('Route Registry:', Object.fromEntries(registry));
  }
}
```

**Step 3: Create Portal Path Prefix Utility**
- Create: `frontend/src/core/routing/prefixRoutes.ts`
- Implement logic to prefix route paths with portal path
- Handle special case for portal "main" (no prefix)
- Handle nested routes recursively
- Pattern: See SPEC-routing.md SPEC-R-RM-011:013

```typescript
import { RegisteredRoute } from './types';

/**
 * Prefix routes with portal path
 * - Portal "main": No prefix (routes stay as-is)
 * - Other portals: Prefix with /:portalId
 */
export function prefixRoutes(
  portalId: string,
  routes: RegisteredRoute[]
): RegisteredRoute[] {
  // Portal "main" has no prefix
  if (portalId === 'main') {
    return routes;
  }

  // Other portals: prefix with /:portalId
  return routes.map(route => prefixRoute(portalId, route));
}

function prefixRoute(portalId: string, route: RegisteredRoute): RegisteredRoute {
  const prefixedPath = prefixPath(portalId, route.path);

  // Recursively prefix child routes
  const children = route.children
    ? route.children.map(child => prefixRoute(portalId, child))
    : undefined;

  return {
    ...route,
    path: prefixedPath,
    children,
  };
}

function prefixPath(portalId: string, path?: string): string {
  if (!path) return `/${portalId}`;

  // Remove leading slash if present
  const cleanPath = path.startsWith('/') ? path.slice(1) : path;

  return `/${portalId}/${cleanPath}`;
}
```

**Step 4: Create Route Registration Function**
- Create: `frontend/src/core/routing/registerRoutes.ts`
- Validate route definitions
- Convert RouteDefinition to RegisteredRoute (RouteObject)
- Apply portal prefix
- Update registry
- Pattern: See SPEC-routing.md SPEC-R-DY-001:009

```typescript
import React from 'react';
import { RouteDefinition, RegisteredRoute } from './types';
import { addPortalRoutes } from './routeRegistry';
import { prefixRoutes } from './prefixRoutes';

export interface RegisterRoutesOptions {
  moduleId?: string;
  replace?: boolean; // If true, replace routes instead of append
}

/**
 * Register routes for a portal from a module
 *
 * @param portalId - Portal identifier
 * @param routes - Array of route definitions from module
 * @param options - Registration options
 */
export function registerRoutes(
  portalId: string,
  routes: RouteDefinition[],
  options: RegisterRoutesOptions = {}
): void {
  try {
    // Validate inputs
    if (!portalId) {
      console.warn('[registerRoutes] Invalid portalId:', portalId);
      return;
    }

    if (!Array.isArray(routes) || routes.length === 0) {
      console.warn('[registerRoutes] No routes to register for portal:', portalId);
      return;
    }

    // Convert RouteDefinition to RegisteredRoute (RouteObject)
    const registeredRoutes: RegisteredRoute[] = routes.map(route =>
      convertToRouteObject(route, options.moduleId)
    );

    // Apply portal prefix
    const prefixedRoutes = prefixRoutes(portalId, registeredRoutes);

    // Update registry
    addPortalRoutes(portalId, prefixedRoutes);

    // Debug log
    if (import.meta.env.DEV) {
      console.log(
        `[registerRoutes] Registered ${routes.length} route(s) for portal "${portalId}"`,
        options.moduleId ? `from module "${options.moduleId}"` : ''
      );
    }
  } catch (error) {
    console.error('[registerRoutes] Error registering routes:', error);
  }
}

/**
 * Convert RouteDefinition to RouteObject with lazy loading support
 */
function convertToRouteObject(
  route: RouteDefinition,
  moduleId?: string
): RegisteredRoute {
  // Wrap component in Suspense and lazy load if not already lazy
  const element = React.createElement(
    React.Suspense,
    { fallback: React.createElement('div', null, 'Loading...') },
    React.createElement(route.component)
  );

  return {
    path: route.path,
    element,
    moduleId,
    requiresAuth: route.requiresAuth,
    permissions: route.permissions,
    layout: route.layout,
  };
}

/**
 * Unregister routes for a portal
 * Used when module is deactivated or portal is unmounted
 */
export function unregisterRoutes(portalId: string, moduleId?: string): void {
  if (moduleId) {
    // Remove only routes from specific module
    const routes = getPortalRoutes(portalId);
    const filtered = routes.filter(r => r.moduleId !== moduleId);
    setPortalRoutes(portalId, filtered);

    if (import.meta.env.DEV) {
      console.log(`[unregisterRoutes] Removed routes for module "${moduleId}" from portal "${portalId}"`);
    }
  } else {
    // Remove all routes for portal
    clearPortalRoutes(portalId);

    if (import.meta.env.DEV) {
      console.log(`[unregisterRoutes] Cleared all routes for portal "${portalId}"`);
    }
  }
}
```

**Step 5: Create usePortalRoutes Hook**
- Create: `frontend/src/core/routing/hooks/usePortalRoutes.ts`
- Subscribe to registry updates
- Return memoized route array for portal
- Auto-update component when routes change
- Pattern: Standard React hook pattern with cleanup

```typescript
import { useState, useEffect, useMemo } from 'react';
import { getPortalRoutes, subscribe } from '../routeRegistry';
import { RegisteredRoute } from '../types';

/**
 * Hook to get routes for a specific portal
 * Automatically updates when routes are registered/unregistered
 *
 * @param portalId - Portal identifier
 * @returns Array of routes for the portal
 */
export default function usePortalRoutes(portalId: string): RegisteredRoute[] {
  // Get initial routes
  const [version, setVersion] = useState(0);

  // Subscribe to registry changes
  useEffect(() => {
    const unsubscribe = subscribe(() => {
      setVersion(v => v + 1); // Force re-render
    });

    return unsubscribe;
  }, []);

  // Get routes and memoize
  const routes = useMemo(() => {
    return getPortalRoutes(portalId);
  }, [portalId, version]);

  return routes;
}
```

### Error Handling Strategy

**Error Types:**

1. **Invalid Portal ID**
   - Validation: Check portalId is non-empty string
   - Handling: Log warning, return early (don't throw)
   - Display: No user-facing error (internal operation)

2. **Invalid Route Definitions**
   - Validation: Check routes array is non-empty, each route has path and component
   - Handling: Filter out invalid routes, log warning for each
   - Display: No user-facing error (developer responsibility)

3. **Component Load Failure (Lazy Loading)**
   - Validation: N/A (runtime error)
   - Handling: Caught by Suspense fallback, then Error Boundary
   - Display: Error UI with retry button

4. **Registry Subscription Failure**
   - Validation: Check listener is function
   - Handling: Log error, continue execution
   - Display: No user-facing error (internal operation)

**Error Display Pattern:**

```typescript
// In registerRoutes.ts
try {
  // Registration logic
} catch (error) {
  console.error('[registerRoutes] Error registering routes:', error);
  // Don't throw - graceful degradation
  // Routes won't be registered but app continues
}

// For lazy loading errors - handled by Error Boundary (Task 1.8.1)
// Error boundary will catch component load failures
```

**Logging Strategy:**
- Use console.warn for validation issues (dev friendly)
- Use console.error for unexpected errors
- Prefix all logs with `[registerRoutes]` for easy filtering
- Only log in development mode (check `import.meta.env.DEV`)
