# Task Plan: 1.4.2 - Implementar validação de queries

## Context and Objective

This task implements comprehensive validation for JQEL queries received at the `/api/jqel` endpoint. The validation layer ensures that all queries conform to the JQEL syntax specification before processing, providing early error detection, preventing invalid database operations, and improving security by rejecting malformed or malicious queries.

### What Will Be Implemented

A complete validation system that:
- Validates JQEL query structure and required fields
- Validates data types for all query components
- Validates WHERE clause operators and conditions
- Validates OPTIONS parameters (limit, offset, orderBy)
- Validates projection fields (output/except exclusivity)
- Returns clear, actionable error messages following JResult format

### Why It's Needed

**Security**: Invalid queries could expose the system to injection attacks or cause unexpected behavior in the database layer.

**Data Integrity**: Prevents malformed queries from reaching the Backbone (n8n) or database, ensuring data operations are always well-formed.

**Developer Experience**: Clear validation errors help frontend developers quickly identify and fix query issues during development.

**Performance**: Early validation prevents wasted processing cycles on queries that would fail anyway.

### How It Integrates

The validation layer integrates with:
- **JQEL Endpoint** (Task 1.4.1): Validates all queries before routing to schema handlers
- **JQEL Router** (Task 1.4.3): Only valid queries proceed to schema-based routing
- **Error Handler Middleware**: Uses existing error handling patterns for consistent responses
- **Frontend JQEL Hooks**: Receives validation errors in standard JResult format

### Business Value

- **Reduced Errors**: Catches 90%+ of query errors before they reach backend processing
- **Improved Security**: Validates input structure, preventing potential attacks
- **Better UX**: Users receive immediate, clear feedback on query issues
- **Reduced Support Load**: Self-documenting validation errors reduce developer confusion

### User Impact

Frontend developers receive immediate, specific feedback when constructing JQEL queries. Instead of cryptic database errors, they see messages like "Field 'schema' is required" or "Operator 'equals' is invalid, use 'eq'". This accelerates development and reduces debugging time.

## Critical Context

### Documentation

Since this is a validation-only task with no external dependencies, all necessary context comes from JQEL specifications:

- **SPEC-jqel-syntax.md** Section 13 (Validação) - Complete validation rules
  - SPEC-JQEL-VAL-001 to VAL-019: Structural validation requirements
  - Defines all required/optional fields and their types

- **SPEC-jqel-syntax.md** Section 7 (WHERE) - WHERE clause operators
  - Valid operators: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `like`, `or`, `not`

- **SPEC-jqel-syntax.md** Section 8 (OPTIONS) - Options validation
  - `limit`: positive integer, max recommended 1000
  - `offset`: non-negative integer
  - `orderBy`: array of objects with direction 'asc' or 'desc'

### Gotchas and Pitfalls

#### WHERE Operator Validation
- **Issue**: The `$` prefix is NOT used in JQEL operators (unlike MongoDB)
  - Correct: `{ "status": { "eq": "ativo" } }`
  - Wrong: `{ "status": { "$eq": "ativo" } }`
- **Why**: JQEL uses plain operator names for simplicity and JSON compatibility
- **Impact**: Validation must reject operators with `$` prefix

#### Mutual Exclusivity Rules
- **Rule**: `select` and `mutate` are mutually exclusive (SPEC-JQEL-VAL-004)
- **Rule**: `output` and `except` cannot coexist (SPEC-JQEL-VAL-019)
- **Implementation**: Check both aren't present simultaneously

#### Action Field Requirement
- **Rule**: If `mutate` is present, `action` is REQUIRED (SPEC-JQEL-VAL-005)
- **Rule**: If `select` is present, `action` is OPTIONAL
- **Why**: Mutations need to specify operation (insert/update/delete/upsert)

#### OrderBy Structure
- **Common mistake**: Treating orderBy as simple array
  - Wrong: `orderBy: ["name", "created_at"]`
  - Correct: `orderBy: [{ "name": "asc" }, { "created_at": "desc" }]`
- **Structure**: Array of objects where each object has ONE field with direction

#### Limit Validation
- **Recommended max**: 1000 (SPEC-JQEL-BP-006)
- **Not enforced**: Specification says "recomendado" (recommended), not "obrigatório" (required)
- **Decision**: Validate as positive integer, optionally warn if > 1000

```typescript
/**
 * JQEL Query structure
 *
 * Based on SPEC-JQEL-STR-002
 */
export interface JQELQuery {
  /** Schema identifier (required) - SPEC-JQEL-STR-003 */
  schema: string;

  /** Entity to select (mutually exclusive with mutate) - SPEC-JQEL-STR-004 */
  select?: string;

  /** Entity to mutate (mutually exclusive with select) - SPEC-JQEL-STR-004 */
  mutate?: string;

  /** Mutation action (required if mutate is present) - SPEC-JQEL-STR-006 */
  action?: string;

  /** Values for insert/update/upsert */
  values?: Record<string, unknown>;

  /** Filter conditions */
  where?: WhereClause;

  /** Query options (pagination, sorting) */
  options?: QueryOptions;

  /** Fields to include in response (exclusive with except) */
  output?: string[];

  /** Fields to exclude from response (exclusive with output) */
  except?: string[];
}

/**
 * WHERE clause structure
 *
 * Supports field conditions and logical operators
 */
export type WhereClause = {
  [field: string]: WhereCondition | WhereClause[] | WhereClause;
  or?: WhereClause[];
  not?: WhereClause;
};

/**
 * Individual field condition
 *
 * Valid operators: eq, ne, gt, gte, lt, lte, in, like
 */
export interface WhereCondition {
  eq?: unknown;
  ne?: unknown;
  gt?: number | string;
  gte?: number | string;
  lt?: number | string;
  lte?: number | string;
  in?: unknown[];
  like?: string;
}

/**
 * Query options (pagination and sorting)
 */
export interface QueryOptions {
  /** Maximum number of results (positive integer) */
  limit?: number;

  /** Number of results to skip (non-negative integer) */
  offset?: number;

  /** Sort order specification */
  orderBy?: OrderByClause[];
}

/**
 * Individual sort specification
 */
export interface OrderByClause {
  [field: string]: 'asc' | 'desc';
}

/**
 * Validation result
 */
export interface ValidationResult {
  valid: boolean;
  error?: {
    message: string;
    field?: string;
  };
}

/**
 * Valid WHERE operators
 */

  'eq', 'ne', 'gt', 'gte', 'lt', 'lte', 'in', 'like'

 * Valid logical operators
```

```typescript
// ============================================================================
// TYPE GUARDS
// ============================================================================

/**
 * Check if value is a string
 */
function isString(value: unknown): value is string {
  return typeof value === 'string';
}

/**
 * Check if value is a plain object (not array, not null)
 */
function isObject(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

/**
 * Check if value is an array
 */
function isArray(value: unknown): value is unknown[] {
  return Array.isArray(value);
}

/**
 * Check if value is an array of strings
 */
function isArrayOfStrings(value: unknown): value is string[] {
  return Array.isArray(value) && value.every(item => typeof item === 'string');
}

/**
 * Check if value is a positive integer
 */
function isPositiveInteger(value: unknown): value is number {
  return typeof value === 'number' && Number.isInteger(value) && value > 0;
}

/**
 * Check if value is a non-negative integer
 */
function isNonNegativeInteger(value: unknown): value is number {
  return typeof value === 'number' && Number.isInteger(value) && value >= 0;
}

// ============================================================================
// STRUCTURE VALIDATION
// ============================================================================

/**
 * Validate query structure (required fields, mutual exclusivity)
 *
 * SPEC-JQEL-VAL-002: schema required
 * SPEC-JQEL-VAL-003: select OR mutate required
 * SPEC-JQEL-VAL-004: select and mutate are mutually exclusive
 * SPEC-JQEL-VAL-005: if mutate, action is required
 */
export function validateQueryStructure(query: unknown): ValidationResult {
  // Must be an object
  if (!isObject(query)) {
    return {
      valid: false,
      error: {
        message: 'Query deve ser um objeto JSON válido'
      }
    };
  }

  const q = query as Partial<JQELQuery>;

  // SPEC-JQEL-VAL-002: schema required
  if (!q.schema) {
    return {
      valid: false,
      error: {
        message: 'Campo "schema" é obrigatório',
        field: 'schema'
      }
    };
  }

  // SPEC-JQEL-VAL-003: select OR mutate required
  if (!q.select && !q.mutate) {
    return {
      valid: false,
      error: {
        message: 'Campo "select" ou "mutate" é obrigatório'
      }
    };
  }

  // SPEC-JQEL-VAL-004: select and mutate are mutually exclusive
  if (q.select && q.mutate) {
    return {
      valid: false,
      error: {
        message: 'Não use "select" e "mutate" juntos'
      }
    };
  }

  // SPEC-JQEL-VAL-005: if mutate, action is required
  if (q.mutate && !q.action) {
    return {
      valid: false,
      error: {
        message: 'Campo "action" é obrigatório quando "mutate" está presente',
        field: 'action'
      }
    };
  }

  return { valid: true };
}

// ============================================================================
// TYPE VALIDATION
// ============================================================================

/**
 * Validate field types
 *
 * SPEC-JQEL-VAL-006 to VAL-013
 */
export function validateTypes(query: unknown): ValidationResult {
  if (!isObject(query)) {
    return { valid: true }; // Structure validation handles this
  }

  const q = query as Partial<JQELQuery>;

  // SPEC-JQEL-VAL-006: schema must be string
  if (q.schema !== undefined && !isString(q.schema)) {
    return {
      valid: false,
      error: {
        message: 'Campo "schema" deve ser string',
        field: 'schema'
      }
    };
  }

  // SPEC-JQEL-VAL-007: select/mutate must be string
  if (q.select !== undefined && !isString(q.select)) {
    return {
      valid: false,
      error: {
        message: 'Campo "select" deve ser string',
        field: 'select'
      }
    };
  }

  if (q.mutate !== undefined && !isString(q.mutate)) {
    return {
      valid: false,
      error: {
        message: 'Campo "mutate" deve ser string',
        field: 'mutate'
      }
    };
  }

  // SPEC-JQEL-VAL-008: action must be string
  if (q.action !== undefined && !isString(q.action)) {
    return {
      valid: false,
      error: {
        message: 'Campo "action" deve ser string',
        field: 'action'
      }
    };
  }

  // SPEC-JQEL-VAL-009: where must be object
  if (q.where !== undefined && !isObject(q.where)) {
    return {
      valid: false,
      error: {
        message: 'Campo "where" deve ser objeto',
        field: 'where'
      }
    };
  }

  // SPEC-JQEL-VAL-010: values must be object
  if (q.values !== undefined && !isObject(q.values)) {
    return {
      valid: false,
      error: {
        message: 'Campo "values" deve ser objeto',
        field: 'values'
      }
    };
  }

  // SPEC-JQEL-VAL-011: options must be object
  if (q.options !== undefined && !isObject(q.options)) {
    return {
      valid: false,
      error: {
        message: 'Campo "options" deve ser objeto',
        field: 'options'
      }
    };
  }

  // SPEC-JQEL-VAL-012: output must be array of strings
  if (q.output !== undefined && !isArrayOfStrings(q.output)) {
    return {
      valid: false,
      error: {
        message: 'Campo "output" deve ser array de strings',
        field: 'output'
      }
    };
  }

  // SPEC-JQEL-VAL-013: except must be array of strings
  if (q.except !== undefined && !isArrayOfStrings(q.except)) {
    return {
      valid: false,
      error: {
        message: 'Campo "except" deve ser array de strings',
        field: 'except'
      }
    };
  }

  return { valid: true };
}

// ============================================================================
// WHERE CLAUSE VALIDATION
// ============================================================================

/**
 * Validate WHERE clause operators and structure
 *
 * SPEC-JQEL-VAL-018: operators must be valid
 */
export function validateWhereClause(where: unknown): ValidationResult {
  if (where === undefined) {
    return { valid: true }; // WHERE is optional
  }

  if (!isObject(where)) {
    return {
      valid: false,
      error: {
        message: 'Campo "where" deve ser objeto',
        field: 'where'
      }
    };
  }

  return validateWhereObject(where, 'where');
}

/**
 * Recursively validate WHERE object
 */
function validateWhereObject(
  where: Record<string, unknown>,
  path: string
): ValidationResult {
  for (const [key, value] of Object.entries(where)) {
    // Handle logical operators (or, not)
    if (key === 'or') {
      if (!isArray(value)) {
        return {
          valid: false,
          error: {
            message: 'Operador "or" deve ser array',
            field: `${path}.or`
          }
        };
      }

      // Validate each condition in OR array
      for (let i = 0; i < value.length; i++) {
        if (!isObject(value[i])) {
          return {
            valid: false,
            error: {
              message: `Condição em "or[${i}]" deve ser objeto`,
              field: `${path}.or[${i}]`
            }
          };
        }
        const result = validateWhereObject(value[i] as Record<string, unknown>, `${path}.or[${i}]`);
        if (!result.valid) return result;
      }
      continue;
    }

    if (key === 'not') {
      if (!isObject(value)) {
        return {
          valid: false,
          error: {
            message: 'Operador "not" deve ser objeto',
            field: `${path}.not`
          }
        };
      }
      const result = validateWhereObject(value as Record<string, unknown>, `${path}.not`);
      if (!result.valid) return result;
      continue;
    }

    // Field condition - validate operators
    if (isObject(value)) {
      const result = validateFieldCondition(value, `${path}.${key}`);
      if (!result.valid) return result;
    }
  }

  return { valid: true };
}

/**
 * Validate field condition operators
 */
function validateFieldCondition(
  condition: Record<string, unknown>,
  path: string
): ValidationResult {
  for (const operator of Object.keys(condition)) {
    // Check if operator is valid
    if (!VALID_WHERE_OPERATORS.includes(operator as any)) {
      return {
        valid: false,
        error: {
          message: `Operador "${operator}" inválido. Use: ${VALID_WHERE_OPERATORS.join(', ')}`,
          field: path
        }
      };
    }

    // Validate 'in' operator value is array
    if (operator === 'in' && !isArray(condition[operator])) {
      return {
        valid: false,
        error: {
          message: 'Operador "in" requer array',
          field: path
        }
      };
    }
  }

  return { valid: true };
}

// ============================================================================
// OPTIONS VALIDATION
// ============================================================================

/**
 * Validate OPTIONS field
 *
 * SPEC-JQEL-VAL-014: limit must be positive integer
 * SPEC-JQEL-VAL-015: offset must be non-negative integer
 * SPEC-JQEL-VAL-016: orderBy must be array of objects
 * SPEC-JQEL-VAL-017: direction must be "asc" or "desc"
 */
export function validateOptions(options: unknown): ValidationResult {
  if (options === undefined) {
    return { valid: true }; // OPTIONS is optional
  }

  if (!isObject(options)) {
    return {
      valid: false,
      error: {
        message: 'Campo "options" deve ser objeto',
        field: 'options'
      }
    };
  }

  const opts = options as Partial<QueryOptions>;

  // SPEC-JQEL-VAL-014: limit must be positive integer
  if (opts.limit !== undefined) {
    if (!isPositiveInteger(opts.limit)) {
      return {
        valid: false,
        error: {
          message: 'Campo "limit" deve ser inteiro positivo',
          field: 'options.limit'
        }
      };
    }
  }

  // SPEC-JQEL-VAL-015: offset must be non-negative integer
  if (opts.offset !== undefined) {
    if (!isNonNegativeInteger(opts.offset)) {
      return {
        valid: false,
        error: {
          message: 'Campo "offset" deve ser inteiro não-negativo',
          field: 'options.offset'
        }
      };
    }
  }

  // SPEC-JQEL-VAL-016, VAL-017: orderBy validation
  if (opts.orderBy !== undefined) {
    if (!isArray(opts.orderBy)) {
      return {
        valid: false,
        error: {
          message: 'Campo "orderBy" deve ser array',
          field: 'options.orderBy'
        }
      };
    }

    for (let i = 0; i < opts.orderBy.length; i++) {
      const item = opts.orderBy[i];

      if (!isObject(item)) {
        return {
          valid: false,
          error: {
            message: `Item "orderBy[${i}]" deve ser objeto`,
            field: `options.orderBy[${i}]`
          }
        };
      }

      const entries = Object.entries(item);

      // Each orderBy item must have exactly one field
      if (entries.length !== 1) {
        return {
          valid: false,
          error: {
            message: `Item "orderBy[${i}]" deve ter exatamente um campo`,
            field: `options.orderBy[${i}]`
          }
        };
      }

      const [field, direction] = entries[0];

      // Direction must be 'asc' or 'desc'
      if (!VALID_SORT_DIRECTIONS.includes(direction as any)) {
        return {
          valid: false,
          error: {
            message: `Direção de ordenação deve ser "asc" ou "desc", recebeu "${direction}"`,
            field: `options.orderBy[${i}].${field}`
          }
        };
      }
    }
  }

  return { valid: true };
}

// ============================================================================
// PROJECTION VALIDATION
// ============================================================================

/**
 * Validate output/except exclusivity
 *
 * SPEC-JQEL-VAL-019: output and except cannot coexist
 */
export function validateProjection(output: unknown, except: unknown): ValidationResult {
  // SPEC-JQEL-VAL-019: output and except are mutually exclusive
  if (output !== undefined && except !== undefined) {
    return {
      valid: false,
      error: {
        message: 'Não use "output" e "except" juntos'
      }
    };
  }

  return { valid: true };
}
```

#### Step 3: Create Validation Middleware
**Create**: `src/prototype-2/backend/src/middleware/jqel.validation.middleware.ts`

**Purpose**: Express middleware that applies validation

**Details**:
- Extract query from `req.body`
- Call validator utilities in sequence
- Return HTTP 400 with JResult error on validation failure
- Call `next()` on success

**Implementation**:
```typescript
// src/prototype-2/backend/src/middleware/jqel.validation.middleware.ts

import { Request, Response, NextFunction } from 'express';
import type { JQELQuery } from '../types/jqel.types.js';
import {
  validateQueryStructure,
  validateTypes,
  validateWhereClause,
  validateOptions,
  validateProjection
} from '../utils/jqel.validator.js';

/**
 * Validation middleware for JQEL queries
 *
 * Validates query structure, types, WHERE clause, OPTIONS, and projection.
 * Returns HTTP 400 with error details on validation failure.
 *
 * Usage:
 *   router.post('/api/jqel', validateJqelQuery, jqelHandler);
 */
export const validateJqelQuery = (
  req: Request,
  res: Response,
  next: NextFunction
): void => {
  try {
    const query = req.body;

    // Step 1: Validate query structure (required fields, mutual exclusivity)
    const structureResult = validateQueryStructure(query);
    if (!structureResult.valid) {
      res.status(400).json({
        code: 400,
        message: structureResult.error!.message,
        field: structureResult.error!.field
      });
      return;
    }

    // Step 2: Validate field types
    const typesResult = validateTypes(query);
    if (!typesResult.valid) {
      res.status(400).json({
        code: 400,
        message: typesResult.error!.message,
        field: typesResult.error!.field
      });
      return;
    }

    const q = query as Partial<JQELQuery>;

    // Step 3: Validate WHERE clause (if present)
    if (q.where !== undefined) {
      const whereResult = validateWhereClause(q.where);
      if (!whereResult.valid) {
        res.status(400).json({
          code: 400,
          message: whereResult.error!.message,
          field: whereResult.error!.field
        });
        return;
      }
    }

    // Step 4: Validate OPTIONS (if present)
    if (q.options !== undefined) {
      const optionsResult = validateOptions(q.options);
      if (!optionsResult.valid) {
        res.status(400).json({
          code: 400,
          message: optionsResult.error!.message,
          field: optionsResult.error!.field
        });
        return;
      }
    }

    // Step 5: Validate projection exclusivity
    const projectionResult = validateProjection(q.output, q.except);
    if (!projectionResult.valid) {
      res.status(400).json({
        code: 400,
        message: projectionResult.error!.message,
        field: projectionResult.error!.field
      });
      return;
    }

    // All validations passed - continue to next handler
    next();
  } catch (error) {
    // Unexpected error - propagate to error handler
    next(error);
  }
};
```

## Error Handling Strategy

### Error Types

#### Validation Errors (HTTP 400)
**When**: Query structure, types, or values are invalid
**Response**:
```json
{
  "code": 400,
  "message": "Campo 'schema' é obrigatório",
  "field": "schema"
}
```

**Examples**:
- Missing required fields: `"Campo 'schema' é obrigatório"`
- Type mismatches: `"Campo 'where' deve ser objeto"`
- Invalid operators: `"Operador 'equals' inválido. Use: eq, ne, gt, ..."`
- Mutual exclusivity: `"Não use 'select' e 'mutate' juntos"`
- Invalid values: `"Campo 'limit' deve ser inteiro positivo"`

#### Unexpected Errors (HTTP 500)
**When**: Validation code throws unexpected exception
**Handling**: Caught by try/catch, propagated to error handler via `next(error)`

### Error Display Pattern

#### Field-Specific Errors
Include `field` property to identify problematic field:
```json
{
  "code": 400,
  "message": "Operador 'in' requer array",
  "field": "where.status"
}
```

#### Nested Field Errors
Use dot notation for nested paths:
```json
{
  "code": 400,
  "message": "Direção de ordenação deve ser 'asc' ou 'desc'",
  "field": "options.orderBy[0].created_at"
}
```

#### General Errors
Omit `field` for query-level errors:
```json
{
  "code": 400,
  "message": "Não use 'output' e 'except' juntos"
}
```
