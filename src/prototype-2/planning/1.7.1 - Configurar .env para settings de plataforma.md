# Task Plan: 1.7.1 - Configurar .env para settings de plataforma

## Context and Objective

This task implements **Platform Settings** configuration via `.env` files for both backend and frontend. Platform Settings are structural configurations that affect the basic functioning of the system and require application restart when changed.

**What will be implemented:**
- Backend `.env` structure refinement and documentation
- Frontend `.env` structure for client-side platform settings
- Environment variable categorization (required vs optional)
- Placeholder values in `.env.example` files
- No-secret policy enforcement in examples

**Why it's needed:**
Platform Settings control infrastructure-level configuration (URLs, Redis connection, JWT settings, n8n integration). These must be separated from Application Settings (portals/modules/instances) and properly documented for deployment and maintenance.

**How it integrates:**
- Backend `.env` already exists but needs SPEC compliance verification
- Frontend `.env.example` exists but needs expansion for platform-level settings
- Settings will be loaded at startup by `src/config/env.ts` (backend) and `import.meta.env` (frontend)
- Validation happens at application bootstrap (Task 1.7.2 will implement)

**Business value:**
- Clear separation of platform vs application configuration
- Easy deployment across environments (dev/staging/prod)
- Secure secret management
- Documentation for DevOps teams

**User impact:**
Transparent to end users. This is pure infrastructure configuration for system administrators and developers.

```typescript
function validateEnv(): EnvConfig {
  const errors: string[] = [];

  const getRequired = (key: string): string => {
    const value = process.env[key];
    if (!value || value.trim() === '') {
      errors.push(`Missing required environment variable: ${key}`);
    }
    return value || '';
  };

  const getOptional = (key: string, defaultValue: string): string => {
    return process.env[key] || defaultValue;
  };

  // Validation logic...
  if (errors.length > 0) {
    console.error('\n❌ Environment validation failed:\n');
    errors.forEach(err => console.error(`   - ${err}`));
    console.error('\n📝 Please check your .env file against .env.example\n');
    process.exit(1);
  }

  return config;
}
```

### Gotchas and Pitfalls

⚠️ **Frontend environment variables:**
- Vite ONLY exposes variables with `VITE_` prefix to client code
- Variables without prefix are NOT available in browser
- Cannot use `process.env` in frontend (Node.js-specific)
- Must use `import.meta.env.VITE_*` instead

⚠️ **Security:**
- NEVER commit `.env` with real secrets
- `.env.example` must use placeholders only
- Verify `.gitignore` includes `.env`
- Mask sensitive values when displaying (passwords, secrets)

⚠️ **Secret minimum lengths:**
- `JWT_SECRET`: minimum 32 characters (256 bits)
- `N8N_SHARED_SECRET`: minimum 32 characters
- `PLATFORM_SHARED_SECRET`: must match `N8N_SHARED_SECRET`

⚠️ **URL validation:**
- All URLs must be valid (use `new URL()` to validate)
- HTTP allowed in development, HTTPS required in production
- No trailing slashes in base URLs

```typescript
/**
 * Environment validation helper utilities
 * Used by env.ts for startup validation
 */

export interface ValidationError {
  field: string;
  message: string;
}

/**
 * Validate URL format
 */
export function validateUrl(value: string, fieldName: string): ValidationError | null {
  try {
    new URL(value);
    return null;
  } catch {
    return {
      field: fieldName,
      message: `${fieldName} must be a valid URL`,
    };
  }
}

/**
 * Validate port number
 */
export function validatePort(value: number, fieldName: string): ValidationError | null {
  if (isNaN(value) || value < 1 || value > 65535) {
    return {
      field: fieldName,
      message: `${fieldName} must be a number between 1 and 65535`,
    };
  }
  return null;
}

/**
 * Validate secret minimum length
 */
export function validateSecret(
  value: string,
  fieldName: string,
  minLength: number = 32
): ValidationError | null {
  if (value.length < minLength) {
    return {
      field: fieldName,
      message: `${fieldName} must be at least ${minLength} characters`,
    };
  }
  return null;
}

/**
 * Validate enum value
 */
export function validateEnum(
  value: string,
  fieldName: string,
  allowedValues: string[]
): ValidationError | null {
  if (!allowedValues.includes(value)) {
    return {
      field: fieldName,
      message: `${fieldName} must be one of: ${allowedValues.join(', ')}`,
    };
  }
  return null;
}

/**
 * Mask sensitive value for logging
 */
export function maskSecret(value: string): string {
  if (!value || value.length < 8) {
    return '***';
  }
  return value.substring(0, 4) + '***' + value.substring(value.length - 4);
}

/**
 * Mask password in connection string
 */
export function maskConnectionString(url: string): string {
  try {
    const parsed = new URL(url);
    if (parsed.password) {
      parsed.password = '***';
    }
    return parsed.toString();
  } catch {
    return '***';
  }
}
```

### Error Handling Strategy

**Validation Errors:**
- Collect all errors before failing (don't fail fast)
- Clear, actionable error messages
- Reference `.env.example` in error output
- Exit with code 1 (failure)

**Missing Files:**
- `.env.example` missing: Error and exit (template required)
- `.env` missing: Error and exit with instructions to copy from example

**Invalid Values:**
- Type mismatch: Clear message about expected type
- Range errors: Show valid range
- Format errors: Show example of valid format

**Error Display Pattern:**
```typescript
if (errors.length > 0) {

  errors.forEach(err => console.error(`   - ${err}`));

}
```
