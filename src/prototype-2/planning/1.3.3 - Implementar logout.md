**Service method with idempotent behavior:**
```typescript
// File: src/prototype-2/backend/src/services/tokenRotation.service.ts (lines 291-316)
async revokeToken(token: string): Promise<void> {
  try {
    const tokenHash = this.hashToken(token);
    const key = `${this.KEY_PREFIX}${tokenHash}`;
    const dataStr = await redisService.get(key);

    if (!dataStr) return; // Token doesn't exist, idempotent

    const data: BackendRefreshTokenData = JSON.parse(dataStr);
    data.revoked = true;

    const ttl = await redisService.ttl(key);
    await redisService.set(key, JSON.stringify(data), ttl > 0 ? ttl : this.getTTL());
  } catch (error) {
    console.error('❌ Error revoking token:', error);
    throw error;
  }
}
```

## Critical Context

### SPEC Requirements Summary

**SPEC-AU-LO-* (Logout Endpoint):**
- **SPEC-AU-LO-001**: Accept `refresh_token` in body JSON
- **SPEC-AU-LO-002**: Accept `refresh_token` in HTTP-only cookie
- **SPEC-AU-LO-003**: Body has priority if both present
- **SPEC-AU-LO-004**: Backend must forward to Backbone
- **SPEC-AU-LO-005**: Backbone must revoke specific refresh_token
- **SPEC-AU-LO-006**: Revocation must be immediate
- **SPEC-AU-LO-007**: Revoked token cannot be used for refresh
- **SPEC-AU-LO-008**: Return HTTP 200 on success
- **SPEC-AU-LO-009**: Return code "success" on success
- **SPEC-AU-LO-010**: Return message on success
- **SPEC-AU-LO-011**: Invalid token may return success (idempotent)
- **SPEC-AU-LO-012**: Internal error returns HTTP 500
- **SPEC-AU-LO-013**: Frontend must clear access token
- **SPEC-AU-LO-014**: Frontend must clear refresh token
- **SPEC-AU-LO-015**: Frontend must clear auth state

### Architecture Notes

**Important**: The existing implementation does NOT proxy to n8n (Backbone). This is a deliberate architectural decision for prototype-2:
- Token rotation is handled entirely by Backend (Express + Redis)
- n8n is not involved in token lifecycle management
- SPEC-AU-LO-004 is intentionally not followed in this prototype

**Idempotency Critical:**
- Calling `/logout` with already-revoked token must return success (SPEC-AU-LO-011)
- This prevents error states when users logout multiple times
- Current implementation handles this correctly (returns early if token not found)

### Gotchas and Pitfalls

**1. Cookie vs Body Priority:**
- Current implementation: `req.body.refresh_token || req.cookies?.refresh_token`
- This correctly prioritizes body over cookie (SPEC-AU-LO-003)

**2. Idempotency Requirement:**
- SPEC-AU-LO-011 states invalid token "MAY" return success (idempotent)
- Current implementation returns `400 Bad Request` if token is missing
- This is correct - idempotency applies to invalid/expired tokens, not missing tokens

**3. Token Not Found vs Token Invalid:**
- Token not in Redis: Idempotent success (already revoked or expired)
- Token explicitly revoked: Idempotent success (already processed)
- Missing token parameter: 400 error (missing required field)

**4. Error Handling:**
- Redis errors should return 500 Internal Server Error
- Token validation errors should be idempotent (200 success)
- Missing token parameter should return 400 Bad Request

## Technical Specification

### Current Implementation Analysis

**Endpoint:** `POST /api/1/auth/logout` (lines 157-187 in auth.routes.ts)

**Current Flow:**
1. Extract `refresh_token` from body or cookie (body priority)
2. Validate token presence → 400 if missing
3. Call `tokenRotationService.revokeToken(refreshToken)`
4. Return 200 success with code/message
5. Errors caught and passed to error handler

**Service Method:** `tokenRotation.service.ts` → `revokeToken()`
- Hashes token with SHA-256
- Retrieves token data from Redis
- If not found, returns early (idempotent)
- Sets `revoked: true` in token data
- Updates Redis with same TTL
