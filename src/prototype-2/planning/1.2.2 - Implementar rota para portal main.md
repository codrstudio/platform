# Task Plan: 1.2.2 - Implementar rota "/" para portal main

## Context and Objective

This task implements the foundation of the routing system for prototype-2, specifically creating the route for the "main" portal at the root path (`/`). This is the first user-facing routing implementation and establishes patterns that will be replicated for other portals.

The main portal is special because:
- It uses the root path `/` instead of `/:portalId/*`
- It has absolute priority over all other portals in route conflicts
- It must load dynamically based on configuration (active modules)
- It serves as the primary entry point for the platform

This implementation will integrate React Router v7 with the platform's portal and module system, loading portal configuration from the backend via JQEL, and preparing the infrastructure for dynamic module loading (though module loading will be fully implemented in subsequent tasks).

**Business Value:** Enables users to access the main portal and establishes the routing architecture that all other portals will follow.

**User Impact:** Users can navigate to the platform root and see the main portal (even if initially empty, as main portal starts with no active modules per SPEC-C-S-002).

- React Router v7 changed from v6 - ensure using correct API
- Routes must be inside `<Routes>` component, not standalone
- `element` prop takes JSX, not component reference

- Backend schema routes to local JSON, not n8n
- Query structure: `{ schema: "backend", select: "portal", where: { portalId: { $eq: "main" } } }`

### Data Flow

**Portal Configuration Loading:**
1. User navigates to `/`
2. React Router renders `<PortalLoader portalId="main" />`
3. PortalLoader uses `usePortalConfig("main")` hook
4. Hook uses TanStack Query to fetch portal config
5. Query calls `fetchPortalConfig("main")` service function
6. Service makes JQEL POST to `/api/jqel` with:
   ```json
   {
     "schema": "backend",
     "select": "portal",
     "where": { "portalId": { "$eq": "main" } },
     "output": ["portalId", "name", "path", "activeModules", "settings"]
   }
   ```
7. Backend responds with portal configuration
8. TanStack Query caches result
9. PortalLoader receives config and renders MainPortalRouter
10. MainPortalRouter displays portal (empty state if no modules)

**Module Loading (Future):**
- Portal config includes `activeModules` array
- MainPortalRouter will iterate and lazy-load modules
- Each module registers routes dynamically
- For now, just render empty state or welcome message

**Step 2: Create JQEL Client**
- Create `frontend/src/services/jqel/client.ts`:
  ```typescript
  import type { JQELQuery, JResult } from '@/types/jqel';

  const API_BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:3000';

  export async function jqelQuery<T>(query: JQELQuery): Promise<T> {
    const response = await fetch(`${API_BASE_URL}/api/jqel`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify(query),
    });

    if (!response.ok) {
      throw new Error(`JQEL request failed: ${response.statusText}`);
    }

    const result: JResult<T> = await response.json();

    if (!result.success || !result.data) {
      throw new Error(result.error?.message || 'JQEL query failed');
    }

    return result.data;
  }
  ```
- Error Handling: Throw on HTTP errors and JQEL errors
- Pattern: Generic function for type-safe queries

**Step 3: Create Portal Queries Service**

  import { jqelQuery } from './client';
  import type { Portal } from '@/types/portal';

  export async function fetchPortalConfig(portalId: string): Promise<Portal> {
    const portals = await jqelQuery<Portal[]>({
      schema: 'backend',
      select: 'portal',
      where: {
        portalId: { $eq: portalId },
      },
      output: ['portalId', 'name', 'description', 'path', 'activeModules', 'settings'],
    });

      throw new Error(`Portal "${portalId}" not found`);
    }

    return portals[0];

**Step 5: Create PortalLoader Component**
- Create `frontend/src/core/routing/PortalLoader.tsx`:
  ```typescript
  import { usePortalConfig } from '@/hooks/usePortalConfig';
  import { MainPortalRouter } from './MainPortalRouter';
  import { ErrorState } from '@/components/common/ErrorState';
  import { LoadingState } from '@/components/common/LoadingState';

  interface PortalLoaderProps {
    portalId: string;
  }

  export function PortalLoader({ portalId }: PortalLoaderProps) {
    const { data: portal, isLoading, error } = usePortalConfig(portalId);

    if (isLoading) {
      return <LoadingState message="Loading platform..." />;
    }

    if (error) {
      return (
        <ErrorState
          title="Portal Not Found"
          message={error.message}
          onRetry={() => window.location.reload()}
        />
      );
    }

    if (!portal) {
      return (
        <ErrorState
          title="Portal Not Found"
          message={`Portal "${portalId}" could not be loaded.`}
        />
      );
    }

    // For now, only main portal is implemented
    if (portalId === 'main') {
      return <MainPortalRouter portal={portal} />;
    }

    // Other portals will be implemented in task 1.2.3
    return (
      <ErrorState
        title="Portal Not Implemented"
        message={`Portal "${portalId}" routing is not yet implemented.`}
      />
    );
  }
  ```
- Pattern: Centralized loading/error handling
- Future: Add support for other portals

### Error Handling Strategy

**Network Errors:**
- HTTP fetch failures: Show "Unable to connect to platform" message
- Retry: TanStack Query retries 3 times automatically
- User Action: "Try Again" button reloads page

**JQEL Errors:**
- Portal not found: Show "Portal not found" message
- Invalid response: Show generic error message
- Log errors to console for debugging

**React Errors:**
- Component errors: Caught by Error Boundary (future task)
- Render errors: Log to console, show fallback UI
- For now, uncaught errors will crash app (acceptable in development)

**Loading States:**
- Always show loading UI during async operations
- Minimum loading time: none (show immediately)
- Maximum: 30 seconds before timeout (TanStack Query default)

**Error Display Pattern:**
```typescript
// Consistent error display
<ErrorState
  title="User-friendly title"
  message="Descriptive message explaining what went wrong"
  onRetry={() => /* retry logic */}
/>
```
