# Task Plan: 1.7.4 - Criar estrutura de arquivos JSON

## Context and Objective

This task creates the JSON file structure for Application Settings in prototype-2's backend. Application Settings store portal, module, and instance configurations and MUST be persistent, accessible via JQEL, and manually editable.

**What will be implemented:**
- JSON files in `backend/config/` for portals, modules, instances
- File structure validation and initialization
- Proper error handling for file operations

**Why it's needed:**
- Platform needs persistent storage for portal/module/instance configurations
- JQEL backend processor requires JSON files to read/write configurations
- Separates Application Settings (user-editable) from Platform Settings (.env)

**How it integrates:**
- Files are read/written by `BackendProcessorService` (already implemented)
- JQEL queries with `schema: "backend"` access these files
- Setup module will use JQEL to edit these configurations

**Business value:**
- Enables dynamic portal/module configuration without code changes
- Provides human-readable, version-controllable configuration
- Supports emergency manual edits when needed

**User impact:**
- Setup module can CRUD portals/modules/instances via UI
- Configuration changes take effect immediately (no server restart)
- System admins can manually edit JSON files in emergencies

**File Naming:**
- Plural names: `portals.json`, `modules.json`, `instances.json`
- Location: `backend/config/` directory
- Encoding: UTF-8 with BOM disabled

**JSON Structure:**

- No trailing commas (strict JSON)

- Don't crash server on config errors - use defaults or empty arrays

### Gotchas and Pitfalls

- **⚠️ File encoding MUST be UTF-8**: Windows default encoding (UTF-16) will break JSON parsing
- **⚠️ Arrays vs Objects**: BackendProcessor expects arrays - single objects will be wrapped in array
- **⚠️ Directory creation**: `fs.mkdir()` with `{ recursive: true }` prevents ENOENT errors
- **⚠️ JSON.parse() errors**: Invalid JSON crashes server - validate before writing
- **⚠️ Race conditions**: Multiple writes to same file can corrupt data (use atomic writes in future if needed)
- **⚠️ Git tracking**: Configuration files SHOULD be tracked in git (unlike .env) but may need .gitignore for environment-specific overrides

### Error Handling Strategy

**Error Types:**

1. **File not found (ENOENT)**
   - Handling: Create file with default configuration
   - User feedback: Log warning + created file path
   - Example: `⚠️  portals.json not found, creating with defaults`

2. **Permission denied (EACCES)**
   - Handling: Log error, exit process
   - User feedback: `❌ Cannot write to config directory. Check permissions.`
   - Recovery: System admin must fix permissions

3. **Invalid JSON (SyntaxError)**
   - Handling: Log error with file name and position
   - User feedback: `❌ Invalid JSON in portals.json at line 5`
   - Recovery: System admin must fix JSON syntax manually

4. **Directory creation failure**
   - Handling: Log error, exit process
   - User feedback: `❌ Cannot create config directory at [path]`
   - Recovery: Check disk space and permissions

**Error Display Pattern:**

```typescript
// Pattern from: backend/src/config/env.ts (lines 156-159)
```

**Non-fatal errors:**
- Missing files (create defaults)
- Empty arrays (valid state)
- Extra fields in objects (ignored)

**Fatal errors (exit process):**
- Cannot create config directory
- Cannot write to config files (permissions)
- Corrupted JSON that cannot be parsed

```typescript
import fs from 'fs/promises';
import path from 'path';
import type { Portal, Module, Instance } from '../types/config.types.js';

/**
 * ConfigInitializerService
 *
 * Ensures configuration files exist and are valid on startup.
 * Creates default configurations if files are missing.
 *
 * SPEC References:
 * - SPEC-CF-AS-001:004: Application Settings storage
 * - SPEC-CF-AS-009: Configuration structure
 */
export class ConfigInitializerService {
  private readonly configDir: string;

  constructor() {
    this.configDir = path.join(process.cwd(), 'config');
  }

  /**
   * Initialize configuration files
   * Called during application startup
   */
  async initialize(): Promise<void> {
    try {
      console.log('\n🔧 Initializing configuration files...');

      // Ensure config directory exists
      await this.ensureConfigDir();

      // Check and create files if needed
      await this.ensurePortalsFile();
      await this.ensureModulesFile();
      await this.ensureInstancesFile();

      console.log('✅ Configuration files ready\n');
    } catch (error: any) {
      console.error('\n❌ Configuration initialization failed:', error.message);
      console.error('   Stack:', error.stack);
      process.exit(1);
    }
  }

  // Implementation methods...
}

export const configInitializer = new ConfigInitializerService();
```
