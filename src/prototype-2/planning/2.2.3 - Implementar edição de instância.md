# Task Plan: 2.2.3 - Implementar edição de instância

## Context and Objective

Implement the Instance editing functionality for the Setup Module, allowing administrators to modify existing instance configurations. This task reuses the form component from task 2.2.2 (creation) but pre-fills it with existing instance data and handles updates instead of inserts.

**Business Value:** Enables administrators to adjust instance configurations over time without recreating instances, supporting iterative refinement and troubleshooting.

**User Impact:** Users can edit instance settings, update configurations, and enable/disable instances without losing data or having to recreate them.

  ```typescript
  export function useInstance(instanceId: string, options?: Omit<UseJQELQueryOptions<Instance>, 'queryKey'>) {
    return useJQELQuery<Instance>(
      {
        schema: 'backend',
        select: 'instance',
        where: { instanceId: { $eq: instanceId } },
      },
      {
        queryKey: queryKeys.backend.instance(instanceId),
        enabled: !!instanceId,
        ...options,
      }
    );
  }
  ```

**Mutation Hook Pattern:**
- `src/prototype-2/frontend/src/hooks/jqel/useInstanceMutations.ts` - Update instance:
  ```typescript
  export function useUpdateInstance() {
    const queryClient = useQueryClient();
    return useOptimisticMutation<Instance, { instanceId: string; values: Partial<Instance> }>({
      mutationFn: async ({ instanceId, values }) => {
        return updateRecord<Instance>(
          'backend',
          'instance',
          { instanceId: { $eq: instanceId } },
          values as Record<string, unknown>
        );
      },
      onSuccess: (data, { instanceId }) => {
        // Invalidate specific instance + lists
        queryClient.invalidateQueries({ queryKey: queryKeys.backend.instance(instanceId) });
        queryClient.invalidateQueries({ queryKey: queryKeys.backend.instances() });
        if (data?.portalId) {
          queryClient.invalidateQueries({ queryKey: queryKeys.backend.instances(data.portalId) });
        }
      },
    });
  }
  ```

### Gotchas and Pitfalls

- ⚠️ **Immutable fields**: `instanceId`, `portalId`, and `moduleId` CANNOT be changed after creation. Make these fields read-only/disabled in edit mode.
- ⚠️ **Partial updates**: The `useUpdateInstance` mutation only sends changed fields, but for simplicity we can send all editable fields.
- ⚠️ **Config validation**: Changes to `config` should be validated against module schema (task 2.2.5), but for now accept any valid JSON.
- ⚠️ **Form reset timing**: Call `form.reset(data)` inside `useEffect` when instance data loads to avoid race conditions.
- ⚠️ **Navigation state**: After save, navigate back to instance list, not to the edit page (to show updated data).
- ⚠️ **Loading state**: Show skeleton during initial fetch; don't render form until data is loaded.
- ⚠️ **404 handling**: If `instanceId` doesn't exist, show error and redirect to instance list.

### Existing Patterns to Follow

- **Form reuse**: Use same InstanceForm component, pass `mode` prop to differentiate create/edit
- **Loading states**: See SPEC-MS-LO-001 - Show skeleton during fetch
- **Immutable fields**: Disable fields that can't be edited (instanceId, portalId, moduleId)
- **Success feedback**: See SPEC-MS-FB-005:007 - Toast notification after save
- **Error feedback**: See SPEC-MS-FB-008:011 - Clear, field-specific errors

```
  2. Fetch instance via useInstance(instanceId)

  6. On success: navigate to instance list + toast
```

### Data Flow

```
User navigates to edit page → Fetch instance data

1. Extract instanceId from URL params
2. Call useInstance(instanceId) → TanStack Query
   - Query backend for instance
   - If found: Continue to step 3
   - If not found: Show 404 error, redirect to list

3. Pre-fill form with instance data
   - Use form.reset(instanceData)
   - Disable immutable fields (instanceId, portalId, moduleId)
   - Enable editable fields (config, active)

User edits form → Submit

4. Validate changes (Zod schema, client-side)
   - If invalid: Show field errors
   - If valid: Continue to step 5

5. Call useUpdateInstance().mutate({ instanceId, values })
   - TanStack Query mutation starts
   - UI: Button shows spinner, form disabled

6. JQEL mutation sent to backend
   POST /api/jqel
   {
     schema: "backend",
     mutate: "instance",
     action: "update",
     where: { instanceId: { $eq: instanceId } },
     values: { config: {...}, active: true }
   }

7. Backend processes mutation
   - Validates data
   - Updates instances.json
   - Returns updated instance

8. Mutation onSuccess callback
   - Invalidate instance queries (cache refresh)
   - Navigate to instance list
   - Show success toast

9. If mutation fails
   - Show error toast
   - Re-enable form
   - Keep user on page
```

**Loaded State (Form Pre-filled):**
- All fields visible with current values

**Editing State (User Typing):**

- All inputs disabled

### Error Handling Strategy

**Error Types:**

- **Instance not found (404)**:
  - Display: Alert "Instance not found or has been deleted"
  - Recovery: "Back to Instances" button, auto-redirect after 3s

- **Fetch error (network)**:
  - Display: Alert "Failed to load instance. Check your connection."
  - Recovery: "Retry" button that refetches data

- **Validation errors (client-side)**:
  - Same as task 2.2.2 (inline errors via FormFieldError)

- **Save error (server/network)**:
  - Display: Toast "Failed to update instance: {error}"
  - Recovery: Form remains enabled, user can retry

**Error Display Pattern:**
```typescript
// 404 / Fetch error
if (error || (!isLoading && !instance)) {
  return (
    <Alert variant="destructive">
      <AlertCircle className="h-4 w-4" />
      <AlertDescription>
        Instance not found or failed to load.
        <Button onClick={() => navigate(`/setup/portals/${portalId}/modules/${moduleId}/instances`)}>
          Back to Instances
        </Button>
      </AlertDescription>
    </Alert>
  );
}

// Save error (toast)
if (updateInstance.isError) {
  toast({
    title: 'Error',
    description: updateInstance.error.message,
    variant: 'destructive',
  });
}
```
