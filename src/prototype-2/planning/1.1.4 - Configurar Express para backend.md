# Task Plan: 1.1.4 - Configurar Express para backend

## Context and Objective

This task implements the foundational Express.js server configuration for prototype-2's Backend layer. The Backend acts as a critical proxy between the Frontend (React 19 + Vite) and Backbone (n8n), handling validation, authentication, routing, and minimal control logic as defined by the three-layer architecture.

**What will be implemented:**
- Express server with TypeScript
- Essential middleware stack (CORS, body parsing, security headers, request logging)
- Environment variable validation and configuration management
- Centralized error handling middleware
- Server initialization with graceful shutdown handling
- Health check endpoint for monitoring

**Why it's needed:**
The Backend serves as the security and routing layer that:
- Enforces security boundaries through CORS, authentication validation, and rate limiting
- Routes JQEL requests by schema (`backend`, `platform`, `system`) to appropriate handlers
- Provides Server-Sent Events (SSE) endpoints for real-time event streaming
- Validates and sanitizes all incoming requests before processing
- Acts as the single point of integration with the n8n Backbone via mutual authentication

**How it integrates:**
- Frontend sends all API requests to Backend endpoints (`/api/jqel`, `/api/1/auth/*`, `/api/events/stream`)
- Backend validates requests and proxies to n8n workflows using X-Platform-Key header for mutual authentication
- Backend subscribes to Redis Pub/Sub channels to receive events from n8n
- Backend relays events to Frontend clients via SSE connections
- Backend processes `schema="backend"` JQEL queries locally (portal/module/instance configurations)

**Business value:**
A properly configured Express server ensures:
- Secure, reliable communication between all architectural layers
- Consistent error handling and structured logging for debugging and monitoring
- Scalable foundation for adding new endpoints and features
- Clear separation of concerns aligning with the three-layer architecture

**User impact:**
While users don't directly interact with this infrastructure layer, it provides:
- Fast, reliable API responses for all user actions
- Secure authentication protecting user data and sessions
- Real-time notifications delivered via SSE
- Graceful error messages instead of application crashes
- System observability through health checks and logging

**Import/Export Patterns:**
- Use ES6 module syntax: `import express from 'express'`
- Named exports for utilities: `export const validateEnv = () => { ... }`
- Default exports for main objects: `export default app;`
- Group imports: Node built-ins → external packages → local modules

**State Management:**
- Express app is **stateless** (no in-memory state)
- Configuration loaded once at startup from environment
- Runtime state stored externally:
  - Redis for cache and Pub/Sub
  - JWT tokens for session state (client-side)
  - File system for configuration (backend/src/config/*.json)

**Error Handling:**
- Use try-catch in async route handlers
- Forward errors to centralized error middleware via `next(err)`
- Error middleware MUST have 4 parameters: `(err, req, res, next)`
- Structure error responses per SPEC-ERR-BOUND-* requirements
- Never expose stack traces or sensitive data in production

### Gotchas and Pitfalls

**Error Middleware Signature:**
- ⚠️ **CRITICAL**: Error middleware MUST have exactly 4 parameters: `(err, req, res, next)`
- Even if `next` is unused, it MUST be present for Express to recognize it as error middleware
- With only 3 parameters, Express treats it as regular middleware and won't catch errors
- Error middleware MUST be registered AFTER all routes

**CORS Configuration:**
- ⚠️ CORS middleware MUST be registered BEFORE routes
- Must explicitly set `credentials: true` to allow cookies and Authorization headers
- `origin` must match Frontend URL exactly (no trailing slash mismatch)
- In development, `localhost:5173` and `localhost:3000` are different origins
- Preflight requests (OPTIONS) must be handled automatically by cors middleware

**Body Parser Limits:**
- ⚠️ Default body size limit is 100kb - too small for some use cases
- Set `limit` parameter in `express.json()` and `express.urlencoded()`
- Recommended: 10mb for API endpoints (can adjust per route if needed)
- Large payloads without limits are a DoS attack vector

**TypeScript with Express:**
- ⚠️ Middleware `next` parameter type is `NextFunction` from 'express', not `Function`
- Request/Response types: `Request`, `Response` from 'express'
- To add custom properties to req, extend Express types using declaration merging
- Async middleware requires proper error handling (Express doesn't catch async errors by default)

**Environment Variables:**
- ⚠️ **CRITICAL**: `dotenv.config()` MUST be called before any imports that use env vars
- Place at very top of index.ts (or in separate env.ts that's imported first)
- Missing required env vars MUST crash the app immediately (fail-fast principle)
- Never use `process.env.VAR` directly - use typed config object

**Async Error Handling:**
- ⚠️ Express (v4) doesn't automatically catch errors in async route handlers
- Must wrap async handlers with try-catch or use async wrapper utility
- Unhandled promise rejections can crash the server silently
- Solution: Global handlers for `unhandledRejection` and `uncaughtException`

**Helmet Security Headers:**
- ⚠️ Default Helmet CSP may block legitimate Frontend assets (inline scripts, styles)
- Must customize CSP directives for Vite dev server and production build
- HSTS header should only be enabled in production with valid HTTPS
- In development, relax CSP to avoid blocking hot reload

**Port Binding:**
- ⚠️ If PORT is already in use, server will fail to start
- Provide clear error message: "Port 3000 is already in use"
- Suggest checking for other running instances or changing PORT in .env

### Data Flow

**Request Lifecycle:**
```
Incoming HTTP Request
    ↓
[1. Security Middleware (Helmet)]
    ├─ Adds security headers
    ├─ Configures CSP
    └─ Sets HSTS (prod only)
    ↓
[2. CORS Middleware]
    ├─ Checks origin against whitelist
    ├─ Handles preflight requests
    └─ Rejects if origin not allowed
    ↓
[3. Logger Middleware (Morgan)]
    ├─ Logs request method, URL, IP
    └─ Sanitizes sensitive data
    ↓
[4. Body Parser]
    ├─ Parses JSON bodies (limit: 10mb)
    └─ Parses URL-encoded bodies
    ↓
[5. Compression Middleware]
    └─ Compresses responses (gzip)
    ↓
[6. Routes]
    ├─ /api/health        → Health check
    ├─ /api/1/auth/*      → (future) Auth endpoints
    ├─ /api/jqel          → (future) JQEL processor
    └─ /api/events/stream → (future) SSE endpoint
    ↓
[7. 404 Handler]
    └─ Route not found
    ↓
[8. Error Middleware]
    ├─ Catches all errors
    ├─ Logs with context
    └─ Returns structured response
    ↓
HTTP Response to Client
```

**Middleware Order is Critical:**
1. Security headers FIRST (before any processing)
2. CORS BEFORE routes (handles preflight)
3. Logging AFTER CORS (log successful requests only)
4. Body parsing BEFORE routes
5. Routes in the middle
6. 404 handler AFTER all routes
7. Error handler LAST (4-parameter middleware)

### Modules and Responsibilities

**index.ts (Server Entry Point)**
- **Responsibility:** Application bootstrapping and lifecycle management
- **Actions:**
  - Load environment variables via dotenv at the very top
  - Import and validate configuration from config/env.ts
  - Import configured Express app from app.ts
  - Create HTTP server with the app
  - Start listening on configured PORT
  - Set up graceful shutdown handlers (SIGTERM, SIGINT)
  - Handle unhandled promise rejections
  - Handle uncaught exceptions
  - Log startup information (port, environment, URLs)

**app.ts (Express App Configuration)**
- **Responsibility:** Express application setup and middleware orchestration
- **Actions:**
  - Create Express instance
  - Register middleware in correct order (security → CORS → logging → parsing → compression)
  - Mount route handlers (/api/health, future routes)
  - Register 404 handler (after routes)
  - Register error handler (last, with 4 parameters)
  - Export configured app for testing and server startup

**config/env.ts (Environment Validation)**
- **Responsibility:** Environment configuration validation and typed access
- **Actions:**
  - Load .env file using dotenv
  - Define EnvConfig TypeScript interface
  - Validate all required environment variables exist
  - Validate data types (port as number, URLs as valid URLs, etc.)
  - Validate value ranges (port 1-65535, secret length >= 32 chars)
  - Log all validation errors at once (not one at a time)
  - Exit process immediately if any validation fails (fail-fast)
  - Export typed config object for use throughout application

**middleware/cors.middleware.ts (CORS Configuration)**
- **Responsibility:** Cross-Origin Resource Sharing policy
- **Configuration:**
  - origin: FRONTEND_URL from environment (exact match)
  - credentials: true (allow cookies and Authorization header)
  - methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'OPTIONS']
  - allowedHeaders: ['Content-Type', 'Authorization', 'X-Platform-Key']
  - exposedHeaders: ['X-Total-Count', 'X-Page-Count'] (for pagination)
  - maxAge: 86400 (cache preflight for 24 hours)

**middleware/errorHandler.middleware.ts (Error Handling)**
- **Responsibility:** Centralized error catching and formatting
- **Actions:**
  - Catch all errors passed via next(err)
  - Log error with context (timestamp, URL, method, user ID if available)
  - Determine HTTP status code (from error or default 500)
  - Build structured error response:
    - code: HTTP status
    - message: Error message
    - field: (optional) Which field caused validation error
    - details: (dev only) Additional error context
    - stack: (dev only) Stack trace
  - Send JSON response with appropriate status code
  - Never expose sensitive data or stack traces in production

**middleware/logger.middleware.ts (Request Logging)**
- **Responsibility:** HTTP request/response logging
- **Configuration:**
  - Use morgan with custom format
  - Development format: detailed with response time
  - Production format: minimal (IP, method, URL, status)
  - Sanitize sensitive data (passwords, tokens in request bodies)
  - Skip health check logs in production (reduce noise)
  - Log to console (can be extended to file/service later)

**middleware/security.middleware.ts (Security Headers)**
- **Responsibility:** Set security-related HTTP headers
- **Configuration via Helmet:**
  - Content-Security-Policy (CSP): Control resource loading
  - HTTP Strict Transport Security (HSTS): Force HTTPS (prod only)
  - X-Frame-Options: DENY (prevent clickjacking)
  - X-Content-Type-Options: nosniff (prevent MIME sniffing)
  - X-XSS-Protection: Enable browser XSS filter
  - Referrer-Policy: strict-origin-when-cross-origin
- **Environment-specific:**
  - Production: Full security with HSTS
  - Development: Relaxed CSP, no HSTS

**routes/health.routes.ts (Health Check Endpoint)**

- **Endpoint:** GET /api/health

### State Management

The Express backend is **stateless by design**:

- **No in-memory application state**
  - Each request is independent
  - No global variables for session or user data
  - Horizontal scaling is possible (multiple instances)

- **Configuration state:**
  - Loaded once at startup from .env
  - Immutable during runtime
  - Requires restart to apply changes

- **Session/Auth state:**
  - Stored in JWT tokens (client-side)
  - Backend validates JWT on each request
  - No server-side session storage

- **Cache and shared state (future):**
  - Redis for distributed cache
  - Redis Pub/Sub for real-time events
  - Redis Streams for event buffering

- **Application configuration:**
  - File system: backend/src/config/*.json
  - Accessed via JQEL with schema="backend"
  - Modified via mutations through JQEL

```typescript
import dotenv from 'dotenv';
import { resolve } from 'path';

// Load .env file FIRST (before any other imports that use env vars)
dotenv.config({ path: resolve(__dirname, '../../.env') });

export interface EnvConfig {
  // Server
  nodeEnv: 'development' | 'staging' | 'production';
  port: number;
  frontendUrl: string;

  // n8n Backbone
  n8nBaseUrl: string;
  n8nSharedSecret: string;

  // Redis
  redisHost: string;
  redisPort: number;
  redisPassword?: string;
  redisDb: number;

  // JWT
  jwtSecret: string;
  jwtAccessTokenExpiresIn: string;
  jwtRefreshTokenExpiresIn: string;

  // Platform Security
  platformSharedSecret: string;

  // Optional (with defaults)
  logLevel: 'debug' | 'info' | 'warn' | 'error';
  requestTimeout: number;
  sseHeartbeatInterval: number;
}

function validateEnv(): EnvConfig {
  const errors: string[] = [];

  // Helper: Get required environment variable
  const getRequired = (key: string): string => {
    const value = process.env[key];
    if (!value || value.trim() === '') {
      errors.push(`Missing required environment variable: ${key}`);
    }
    return value || '';
  };

  // Helper: Get optional environment variable with default
  const getOptional = (key: string, defaultValue: string): string => {
    return process.env[key] || defaultValue;
  };

  // Validate NODE_ENV
  const nodeEnv = getRequired('NODE_ENV');
  const validNodeEnvs = ['development', 'staging', 'production'];
  if (nodeEnv && !validNodeEnvs.includes(nodeEnv)) {
    errors.push(`NODE_ENV must be one of: ${validNodeEnvs.join(', ')}`);
  }

  // Validate PORT
  const portStr = getOptional('PORT', '3000');
  const port = parseInt(portStr, 10);
  if (isNaN(port) || port < 1 || port > 65535) {
    errors.push('PORT must be a number between 1 and 65535');
  }

  // Validate URLs
  const frontendUrl = getRequired('FRONTEND_URL');
  const n8nBaseUrl = getRequired('N8N_BASE_URL');

  try {
    if (frontendUrl) new URL(frontendUrl);
  } catch {
    errors.push('FRONTEND_URL must be a valid URL');
  }

  try {
    if (n8nBaseUrl) new URL(n8nBaseUrl);
  } catch {
    errors.push('N8N_BASE_URL must be a valid URL');
  }

  // Validate secrets (minimum 32 characters)
  const n8nSharedSecret = getRequired('N8N_SHARED_SECRET');
  const jwtSecret = getRequired('JWT_SECRET');
  const platformSharedSecret = getRequired('PLATFORM_SHARED_SECRET');

  if (n8nSharedSecret && n8nSharedSecret.length < 32) {
    errors.push('N8N_SHARED_SECRET must be at least 32 characters long');
  }

  if (jwtSecret && jwtSecret.length < 32) {
    errors.push('JWT_SECRET must be at least 32 characters long');
  }

  if (platformSharedSecret && platformSharedSecret.length < 32) {
    errors.push('PLATFORM_SHARED_SECRET must be at least 32 characters long');
  }

  // Validate Redis configuration
  const redisPortStr = getOptional('REDIS_PORT', '6379');
  const redisPort = parseInt(redisPortStr, 10);
  if (isNaN(redisPort) || redisPort < 1 || redisPort > 65535) {
    errors.push('REDIS_PORT must be a number between 1 and 65535');
  }

  // Validate log level
  const logLevel = getOptional('LOG_LEVEL', 'info');
  const validLogLevels = ['debug', 'info', 'warn', 'error'];
  if (!validLogLevels.includes(logLevel)) {
    errors.push(`LOG_LEVEL must be one of: ${validLogLevels.join(', ')}`);
  }

  // If there are validation errors, log them and exit
  if (errors.length > 0) {
    console.error('\n❌ Environment validation failed:\n');
    errors.forEach(err => console.error(`   - ${err}`));
    console.error('\n📝 Please check your .env file against .env.example\n');
    process.exit(1);
  }

  // Return validated and typed configuration
  return {
    nodeEnv: nodeEnv as 'development' | 'staging' | 'production',
    port,
    frontendUrl,
    n8nBaseUrl,
    n8nSharedSecret,
    redisHost: getOptional('REDIS_HOST', 'localhost'),
    redisPort,
    redisPassword: process.env.REDIS_PASSWORD,
    redisDb: parseInt(getOptional('REDIS_DB', '0'), 10),
    jwtSecret,
    jwtAccessTokenExpiresIn: getOptional('JWT_ACCESS_TOKEN_EXPIRES_IN', '15m'),
    jwtRefreshTokenExpiresIn: getOptional('JWT_REFRESH_TOKEN_EXPIRES_IN', '7d'),
    platformSharedSecret,
    logLevel: logLevel as 'debug' | 'info' | 'warn' | 'error',
    requestTimeout: parseInt(getOptional('REQUEST_TIMEOUT', '30000'), 10),
    sseHeartbeatInterval: parseInt(getOptional('SSE_HEARTBEAT_INTERVAL', '30000'), 10),
  };
}

// Validate and export configuration
export const config = validateEnv();

// Log startup information (non-sensitive)
console.log('\n✅ Environment configuration loaded:');
console.log(`   - Environment: ${config.nodeEnv}`);
console.log(`   - Port: ${config.port}`);
console.log(`   - Frontend URL: ${config.frontendUrl}`);
console.log(`   - n8n URL: ${config.n8nBaseUrl}`);
console.log(`   - Redis: ${config.redisHost}:${config.redisPort}\n`);
```

```typescript
import { Request, Response, NextFunction } from 'express';
import { config } from '../config/env';

/**
 * Structured error response format
 */
export interface ErrorResponse {
  code: number;
  message: string;
  field?: string;      // Optional: which field caused validation error
  details?: any;       // Optional: additional context (dev only)
  stack?: string;      // Optional: stack trace (dev only)
}

/**
 * Centralized error handling middleware
 *
 * Implements SPEC-ERR-BOUND-001 to SPEC-ERR-BOUND-004:
 * - Catches all errors passed via next(err)
 * - Logs errors with context
 * - Returns structured JSON responses
 * - Hides sensitive details in production
 *
 * IMPORTANT: Must have 4 parameters for Express to recognize as error middleware
 */
export const errorHandler = (
  err: any,
  req: Request,
  res: Response,
  next: NextFunction // Must be present even if unused!
) => {
  // Log error with context
  console.error('\n❌ Error caught by error handler:');
  console.error({
    timestamp: new Date().toISOString(),
    message: err.message,
    stack: config.nodeEnv === 'development' ? err.stack : undefined,
    url: req.url,
    method: req.method,
    ip: req.ip,
  });

  // Determine HTTP status code
  const statusCode = err.statusCode || err.status || 500;

  // Build error response
  const errorResponse: ErrorResponse = {
    code: statusCode,
    message: err.message || 'Internal Server Error',
  };

  // Add optional field if present (validation errors)
  if (err.field) {
    errorResponse.field = err.field;
  }

  // Include additional details only in development
  if (config.nodeEnv === 'development') {
    if (err.details) {
      errorResponse.details = err.details;
    }
    if (err.stack) {
      errorResponse.stack = err.stack;
    }
  }

  // Send JSON error response
  res.status(statusCode).json(errorResponse);
};

/**
 * 404 Not Found handler
 * Must be registered BEFORE the error handler
 */
export const notFoundHandler = (
  req: Request,
  res: Response,
  next: NextFunction
) => {
  const error: any = new Error(`Route not found: ${req.method} ${req.url}`);
  error.statusCode = 404;
  next(error);
};
```

### Error Handling Strategy

**Error Types Handled:**

1. **Environment Validation Errors**
   - When: Missing or invalid .env variables
   - Handling: Collect all errors, log clearly, exit immediately (fail-fast)
   - User Impact: Clear error messages guide developers to fix configuration

2. **Port Binding Errors**
   - When: PORT already in use by another process
   - Handling: Catch 'EADDRINUSE' error, log helpful message, exit
   - User Impact: Developer knows to check for other running instances

3. **Runtime Request Errors**
   - When: Invalid requests, malformed JSON, route not found
   - Handling: Catch in error middleware, return appropriate HTTP status
   - User Impact: Structured error responses with clear messages

4. **Unhandled Promise Rejections**
   - When: Async errors not caught with try-catch
   - Handling: Log error, exit in production (unstable state)
   - User Impact: System exits gracefully rather than hanging

5. **Uncaught Exceptions**
   - When: Synchronous errors not caught
   - Handling: Log error, always exit (application state is unstable)
   - User Impact: System exits rather than continuing in broken state

### Environment Validation Tests

**Test 1: Missing Required Variable**
Create `.env` without NODE_ENV:
```bash
# .env (incomplete)
PORT=3000
```

Run server:
```bash
npm run dev
```

**Expected Output:**
```
❌ Environment validation failed:

   - Missing required environment variable: NODE_ENV
   - Missing required environment variable: FRONTEND_URL
   - Missing required environment variable: N8N_BASE_URL
   - Missing required environment variable: N8N_SHARED_SECRET
   - Missing required environment variable: JWT_SECRET
   - Missing required environment variable: PLATFORM_SHARED_SECRET

📝 Please check your .env file against .env.example
```

**Test 2: Invalid Port**
```bash
# .env
NODE_ENV=development
PORT=99999
FRONTEND_URL=http://localhost:5173
# ... other required vars
```

**Expected Output:**
```
❌ Environment validation failed:

   - PORT must be a number between 1 and 65535
```

```bash
# .env
# ... other vars
JWT_SECRET=short
```

**Expected Output:**
