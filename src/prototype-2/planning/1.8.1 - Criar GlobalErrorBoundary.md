# Task Plan: 1.8.1 - Criar GlobalErrorBoundary

## Context and Objective

This task implements the **Global Error Boundary** for the entire application, the outermost safety net that catches all unhandled React errors. This is the first level in a three-tier error boundary system (Global → Portal → Module).

**What will be implemented:**
- Enhance existing `ErrorBoundary` component to work as the global boundary
- Create a specialized `GlobalErrorFallback` UI component
- Integrate with error logging system
- Ensure proper wrapping of the entire application tree

**Why it's needed:**
- SPEC-ERR-BOUND-001: Application MUST have a global error boundary
- SPEC-ERR-BOUND-002: Must capture all unhandled errors
- SPEC-ERR-BOUND-003: Must display appropriate fallback UI
- SPEC-ERR-BOUND-004: Errors must be logged for monitoring
- Prevents white screen of death (WSOD) in production

**How it integrates:**
- Wraps the entire application at the root level (App.tsx)
- Works in conjunction with Portal and Module error boundaries
- Integrates with the existing `errorLogger` service
- Last resort before error reaches browser console

**Business value:**
- Provides graceful degradation when critical errors occur
- Improves user experience by showing actionable error messages instead of blank screen
- Enables error monitoring and debugging in production
- Protects brand reputation by preventing unprofessional error displays

**User impact:**
- Users see a friendly error page instead of a broken application
- Clear "Reload Page" action to recover from errors
- Development mode shows technical details for debugging
- Production mode hides sensitive information while maintaining usability

## Critical Context

### Documentation

**React Error Boundaries:**
- [React Error Boundaries - Official Docs](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)
  - Static `getDerivedStateFromError()` for state updates
  - `componentDidCatch()` for side effects (logging)
  - Error boundaries do NOT catch errors in: event handlers, async code, server-side rendering, errors in the boundary itself

**ARIA for Errors:**
- [ARIA Live Regions](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Live_Regions)
  - Use `role="alert"` for error messages
  - Use `aria-live="assertive"` for critical errors
  - Ensures screen readers announce errors immediately

### Gotchas and Pitfalls

**Error Boundary Limitations:**
- ⚠️ Error boundaries only catch errors during rendering, in lifecycle methods, and in constructors
- ⚠️ They do NOT catch errors in: event handlers, setTimeout/setInterval, async code (promises, async/await)
- ⚠️ For async errors, use try/catch and display via state
- ⚠️ Error boundary itself must not throw - wrap in try/catch if needed

**React 19 Specifics:**
- ⚠️ React 19 improved error boundary behavior but core API unchanged
- ⚠️ Must use class components (no hooks equivalent yet)
- ⚠️ `getDerivedStateFromError` is static - cannot access `this`

**Common Mistakes:**
- ⚠️ Forgetting to provide fallback - boundary must always render something
- ⚠️ Not differentiating between dev and prod - stack traces leak in production
- ⚠️ Catching too much - boundaries should be strategic, not wrap every component
- ⚠️ Infinite error loops - if fallback throws, can crash app

**Accessibility:**
- ⚠️ Must provide keyboard-accessible actions (buttons, not divs)
- ⚠️ Must announce errors to screen readers (role="alert")
- ⚠️ Focus management after error may be needed

### Error Handling Strategy

**Error Types:**
- **React rendering errors:** Caught by ErrorBoundary automatically
  - Display GlobalErrorFallback
  - Log with category 'error-boundary'

- **Errors in fallback itself:** NOT caught (would cause infinite loop)
  - Prevent by: Keep fallback simple, no complex logic, no async operations
  - Test thoroughly in development

- **Async errors (not caught):** Require separate handling
  - Use try/catch in async functions
  - Display via toast or inline error states
  - DO NOT rely on error boundary for async

**Error Display Pattern:**
