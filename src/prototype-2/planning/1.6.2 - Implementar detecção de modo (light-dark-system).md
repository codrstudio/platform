# Task Plan: 1.6.2 - Implementar detecção de modo (light/dark/system)

## Context and Objective

This task implements the theme mode detection system that handles three modes: `light`, `dark`, and `system`. The system mode is special - it automatically detects the user's OS/browser preference using the `prefers-color-scheme` media query and updates the theme dynamically when the OS preference changes.

**Business Value:** Users can choose to have the application automatically match their system's appearance preference, providing a seamless experience that respects their OS settings. This is particularly valuable for users who switch between light and dark modes based on time of day or environment.

**Integration Point:** This functionality is integrated directly into the ThemeProvider component created in Task 1.6.1. The detection logic resolves the `system` mode to either `light` or `dark` based on the OS preference and listens for changes.

### Gotchas and Pitfalls

- **Event Listener Cleanup:** MUST remove event listener in cleanup function to prevent memory leaks. The media query listener will continue firing even if the component unmounts if not cleaned up.

- **Initial Detection:** Must detect system preference immediately on mount, not just when it changes. Use `mediaQuery.matches` property for initial value.

- **Effect Dependencies:** The effect that sets up the media query listener should only depend on `rawTheme` (the user's preference). If `rawTheme` is not "system", cleanup and don't set up listener.

- **Browser Compatibility:** `matchMedia` is widely supported, but older browsers might not support it. Add fallback to "light" theme if `window.matchMedia` is undefined (though this is rare).

- **Reactive Updates:** When OS theme changes and user has selected "system" mode, the `theme` state (resolved theme) must update immediately. Use state setter in the event listener callback.

- **Double Effect:** You may have two effects:
  1. One that resolves `rawTheme` → `theme` (handles "system" → "light"/"dark" conversion)
  2. One that applies `theme` to DOM (adds class to `<html>`)

  Keep these separate for clarity and proper dependency management.

**Resolution Logic:**
- If `rawTheme === "light"` → `theme = "light"`
- If `rawTheme === "dark"` → `theme = "dark"`
- If `rawTheme === "system"` → detect from OS and listen for changes

### Implementation Algorithm

**Step 1: Detect current OS preference**
```typescript
const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');
const prefersDark = mediaQuery.matches;
const resolvedTheme = prefersDark ? 'dark' : 'light';
```

**Step 2: Listen for OS preference changes**
```typescript
const handleChange = (e: MediaQueryListEvent) => {
  setTheme(e.matches ? 'dark' : 'light');
};

mediaQuery.addEventListener('change', handleChange);
```

**Step 3: Cleanup listener**
```typescript
return () => {
  mediaQuery.removeEventListener('change', handleChange);
};
```

## Implementation Blueprint

### Ordered Steps

1. **Update ThemeProvider component** (`src/providers/ThemeProvider.tsx`)

   **1.1. Add helper function for system theme detection:**
   ```typescript
   /**
    * Detect system theme preference
    * Returns 'dark' if user prefers dark mode, 'light' otherwise
    */
   function detectSystemTheme(): 'light' | 'dark' {
     // Check if matchMedia is available (browser compatibility)
     if (typeof window === 'undefined' || !window.matchMedia) {
       console.warn('matchMedia not available, defaulting to light theme');
       return 'light';
     }

     const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');
     return mediaQuery.matches ? 'dark' : 'light';
   }
   ```

   **1.2. Replace or enhance the theme resolution effect:**
   ```typescript
   // Effect: Resolve "system" theme to actual theme
   useEffect(() => {
     // If not system mode, apply user's choice directly
     if (rawTheme !== 'system') {
       setTheme(rawTheme as 'light' | 'dark');
       return; // No listener needed
     }

     // System mode - detect initial preference
     const initialTheme = detectSystemTheme();
     setTheme(initialTheme);

     // Set up listener for OS theme changes
     const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');

     const handleThemeChange = (e: MediaQueryListEvent) => {
       const newTheme = e.matches ? 'dark' : 'light';
       console.log(`System theme changed to: ${newTheme}`);
       setTheme(newTheme);
     };

     // Add listener
     mediaQuery.addEventListener('change', handleThemeChange);

     // Cleanup listener on unmount or when rawTheme changes
     return () => {
       mediaQuery.removeEventListener('change', handleThemeChange);
     };
   }, [rawTheme]); // Re-run if user changes preference to/from "system"
   ```

   **1.3. Ensure the DOM application effect runs when `theme` changes:**
   ```typescript
   // Effect: Apply resolved theme to DOM
   useEffect(() => {
     // Remove both classes first
     document.documentElement.classList.remove('light', 'dark');

     // Add the resolved theme class (never "system")
     document.documentElement.classList.add(theme);

     console.log(`Applied theme: ${theme}`);
   }, [theme]); // Re-run when resolved theme changes
   ```
