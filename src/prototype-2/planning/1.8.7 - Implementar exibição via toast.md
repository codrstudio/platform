# Task Plan: 1.8.7 - Implementar exibição via toast

## Context and Objective

This task implements toast-based error display integration with the structured logging system. While basic toast UI exists (`use-toast.ts` and `toaster.tsx`), this task creates error-specific toast utilities that automatically log errors, show user-friendly messages, and integrate with the logging system from Tasks 1.8.5 and 1.8.6.

**What will be implemented:**
- Error-to-toast adapter functions (`showErrorToast`, `showWarningToast`, etc.)
- Automatic error logging when toast is shown
- User-friendly message generation from technical errors
- Semantic toast variants matching error severity (error, warning, success, info)
- Integration with JQEL errors, Auth errors, SSE errors
- Retry action support in toast notifications

**Why it's needed:**
Current toast implementation is generic and lacks:
1. Automatic error logging when displaying toasts
2. Error type detection and user-friendly message conversion
3. Integration with structured logging system
4. Semantic variant mapping (JQELError → appropriate toast type)
5. Retry action utilities for recoverable errors

**How it integrates:**
- Uses existing `toast()` from `use-toast.ts` as foundation
- Integrates with `logError()` from Task 1.8.6 (structured logging)
- Used by error boundaries, JQEL hooks, SSE handlers, Auth components
- Follows SPEC-EH-DI-001:004 (toast display requirements)

**Business value:**
- Consistent error messaging across the platform
- Better user experience with actionable error messages
- Complete error tracking (all toasts are logged)
- Reduced developer burden (automatic message generation)

**User impact:**
- Direct: Users see clear, actionable error messages in toasts
- Better UX: Semantic colors and icons indicate error severity
- Actionable: Retry buttons for recoverable errors
- Non-intrusive: Toasts auto-dismiss after appropriate duration

### Gotchas and Pitfalls

**⚠️ Toast Stacking Limit**
- Max 3 toasts visible simultaneously (SPEC-EH-DI-003)
- Older toasts are removed when limit reached
- Avoid showing many toasts in rapid succession

**⚠️ Action Button Memory Leaks**
- Retry callbacks can capture component state
- Use useCallback for retry functions to prevent stale closures
- Clean up timeouts if component unmounts

**⚠️ Error Message Security**
- Never expose stack traces in user-facing toasts
- Don't include request/response bodies (may contain sensitive data)
- Use generic messages for authentication errors (don't reveal if user exists)

**⚠️ Duplicate Toast Prevention**
- Same error shown multiple times if multiple components fail
- Consider debouncing or deduplicating identical messages
- Use toast IDs to track and prevent duplicates

**⚠️ Async Error Handling**
- Errors from async functions may occur after component unmount
- Check component is still mounted before showing toast
- TanStack Query handles this automatically for query errors

```typescript
/**
 * Error Toast Display - User-friendly error notifications
 * Based on SPEC-EH-DI-001:004
 */

import { toast, type ToastVariant } from '../../hooks/use-toast';
import { logError, logWarning } from './errorLogger';
import { isJQELError, type JQELError } from '../jqel/errors';

/**
 * Options for error toast display
 */
export interface ErrorToastOptions {
  /**
   * Error category for logging
   * @default 'error'
   */
  category?: string;

  /**
   * Custom user-facing title (overrides automatic title)
   */
  title?: string;

  /**
   * Custom user-facing message (overrides automatic message)
   */
  message?: string;

  /**
   * Retry callback for recoverable errors
   */
  onRetry?: () => void;

  /**
   * Toast duration in milliseconds (overrides automatic calculation)
   */
  duration?: number;

  /**
   * Additional context for logging
   */
  context?: Record<string, any>;

  /**
   * Whether to log the error (default: true)
   */
  logError?: boolean;
}

/**
 * Get user-friendly error message from error object
 * Based on SPEC-ERR-* error categories
 */
export function getErrorMessage(error: unknown): string {
  // Handle null/undefined
  if (!error) {
    return 'An unexpected error occurred.';
  }

  // Handle JQELError with built-in user messages
  if (isJQELError(error)) {
    return error.getUserMessage();
  }

  // Handle standard Error objects
  if (error instanceof Error) {
    // Network errors
    if (error.name === 'NetworkError' || error.message.includes('network') || error.message.includes('fetch')) {
      return 'Connection error. Please check your internet connection.';
    }

    // Timeout errors
    if (error.message.includes('timeout') || error.message.includes('timed out')) {
      return 'Request timed out. Please try again.';
    }

    // Generic error message (sanitized)
    return error.message || 'An unexpected error occurred.';
  }

  // Handle string errors
  if (typeof error === 'string') {
    return error;
  }

  // Fallback for unknown error types
  return 'An unexpected error occurred.';
}

/**
 * Get appropriate toast title based on error type
 */
export function getErrorTitle(error: unknown): string {
  if (isJQELError(error)) {
    if (error.isValidationError()) return 'Validation Error';
    if (error.isAuthError()) return 'Authentication Error';
    if (error.isNotFound()) return 'Not Found';
    if (error.isServerError()) return 'Server Error';
    return 'Error';
  }

  if (error instanceof Error) {
    if (error.name === 'NetworkError') return 'Connection Error';
    if (error.message.includes('timeout')) return 'Timeout Error';
  }

  return 'Error';
}

/**
 * Calculate toast duration based on message length and severity
 * Based on SPEC-EH-DI-002 (4-6 seconds)
 */
export function getToastDuration(message: string, isError = true): number {
  const baselineDuration = isError ? 5000 : 4000;
  const wordsPerSecond = 3; // Average reading speed
  const words = message.split(' ').length;
  const readingTime = (words / wordsPerSecond) * 1000;

  // Min 3s, max 8s
  return Math.min(Math.max(readingTime, 3000), 8000);
}
```

```typescript
/**
 * Show error toast with automatic logging
 * Based on SPEC-EH-DI-001:004
 *
 * @param error - Error object to display
 * @param options - Display and logging options
 *
 * @example
 * // Basic usage
 * try {
 *   await queryData();
 * } catch (error) {
 *   showErrorToast(error, { category: 'data-query' });
 * }
 *
 * @example
 * // With retry action
 * showErrorToast(error, {
 *   category: 'data-mutation',
 *   onRetry: () => mutation.mutate()
 * });
 *
 * @example
 * // Custom message
 * showErrorToast(error, {
 *   category: 'custom',
 *   title: 'Upload Failed',
 *   message: 'Could not upload file. Please try again.'
 * });
 */
export function showErrorToast(error: unknown, options: ErrorToastOptions = {}): void {
  const {
    category = 'error',
    title,
    message,
    onRetry,
    duration,
    context,
    logError: shouldLog = true
  } = options;

  // Generate user-friendly messages
  const toastTitle = title || getErrorTitle(error);
  const toastMessage = message || getErrorMessage(error);
  const toastDuration = duration || getToastDuration(toastMessage, true);

  // Log error if enabled
  if (shouldLog && error instanceof Error) {
    logError(error, {
      category,
      level: 'ERROR',
      context: {
        toastShown: true,
        userMessage: toastMessage,
        ...context
      }
    });
  }

  // Show toast notification
  toast({
    variant: 'error',
    title: toastTitle,
    description: toastMessage,
    duration: toastDuration,
    action: onRetry ? {
      label: 'Retry',
      onClick: onRetry
    } : undefined
  });
}
```

/**
 * Show warning toast with optional logging
 * Based on SPEC-EH-DI-001:004
 */
export function showWarningToast(
  message: string,
  options: Omit<ErrorToastOptions, 'message'> = {}
): void {
  const {
    category = 'warning',
    title = 'Warning',
    duration,
    context,
    logError: shouldLog = true
  } = options;

  const toastDuration = duration || getToastDuration(message, false);

  // Log warning if enabled
  if (shouldLog) {
    logWarning(message, category, {
      toastShown: true,
      ...context
    });
  }

  toast({
    variant: 'warning',
    title,
    description: message,
    duration: toastDuration
  });
}

/**

### Error Handling Strategy

**Error Toast Display Never Throws:**
- Wrap all toast display in try-catch
- Fallback to console.error if toast fails
- Never let toast display errors crash the app

**Graceful Degradation:**
- If logging fails, still show toast
- If toast fails, still log error
- Both systems should be independent

**Error Display Pattern:**
