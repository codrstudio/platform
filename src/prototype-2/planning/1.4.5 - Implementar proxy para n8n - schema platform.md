# Task Plan: 1.4.5 - Implementar proxy para n8n (schema "platform")

## Context and Objective

This task implements JQEL query proxying to the n8n Backbone for the `platform` schema. When the Backend receives a JQEL query with `schema: "platform"`, it must forward the query to n8n for processing and return the results to the Frontend.

**What will be implemented:**
- Extension of existing `n8nProxyService` to support JQEL queries
- JQEL endpoint routing logic for schema-based delegation
- Error handling and response transformation
- Integration with existing authentication and security patterns

**Why it's needed:**
- The platform uses JQEL as the sole data access method (SPEC-A-D-001)
- The `platform` schema must be processed by the Backbone (n8n) (SPEC-A-D-007)
- Backend acts as proxy between Frontend and Backbone (SPEC-A-L-011)

**How it integrates:**
- Extends existing `n8nProxyService` pattern from task 1.3.1 (authentication)
- Integrates with future JQEL endpoint (task 1.4.1) for routing logic
- Provides foundation for other schema routing (backend, system, application schemas)

**Business value:**
- Enables Frontend to access platform-wide data through unified JQEL interface
- Maintains architectural boundaries (Frontend never talks directly to n8n)
- Ensures all data access goes through validated, authenticated proxy layer

**User impact:**
- Users can query platform configuration, system settings, and cross-module data
- All data queries are secured and validated consistently
- Performance is optimized through existing n8n infrastructure

**Pattern 1: Service method with n8n proxy (from n8nProxy.service.ts)**
```typescript
// File: backend/src/services/n8nProxy.service.ts

/**
 * Call n8n auth-login workflow
 *
 * SPEC-AU-LI-007:011: Backend proxies credentials to n8n for validation
 */
async login(credentials: LoginCredentials): Promise<N8nUserData> {
  const response = await this.callWorkflow<N8nLoginResponse>(
    '/webhook/auth/login',
    credentials
  );

  return response.data.user;
}

/**
 * Generic method to call n8n webhook
 *
 * Handles HTTP communication, authentication, timeout, and error handling.
 */
private async callWorkflow<T>(
  path: string,
  data: any,
  options?: { timeout?: number }
): Promise<T> {
  const timeout = options?.timeout || this.defaultTimeout;
  const url = `${this.baseUrl}${path}`;

  // Setup timeout using AbortController
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeout);

  try {
    // Make HTTP request to n8n
    const response = await fetch(url, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'X-Platform-Key': this.platformKey,
      },
      body: JSON.stringify(data),
      signal: controller.signal,
    });

    // Parse response body
    let responseData: any;
    try {
      responseData = await response.json();
    } catch (error) {
      throw new Error(`n8n returned invalid JSON: ${error}`);
    }

    // Check HTTP status
    if (!response.ok) {
      const errorMessage = responseData?.message || 'Unknown error';

      if (response.status >= 500) {
        throw new Error(`n8n server error: ${errorMessage}`);
      }

      throw new Error(`n8n error (${response.status}): ${errorMessage}`);
    }

    return responseData as T;
  } catch (error: any) {
    // Handle abort (timeout)
    if (error.name === 'AbortError') {
      throw new Error('n8n request timeout');
    }

    // Handle network errors
    if (error.message?.includes('fetch failed') || error.code === 'ECONNREFUSED') {
      throw new Error('n8n unreachable');
    }

    // Re-throw other errors
    throw error;
  } finally {
    // Always clear timeout
    clearTimeout(timeoutId);
  }
}
```

### Gotchas and Pitfalls

**1. JResult Envelope vs Raw Response**
- n8n workflows MUST return JResult format (with `code`, `data`, etc.)
- If n8n returns different structure, Backend must transform or error
- Don't assume n8n always returns expected format - validate!

**2. Error Status Codes**
- n8n might return HTTP 200 with `code: 400` in body (JResult error)
- Backend must check BOTH `response.ok` AND `responseData.code`
- Don't just check HTTP status - inspect JResult code too

**3. Timeout Configuration**
- JQEL queries can be slow (joins, aggregations)
- Default 10s timeout may be too short
- Consider 30s timeout for JQEL vs 10s for auth

**4. Schema Validation**
- Don't validate JQEL query structure in proxy service
- Service only forwards to n8n - validation happens there or in route
- Keep proxy "dumb" - just transport layer

**5. Sensitive Data**
- JQEL queries may contain sensitive WHERE conditions
- Don't log query `values` or `where` clauses
- Log query metadata only (schema, entity, action)

## Technical Specification

### Architecture

```
Frontend (JQEL Query)
    ↓
POST /api/jqel { schema: "platform", select: "portal", ... }
    ↓
Backend: jqel.routes.ts
    ↓ (if schema === "platform")
Backend: jqelRouter.service.ts
    ↓
Backend: n8nProxy.service.ts → queryJQEL(query)
    ↓ HTTP POST
n8n Backbone: /webhook/jqel
    ↓ (process query, access DB)
n8n Backbone: Return JResult { code: 200, data: [...] }
    ↓
Backend: n8nProxy.service.ts → return JResult
    ↓
Backend: jqel.routes.ts → res.json(JResult)
    ↓
Frontend: Receive JResult
```

### Data Flow

1. **Frontend** sends JQEL query via TanStack Query wrapper
2. **Backend** receives at `/api/jqel` endpoint
3. **Router** checks `schema` field and routes accordingly
4. **n8nProxyService.queryJQEL()** forwards to n8n with authentication
5. **n8n** processes query, accesses database, returns JResult
6. **Backend** validates JResult structure and returns to Frontend
7. **Frontend** unwraps JResult in TanStack Query hooks

### Modules and Responsibilities

**n8nProxy.service.ts**
- **Responsibility**: HTTP transport layer to n8n Backbone
- **Interface**:
  - `queryJQEL(query: JQELQuery): Promise<JResult>`

- **Does NOT**: Validate query structure, process queries locally, cache results

```typescript
// At top of file - ADD import
import type { JQELQuery, N8nJQELResponse } from '../types/jqel.types.js';

// In N8nProxyService class - ADD method after authorize()

/**
 * Call n8n JQEL processing workflow
 *
 * Forwards JQEL query to n8n Backbone for execution.
 * Used for queries with schema="platform".
 *
 * SPEC References:
 * - SPEC-A-D-007: Schema "platform" must be proxied to Backbone
 * - SPEC-CH-DA-005:008: Backend proxies queries to n8n
 * - SPEC-DA-W-005: Wrapper POSTs to n8n endpoint
 *
 * @param query - JQEL query object
 * @returns JResult with query results from n8n
 * @throws Error if n8n is unreachable, times out, or returns error
 */
async queryJQEL(query: JQELQuery): Promise<N8nJQELResponse> {
  // JQEL queries may be slower than auth (joins, aggregations)
  // Use 30s timeout instead of default 10s
  const response = await this.callWorkflow<N8nJQELResponse>(
    '/webhook/jqel',
    query,
    { timeout: 30000 } // 30 seconds
  );

  // Validate JResult structure
  // SPEC-JQEL-RES-003: code is REQUIRED
  if (typeof response.code !== 'number') {
    throw new Error('n8n returned invalid JResult: missing code field');
  }

  // Check if n8n returned error in JResult (HTTP 200 but code >= 400)
  // SPEC-JQEL-STA-004:012: Client errors 4xx
  // SPEC-JQEL-STA-011:012: Server errors 5xx
  if (response.code >= 400) {
    const errorMessage = response.message || 'Unknown JQEL error';
    throw new Error(`JQEL error (${response.code}): ${errorMessage}`);
  }

  return response;
}
```

### Error Handling Strategy

**Error Types:**

1. **Network Errors** (`n8n unreachable`)
   - Cause: n8n service down, wrong URL, network issue
   - Thrown by: `callWorkflow()` - existing
   - HTTP Response: 500
   - JResult: `{ code: 500, message: "Data service is unavailable" }`

2. **Timeout Errors** (`n8n request timeout`)
   - Cause: Query took >30s, n8n overloaded
   - Thrown by: `callWorkflow()` - existing
   - HTTP Response: 500
   - JResult: `{ code: 500, message: "Query timed out" }`

3. **JQEL Validation Errors** (n8n returns code 400)
   - Cause: Invalid query structure, missing fields
   - Thrown by: `queryJQEL()` after checking `response.code`
   - HTTP Response: 400
   - JResult: `{ code: 400, message: "Invalid JQEL query", field: "schema" }`

4. **Authorization Errors** (n8n returns code 401/403)
   - Cause: Invalid JWT, missing permissions
   - Thrown by: `queryJQEL()` after checking `response.code`
   - HTTP Response: 401 or 403
   - JResult: `{ code: 401, message: "Unauthorized" }`

5. **Not Found Errors** (n8n returns code 404)
   - Cause: Entity/schema doesn't exist
   - Thrown by: `queryJQEL()` after checking `response.code`
   - HTTP Response: 404
   - JResult: `{ code: 404, message: "Entity not found" }`

6. **Server Errors** (n8n returns code 500)
   - Cause: n8n internal error, database error
   - Thrown by: `queryJQEL()` after checking `response.code`
   - HTTP Response: 500
   - JResult: `{ code: 500, message: "Internal server error" }`

**Error Display Pattern:**
```typescript
// In future jqel.routes.ts (task 1.4.1)

try {
  const result = await n8nProxyService.queryJQEL(query);
  res.status(result.code).json(result);
} catch (error: any) {
  // Map service errors to HTTP responses
  if (error.message?.includes('n8n unreachable')) {
    res.status(500).json({
      code: 500,
      message: 'Data service is unavailable'
    });
    return;
  }

  if (error.message?.includes('timeout')) {
    res.status(500).json({
      code: 500,
      message: 'Query request timed out'
    });
    return;
  }

  if (error.message?.includes('JQEL error')) {
    // Extract code from error message
    const match = error.message.match(/JQEL error \((\d+)\)/);
    const code = match ? parseInt(match[1]) : 500;

    res.status(code).json({
      code,
      message: error.message
    });
    return;
  }

  // Generic error
  res.status(500).json({
    code: 500,
    message: 'An unexpected error occurred'
  });
}
```
