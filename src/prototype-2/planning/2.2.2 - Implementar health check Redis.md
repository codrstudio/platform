# Task Plan: 2.2.2 - Implementar health check Redis

## Context and Objective

Implement Redis health check functionality for the Setup Module. This monitors the connectivity and operational status of the Redis service, which is critical for platform operations (authentication token storage, session management, rate limiting, Pub/Sub events, event streaming).

**Business Value**: Provides administrators with real-time visibility into Redis service health, enabling proactive detection of cache/session issues that could impact all platform users.

**User Impact**: Administrators can quickly identify Redis connectivity problems before they affect users, and troubleshoot issues during platform configuration.

**Integration**: This health check will be displayed in the Platform Settings view of the Setup Module (SPEC-MS-PS-012, SPEC-MS-PS-014:016) alongside n8n and Backend health indicators.

```typescript
// This can be reused for health checks
async healthCheck(): Promise<HealthStatus> {
  try {
    await this.connect();
    const start = Date.now();
    await this.client!.ping();
    const latency = Date.now() - start;

    return {
      status: 'ok',
      latency,
      timestamp: new Date().toISOString()
    };
  } catch (error: any) {
    return {
      status: 'down',
      error: error.message,
      timestamp: new Date().toISOString()
    };
  }
}
```

### Gotchas and Pitfalls

- ⚠️ Redis `PING` is extremely fast (typically <1ms) - don't set timeout too high
- ⚠️ If Redis is down, the connection attempt may hang - use timeout (5 seconds max)
- ⚠️ Redis authentication failures will throw errors - handle gracefully
- ⚠️ Connection pool may mask temporary failures - force new ping each health check
- ⚠️ Don't expose Redis password in health check response
- ⚠️ Redis in subscriber mode cannot execute PING - ensure using regular client

### Error Handling Strategy

**Error Types:**
- **Connection refused**: Redis server not running → Display red indicator "Service unavailable"
- **Authentication failed**: Wrong password → Display red indicator "Authentication failed"
- **Timeout**: Redis not responding → Display red indicator "Service timeout"
- **Network errors**: Cannot reach Redis host → Display red indicator "Network error"

**Error Display Pattern:**
```typescript
// Same pattern as task 2.2.1 - HealthIndicator handles all error display
<HealthIndicator
  service="Redis"
  status={redisHealth.data?.status || 'loading'}
  error={redisHealth.error?.message}
  lastCheck={redisHealth.dataUpdatedAt}
/>
```

**Backend Error Handling:**
```typescript
// In redis.service.ts healthCheck()
try {
  await this.connect();
  const start = Date.now();
  await this.client!.ping();
  const latency = Date.now() - start;

  return {
    status: 'ok',
    latency,
    timestamp: new Date().toISOString()
  };
} catch (error: any) {
  // Classify error types
  let errorMessage = error.message;

  if (error.message.includes('ECONNREFUSED')) {
    errorMessage = 'Connection refused - Redis may not be running';
  } else if (error.message.includes('NOAUTH')) {
    errorMessage = 'Authentication required';
  } else if (error.message.includes('timeout')) {
    errorMessage = 'Connection timeout';
  }

  return {
    status: 'down',
    error: errorMessage,
    timestamp: new Date().toISOString()
  };
}
```
