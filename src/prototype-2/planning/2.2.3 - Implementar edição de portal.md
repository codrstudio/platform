# Task Plan: 2.2.3 - Implementar edição de portal

## Context and Objective

Implement the portal editing functionality within the Setup module, allowing administrators to modify existing portal configurations. This reuses the form component from Task 2.2.2 with pre-populated values and adds update-specific logic.

**Business Value:** Enables platform administrators to modify portal configurations without manual JSON editing, supporting iterative development and configuration refinement.

**User Impact:** Provides a safe, validated way to update portal settings with immediate feedback and error prevention.

**Integration:** Builds on portal creation (Task 2.2.2) by reusing the form component, integrates with portal listing (Task 2.2.1) for navigation, and uses JQEL mutation infrastructure with optimistic updates.

```typescript
// File: src/prototype-2/frontend/src/hooks/jqel/usePortalMutations.ts
// Update hook is already implemented with optimistic updates
export function useUpdatePortal() {
  return useOptimisticMutation<Portal, UpdatePortalVariables, Error, Portal[]>({
    mutationFn: updatePortal,
    optimistic: {
      queryKeys: [
        ['backend', 'portal'],
        ['backend', 'portal', { portalId: undefined }]
      ],
      updater: (portals: Portal[] | undefined, variables) => {
        if (!portals) return [] as Portal[];
        return updateItemInList(
          portals,
          variables.portalId,
          variables as Partial<Portal>,
          'portalId'
        );
      },
      invalidateOnSettled: true
    }
  });
}
```

```typescript
// File: src/prototype-2/frontend/src/hooks/jqel/usePortalQueries.ts
// Fetch single portal by ID
export function usePortal(portalId: string) {
  return useJQELQuery<Portal>(
    {
      schema: 'backend',
      select: 'portal',
      where: { portalId: { $eq: portalId } },
    },
    {
      queryKey: queryKeys.backend.portal(portalId),
      enabled: !!portalId,
    }
  );
}
```

### Gotchas and Pitfalls

- **Immutable fields:** `portalId` and `removable` CANNOT be changed after creation (SPEC-C-P-003, SPEC-MS-UI-014)
  - Display these fields as read-only in edit mode
  - Do not include in update mutation
- **Portal "main" special case:** Route MUST remain `/` and cannot be edited (SPEC-C-P-004)
  - Disable route field when editing "main" portal
- **Loading sequence:** Must fetch portal data before rendering form
  - Show loading state while fetching
  - Handle not found case (404)
- **Form reset:** React Hook Form needs initial values AFTER data loads
  - Use `reset()` function when data arrives
  - Or use `key={portalId}` to remount form
- **Optimistic updates:** Update hook already implements, UI updates immediately
