# Task Plan: 1.1.2 - Configurar TypeScript

## Context and Objective

Configure TypeScript for both frontend and backend projects in prototype-2. This task establishes the TypeScript compilation settings, path aliases, and type checking rules that will be used throughout the entire platform implementation.

**Business Value**: TypeScript provides static type checking, improved IDE support, and better code maintainability - critical for a modular platform with multiple portals and modules.

**Integration**: This configuration will enable:
- Type-safe development across frontend (React + Vite) and backend (Express + Node.js)
- Path aliases for cleaner imports and better code organization
- Strict type checking to catch errors early in development
- Support for modern ES features and JSX/TSX

### Conventions to Follow

**Compiler Options - Frontend:**
- `target: "ES2020"` - Modern JavaScript features
- `lib: ["ES2020", "DOM", "DOM.Iterable"]` - Browser environment
- `module: "ESNext"` - ES modules
- `moduleResolution: "bundler"` - Vite bundler mode
- `jsx: "react-jsx"` - New JSX transform (React 19)
- `noEmit: true` - Vite handles compilation

**Compiler Options - Backend:**
- `target: "ES2020"` - Modern Node.js features
- `module: "ESNext"` - ES modules
- `moduleResolution: "node"` - Node.js resolution
- `outDir: "./dist"` - Compiled output directory
- `rootDir: "./src"` - Source directory
- `declaration: true` - Generate .d.ts files
- `sourceMap: true` - Enable debugging

**Strict Type Checking (Both):**
- `strict: true` - Enable all strict checks
- `noUnusedLocals: true` - Catch unused variables
- `noUnusedParameters: true` - Catch unused parameters
- `noFallthroughCasesInSwitch: true` - Prevent switch fallthrough bugs

**Path Aliases Convention:**
- `@/*` maps to `./src/*` - Root source alias
- Specific aliases for major directories: `@/core/*`, `@/services/*`, `@/modules/*`, etc.
- Frontend aliases: components, hooks, types, utils, lib, providers
- Backend aliases: config, routes, services, middleware, types, utils

## Critical Context

### Documentation

- [TypeScript Handbook - tsconfig.json](https://www.typescriptlang.org/docs/handbook/tsconfig-json.html) - Official documentation on compiler options
- [Vite - TypeScript](https://vitejs.dev/guide/features.html#typescript) - Vite-specific TypeScript integration
- [TypeScript - Module Resolution](https://www.typescriptlogs.org/docs/handbook/module-resolution.html) - Understanding moduleResolution strategies

### Gotchas and Pitfalls

- **Vite and TypeScript**: Vite doesn't perform type checking during build by default - it only transpiles. Consider adding `tsc --noEmit` as a separate validation step.
- **Path Aliases**: Path aliases in tsconfig.json need corresponding configuration in Vite (via vite.config.ts) and bundler tools to work at runtime.
- **moduleResolution "bundler"**: This is a newer option (TS 5.0+) specifically for bundlers like Vite. It allows TypeScript to understand bundler-specific features.
- **React 19 JSX**: Use `"jsx": "react-jsx"` for the new JSX transform (not `"react"`) to avoid importing React in every file.
- **Backend Compilation**: Backend needs `outDir` and actual compilation since Node.js will run the compiled JavaScript.
- **skipLibCheck**: Set to `true` to speed up compilation by not checking types in node_modules - essential for large projects.

### Existing Patterns to Follow

- **Strict Mode Everywhere**: All prototype-1 configs use `strict: true` - follow this for type safety
- **Path Aliases**: Use `@/` prefix consistently for internal imports
- **Separate Configs**: Frontend and backend have completely independent TypeScript configurations
- **Vite Tooling Config**: Frontend has a separate `tsconfig.node.json` for Vite configuration files

### TypeScript Configuration Strategy

**Frontend Configuration Goals:**
1. Enable React JSX/TSX support with new JSX transform
2. Configure for Vite bundler mode (no emit, bundler resolution)
3. Enable strict type checking for quality
4. Set up path aliases for clean imports
5. Support modern ES2020+ features

**Backend Configuration Goals:**
1. Enable Node.js ES modules support
2. Configure compilation output (dist directory)
3. Enable strict type checking for quality
4. Set up path aliases for clean imports
5. Generate declaration files for potential sharing

**Shared Configuration Goals:**
1. Strict type checking enabled across all code
2. Consistent error reporting (unused locals, parameters)
3. JSON import support for configuration files
4. Skip library checks for faster compilation

### Compiler Options Breakdown

**Frontend-Specific Options:**
- `moduleResolution: "bundler"` - Vite bundler mode
- `allowImportingTsExtensions: true` - Allow .ts imports (Vite handles)
- `isolatedModules: true` - Each file can be transpiled independently
- `noEmit: true` - Vite handles output
- `jsx: "react-jsx"` - New JSX transform

**Backend-Specific Options:**
- `moduleResolution: "node"` - Node.js module resolution
- `outDir: "./dist"` - Compiled output location
- `rootDir: "./src"` - Source root
- `declaration: true` - Generate .d.ts type declaration files
- `declarationMap: true` - Generate .d.ts.map for debugging
- `sourceMap: true` - Generate .js.map for debugging
- `esModuleInterop: true` - Better CommonJS/ES module interop
- `noImplicitReturns: true` - Ensure all code paths return a value

## Implementation Blueprint

### Ordered Steps

#### Step 1: Create Frontend Main TypeScript Configuration

**File**: `src/prototype-2/frontend/tsconfig.json`

**Purpose**: Main TypeScript configuration for React application using Vite

**Configuration Details**:
```json
{
  "compilerOptions": {
    "target": "ES2020",
    "useDefineForClassFields": true,
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "skipLibCheck": true,

    /* Bundler mode */
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "jsx": "react-jsx",

    /* Linting */
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,

    /* Path aliases */
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@/core/*": ["./src/core/*"],
      "@/services/*": ["./src/services/*"],
      "@/modules/*": ["./src/modules/*"],
      "@/components/*": ["./src/components/*"],
      "@/hooks/*": ["./src/hooks/*"],
      "@/types/*": ["./src/types/*"],
      "@/utils/*": ["./src/utils/*"],
      "@/lib/*": ["./src/lib/*"],
      "@/providers/*": ["./src/providers/*"]
    }
  },
  "include": ["src"],
  "references": [{ "path": "./tsconfig.node.json" }]
}
```

**Key Points**:
- Uses React 19's new JSX transform (`react-jsx`)
- Bundler mode for Vite integration
- Strict type checking enabled
- Path aliases for clean imports
- References separate config for Vite tooling
