# Task Plan: 1.4.1 - Criar /api/jqel no backend

## Context and Objective

**What will be implemented:**
This task creates the `/api/jqel` HTTP endpoint in the Express backend to process JQEL (JSON Query Expression Language) queries. The endpoint will validate incoming JQEL queries, route them to the appropriate processor (backend or n8n), and return results in the JResult envelope format.

**Why it's needed:**
JQEL is the ONLY way the frontend accesses data in the platform. All data operations (SELECT, MUTATE) must go through this unified endpoint, which provides:
- Single point of validation and security
- Unified error handling
- Schema-based routing (backend/platform/system/application)
- Standardized response format (JResult)

**How it integrates:**
- **Frontend**: TanStack Query hooks (to be implemented in 1.4.3) will POST JQEL queries to this endpoint
- **Backend**: Routes queries based on `schema` field - processes "backend" schema locally, proxies others to n8n
- **n8n Backbone**: Processes queries for "platform" and application schemas, returns JResult responses

**Business value:**
- Database-agnostic data access layer
- Simplified frontend development (no direct database/API knowledge needed)
- Centralized access control and logging
- Consistent error handling across the entire platform

**User impact:**
Users will not interact with this endpoint directly, but it enables all data-driven features in the platform (dashboards, forms, lists, etc.) by providing a unified and reliable data access mechanism.

```typescript
export class N8nProxyService {
  private readonly baseUrl: string;
  private readonly platformKey: string;
  private readonly defaultTimeout: number = 10000;

  constructor() {
    this.baseUrl = config.n8nBaseUrl;
    this.platformKey = config.platformSharedSecret;
  }

  async login(credentials: LoginCredentials): Promise<N8nUserData> {
    const response = await this.callWorkflow<N8nLoginResponse>(
      '/webhook/auth/login',
      credentials
    );
    return response.data.user;
  }

  private async callWorkflow<T>(
    path: string,
    data: any,
    options?: { timeout?: number }
  ): Promise<T> {
    const timeout = options?.timeout || this.defaultTimeout;
    const url = `${this.baseUrl}${path}`;

    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), timeout);

    try {
      const response = await fetch(url, {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'X-Platform-Key': this.platformKey,
        },
        body: JSON.stringify(data),
        signal: controller.signal,
      });

      let responseData: any;
      try {
        responseData = await response.json();
      } catch (error) {
        throw new Error(`n8n returned invalid JSON: ${error}`);
      }

      if (!response.ok) {
        const errorMessage = responseData?.message || 'Unknown error';
        if (response.status === 401 || response.status === 403) {
          throw new Error(`Invalid credentials: ${errorMessage}`);
        }
        throw new Error(`n8n error (${response.status}): ${errorMessage}`);
      }

      return responseData as T;
    } catch (error: any) {
      if (error.name === 'AbortError') {
        throw new Error('n8n request timeout');
      }
      if (error.message?.includes('fetch failed')) {
        throw new Error('n8n unreachable');
      }
      throw error;
    } finally {
      clearTimeout(timeoutId);
    }
  }
}

export const n8nProxyService = new N8nProxyService();
```

### Gotchas and Pitfalls

**ES Modules Import Extensions**
- All imports MUST include `.js` extension
- TypeScript compiles `.ts` to `.js`, but imports must reference `.js`
- Example: `import { config } from './config/env.js';` (NOT `./config/env`)

**Express Error Handler Signature**
- Error handler MUST have 4 parameters: `(err, req, res, next)`
- Even if `next` is unused, it must be present for Express to recognize it
- Missing parameter will cause handler to not catch errors

**Async Route Handlers**
- MUST use try-catch blocks
- MUST call `next(error)` for unhandled errors
- MUST explicitly `return` after sending response (avoid double responses)

**JResult Response Format**
- `data` field is ALWAYS an array, even for single records
- `code` is HTTP status code (number), not string
- `message` is optional for success (200), required for errors
- Empty result is `{ code: 200, data: [] }` NOT `{ code: 404 }`

**Schema Routing**
- Schema "backend" MUST be processed locally (portal/module/instance config)
- Schema "platform" MUST be proxied to n8n
- Application schemas (e.g., "sac", "crm") MUST be proxied to n8n
- Schema "system" routing is configurable (default: backend)

**JWT Validation**
- Not all JQEL queries require authentication (depends on schema/entity)
- JWT validation should be middleware-based (optional per route)
- Extract userId from `payload.sub` for access control

#### Step 2: Create Validation Middleware
**File**: `backend/src/middleware/jqelValidation.middleware.ts`

**Details**: Validate JQEL query structure before processing. Check required fields, types, and mutually exclusive fields per SPEC-JQEL-VAL-001:019.

**Implementation**:
```typescript
import { Request, Response, NextFunction } from 'express';
import type { JQELQuery } from '../types/jqel.types.js';

/**
 * JQEL Query Validation Middleware
 *
 * Validates JQEL query structure before processing.
 *
 * SPEC References:
 * - SPEC-JQEL-VAL-001:019: Validation rules
 * - SPEC-JQEL-STR-003:006: Required fields
 */
export const jqelValidationMiddleware = (
  req: Request,
  res: Response,
  next: NextFunction
): void => {
  const query = req.body as Partial<JQELQuery>;

  // SPEC-JQEL-VAL-002: schema is required
  if (!query.schema || typeof query.schema !== 'string' || query.schema.trim() === '') {
    res.status(400).json({
      code: 400,
      message: "Field 'schema' is required and must be a non-empty string",
      field: 'schema',
    });
    return;
  }

  // SPEC-JQEL-VAL-003: select OR mutate is required
  if (!query.select && !query.mutate) {
    res.status(400).json({
      code: 400,
      message: "Query must have 'select' or 'mutate'",
    });
    return;
  }

  // SPEC-JQEL-VAL-004: select and mutate are mutually exclusive
  if (query.select && query.mutate) {
    res.status(400).json({
      code: 400,
      message: "Query cannot have both 'select' and 'mutate'",
    });
    return;
  }

  // SPEC-JQEL-VAL-005: If mutate, action is required
  if (query.mutate && !query.action) {
    res.status(400).json({
      code: 400,
      message: "Field 'action' is required when using 'mutate'",
      field: 'action',
    });
    return;
  }

  // SPEC-JQEL-VAL-007: select/mutate must be string
  if (query.select && typeof query.select !== 'string') {
    res.status(400).json({
      code: 400,
      message: "Field 'select' must be a string",
      field: 'select',
    });
    return;
  }

  if (query.mutate && typeof query.mutate !== 'string') {
    res.status(400).json({
      code: 400,
      message: "Field 'mutate' must be a string",
      field: 'mutate',
    });
    return;
  }

  // SPEC-JQEL-VAL-019: output and except cannot coexist
  if (query.output && query.except) {
    res.status(400).json({
      code: 400,
      message: "Do not use 'output' and 'except' together",
    });
    return;
  }

  // All validations passed
  next();
};
```

#### Step 4: Create JQEL Processor Service
**File**: `backend/src/services/jqelProcessor.service.ts`

**Details**: Route JQEL queries based on schema. Process "backend" schema locally, proxy others to n8n.

**Implementation**:
```typescript
import { n8nProxyService } from './n8nProxy.service.js';
import type { JQELQuery, JResult, RESERVED_SCHEMAS } from '../types/jqel.types.js';

/**
 * JQEL Processor Service
 *
 * Routes JQEL queries based on schema:
 * - "backend" schema → processed locally
 * - Other schemas → proxied to n8n Backbone
 *
 * SPEC References:
 * - SPEC-DA-SC-001:007: Schema routing
 * - SPEC-CH-DA-005:008: Backend routing responsibility
 */
export class JQELProcessor {
  /**
   * Process a JQEL query
   *
   * @param query - Validated JQEL query
   * @returns JResult response
   * @throws Error for processing failures
   */
  async process(query: JQELQuery): Promise<JResult> {
    // SPEC-CH-DA-019: Schema "backend" processed by Backend
    if (query.schema === 'backend') {
      return this.processLocal(query);
    }

    // SPEC-CH-DA-018: Schema "platform" and app schemas → n8n
    return this.processRemote(query);
  }

  /**
   * Process query locally (backend schema)
   *
   * Handles portal, module, and instance configuration queries.
   *
   * TODO (Task 1.4.2): Implement local processing for backend schema
   * For now, return "not implemented" response
   */
  private async processLocal(query: JQELQuery): Promise<JResult> {
    // Placeholder implementation
    // Will be implemented in Task 1.4.2 (schema routing)
    return {
      code: 501,
      message: 'Local processing for "backend" schema not yet implemented',
      data: [],
    };
  }

  /**
   * Process query remotely via n8n
   *
   * Proxies query to n8n Backbone for processing.
   *
   * SPEC-CH-DA-006: Backend proxies to Backbone
   */
  private async processRemote(query: JQELQuery): Promise<JResult> {
    try {
      const result = await n8nProxyService.jqel(query);
      return result;
    } catch (error: any) {
      // Map n8n errors to JResult format
      if (error.message?.includes('n8n unreachable')) {
        return {
          code: 503,
          message: 'Data service is unavailable',
        };
      }

      if (error.message?.includes('timeout')) {
        return {
          code: 504,
          message: 'Data service request timed out',
        };
      }

      // Re-throw unexpected errors (will be caught by route handler)
      throw error;
    }
  }
}

// Export singleton instance
export const jqelProcessor = new JQELProcessor();
```

#### Step 5: Create JQEL Route Handler

**Implementation**:
```typescript
import { Router, Request, Response, NextFunction } from 'express';
import { jqelValidationMiddleware } from '../middleware/jqelValidation.middleware.js';
import { jqelProcessor } from '../services/jqelProcessor.service.js';
import type { JQELQuery, JResult } from '../types/jqel.types.js';

const router = Router();

/**
 * POST /api/jqel
 *
 * Process JQEL queries (SELECT and MUTATE operations).
 *
 * SPEC References:
 * - SPEC-DA-EP-001:009: JQEL endpoint requirements
 * - SPEC-CH-DA-001:004: Data channel definition
 *
 * Flow:
 * 1. Validation middleware checks query structure
 * 2. Route handler extracts query from body
 * 3. Processor routes based on schema
 * 4. Result returned as JResult JSON
 *
 * Authentication:
 * - Optional (depends on schema/entity/operation)
 * - TODO (Task 1.4.2): Add JWT validation middleware conditionally
 */
router.post(
  '/',
  jqelValidationMiddleware,
  async (req: Request, res: Response, next: NextFunction): Promise<void> => {
    try {
      // Extract validated query from body
      const query = req.body as JQELQuery;

      // Log query for debugging (development only)
      if (process.env.NODE_ENV === 'development') {
        console.log('📊 JQEL Query:', {
          schema: query.schema,
          operation: query.select ? `SELECT ${query.select}` : `MUTATE ${query.mutate}`,
          action: query.action,
        });
      }

      // Process query via processor service
      const result: JResult = await jqelProcessor.process(query);

      // Return result with appropriate HTTP status
      // SPEC-JQEL-RES-003:005: Use code field as HTTP status
      res.status(result.code).json(result);

    } catch (error: any) {
      // Log unexpected errors
      console.error('❌ Error in /api/jqel:', {
        timestamp: new Date().toISOString(),
        error: error.message,
        query: req.body?.schema,
        stack: error.stack,
      });

      // Pass to centralized error handler
      next(error);
    }
  }
);

export default router;
```

### Error Handling Strategy

**Error Types:**

**1. Validation Errors (400 Bad Request)**
- Missing required fields (`schema`, `select`/`mutate`)
- Invalid field types (schema not string, etc.)
- Mutually exclusive fields used together
- **Handling**: Caught by validation middleware, returned immediately
- **Response**:
  ```json
  {
    "code": 400,
    "message": "Field 'schema' is required",
    "field": "schema"
  }
  ```

**2. Network Errors (503 Service Unavailable)**
- n8n unreachable
- Connection refused
- DNS resolution failure
- **Handling**: Caught in `processRemote()`, mapped to JResult
- **Response**:
  ```json
  {
    "code": 503,
    "message": "Data service is unavailable"
  }
  ```

**3. Timeout Errors (504 Gateway Timeout)**
- n8n request exceeds timeout (10s default)
- AbortController triggers
- **Handling**: Caught in n8nProxy service, mapped to JResult
- **Response**:
  ```json
  {
    "code": 504,
    "message": "Data service request timed out"
  }
  ```

**4. Authorization Errors (401/403)**
- JWT missing or invalid (401)
- User lacks permission for operation (403)
- **Handling**: Returned by n8n, passed through as JResult
- **Note**: JWT validation added in Task 1.4.2

**5. Business Logic Errors (422 Unprocessable Entity)**
- Query semantically invalid (e.g., WHERE clause malformed)
- Entity not found in schema
- Constraint violation
- **Handling**: Returned by n8n as JResult, passed through

**6. Unexpected Errors (500 Internal Server Error)**
- Unhandled exceptions
- Programming errors
- **Handling**: Caught by route handler try-catch, passed to `next(error)`
- Centralized error handler formats response

**Error Display Pattern:**
```typescript
// File: backend/src/routes/jqel.routes.ts
try {
  const result = await jqelProcessor.process(query);
  res.status(result.code).json(result);
} catch (error: any) {
  console.error('❌ Error in /api/jqel:', {
    timestamp: new Date().toISOString(),
    error: error.message,
    query: req.body?.schema,
  });
  next(error); // Centralized handler formats response
}
```
