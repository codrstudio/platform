# Task Plan: 1.2.8 - Implementar validação de autenticação

## Context and Objective

This task implements the authentication validation layer for protected routes in the platform. The validation ensures that:

- Users attempting to access protected routes have valid authentication (JWT tokens)
- Invalid or expired tokens trigger automatic token refresh attempts
- Failed authentication redirects users to the login page
- Valid authentication allows seamless access to protected content
- The authentication state is properly integrated with the routing system

This is a critical security component that protects sensitive routes and ensures only authenticated users can access restricted areas of the application. The implementation bridges the authentication system (implemented in System 1.3) with the routing system (System 1.2), providing seamless integration through React components and hooks.

**Business Value:** Ensures application security by preventing unauthorized access while providing a smooth user experience through automatic token refresh and graceful degradation.

**User Impact:** Users remain authenticated across page refreshes, experience seamless navigation without repeated logins, and are only prompted to log in when their session truly expires.

### Gotchas and Pitfalls

**JWT Client-Side Validation:**
- Client-side validation is for UX only, NOT security
- Never trust client-side token validation for authorization
- Always validate tokens server-side before granting access
- Client can only check expiration time, not signature validity
- Use client validation to avoid unnecessary API calls

**Token Expiration Timing:**
- Access tokens expire quickly (15 minutes per SPEC-AU-JWT-014)
- Refresh tokens expire slowly (7 days per SPEC-AU-JWT-015)
- Pre-emptive refresh (5 min before expiry) prevents interruptions
- Race condition: user might make request while refresh is pending
- Solution: Queue requests during refresh, resume after

**Redirect Loop Prevention:**
- Protected route redirects to login → login redirects to protected route → loop
- Always check current location before redirecting
- Store intended destination in state: `<Navigate to="/login" state={{ from: location }} />`
- After login, redirect back to intended destination

**React Router v7 Navigate Behavior:**
- `<Navigate>` component triggers navigation during render
- Use `replace` prop to replace history entry (avoid back button issues)
- For programmatic navigation, use `useNavigate()` hook in effects/callbacks
- Don't call `navigate()` during render (causes warnings)

**Async Validation in React:**
- Token refresh is async, but React render is sync
- Show loading state while validating/refreshing
- Use Suspense boundaries for better UX (future enhancement)
- Don't block render indefinitely (timeout after 10s)

**Multiple Protected Routes:**
- Each `<ProtectedRoute>` might validate independently
- Solution: Centralize validation in AuthContext
- Cache validation result for current render cycle
- Only re-validate on token change or explicit trigger

#### Step 1: Create Token Validation Utilities
- Create: `frontend/src/services/auth/tokenValidator.ts`

```typescript
/**
 * Token validation utilities - client-side only
 * Security note: These checks are for UX, not security.
 * Always validate tokens server-side.
 */

export interface TokenValidationResult {
  isValid: boolean;
  isExpired: boolean;
  expiresIn: number; // seconds until expiration
  shouldRefresh: boolean; // true if expiration < 5 minutes
}

export function validateToken(token: string | null): TokenValidationResult {
  if (!token) {
    return {
      isValid: false,
      isExpired: true,
      expiresIn: 0,
      shouldRefresh: false
    };
  }

  try {
    const payload = decodeTokenPayload(token);
    const now = Math.floor(Date.now() / 1000);
    const expiresIn = payload.exp - now;

    return {
      isValid: expiresIn > 0,
      isExpired: expiresIn <= 0,
      expiresIn: Math.max(0, expiresIn),
      shouldRefresh: expiresIn < 300 && expiresIn > 0 // 5 minutes
    };
  } catch (error) {
    console.error('Token validation error:', error);
    return {
      isValid: false,
      isExpired: true,
      expiresIn: 0,
      shouldRefresh: false
    };
  }
}

function decodeTokenPayload(token: string): { exp: number; sub: string } {
  // Simple JWT decode without verification
  // Split JWT: header.payload.signature
  const parts = token.split('.');
  if (parts.length !== 3) {
    throw new Error('Invalid token format');
  }

  // Decode base64url payload
  const payload = parts[1];
  const decoded = atob(payload.replace(/-/g, '+').replace(/_/g, '/'));
  return JSON.parse(decoded);
}

export function isTokenExpired(token: string | null): boolean {
  const result = validateToken(token);
  return result.isExpired;
}

export function shouldRefreshToken(token: string | null): boolean {
  const result = validateToken(token);
  return result.shouldRefresh;
}
```

#### Step 2: Create Authentication Validation Hook
- Create: `frontend/src/hooks/useAuthValidation.ts`
- Integrate with AuthContext
- Handle token refresh logic
- Pattern: Custom React hook with auth integration

```typescript
import { useEffect, useState } from 'react';
import { useAuth } from '../providers/AuthProvider';
import { validateToken, shouldRefreshToken } from '../services/auth/tokenValidator';

export interface AuthValidationState {
  isValidating: boolean;
  isAuthenticated: boolean;
  shouldRedirect: boolean;
  redirectTo: string | null;
  error: Error | null;
}

export function useAuthValidation() {
  const auth = useAuth();
  const [validationState, setValidationState] = useState<AuthValidationState>({
    isValidating: true,
    isAuthenticated: false,
    shouldRedirect: false,
    redirectTo: null,
    error: null
  });

  useEffect(() => {
    validateAuth();
  }, [auth.accessToken]);

  async function validateAuth() {
    setValidationState(prev => ({ ...prev, isValidating: true }));

    try {
      // No token = not authenticated
      if (!auth.accessToken) {
        setValidationState({
          isValidating: false,
          isAuthenticated: false,
          shouldRedirect: true,
          redirectTo: '/login',
          error: null
        });
        return;
      }

      // Validate token expiration
      const validation = validateToken(auth.accessToken);

      // Token expired = redirect to login
      if (validation.isExpired) {
        setValidationState({
          isValidating: false,
          isAuthenticated: false,
          shouldRedirect: true,
          redirectTo: '/login',
          error: null
        });
        return;
      }

      // Token expiring soon = attempt refresh
      if (validation.shouldRefresh) {
        try {
          await auth.refreshToken();
          // Refresh successful, re-validate
          const newValidation = validateToken(auth.accessToken);
          setValidationState({
            isValidating: false,
            isAuthenticated: newValidation.isValid,
            shouldRedirect: !newValidation.isValid,
            redirectTo: newValidation.isValid ? null : '/login',
            error: null
          });
        } catch (refreshError) {
          // Refresh failed = redirect to login
          setValidationState({
            isValidating: false,
            isAuthenticated: false,
            shouldRedirect: true,
            redirectTo: '/login',
            error: refreshError as Error
          });
        }
        return;
      }

      // Token valid = authenticated
      setValidationState({
        isValidating: false,
        isAuthenticated: true,
        shouldRedirect: false,
        redirectTo: null,
        error: null
      });

    } catch (error) {
      setValidationState({
        isValidating: false,
        isAuthenticated: false,
        shouldRedirect: true,
        redirectTo: '/login',
        error: error as Error
      });
    }
  }

  return validationState;
}
```

```typescript
import { Navigate, useLocation } from 'react-router-dom';
import { useAuthValidation } from '../hooks/useAuthValidation';

interface ProtectedRouteProps {
  children: React.ReactNode;
  requiresAuth?: boolean;
  fallback?: React.ReactNode;
}

export default function ProtectedRoute({
  children,
  requiresAuth = true,
  fallback = <div>Loading...</div>
}: ProtectedRouteProps) {
  const location = useLocation();
  const validation = useAuthValidation();

  // Skip validation if route doesn't require auth
  if (!requiresAuth) {
    return <>{children}</>;
  }

  // Show loading state during validation
  if (validation.isValidating) {
    return <>{fallback}</>;
  }

  // Redirect to login if not authenticated
  if (validation.shouldRedirect && validation.redirectTo) {
    return (
      <Navigate
        to={validation.redirectTo}
        state={{ from: location.pathname }}
        replace
      />
    );
  }

  // Authenticated - render protected content
  if (validation.isAuthenticated) {
    return <>{children}</>;
  }

  // Fallback (should not reach here)
  return <>{fallback}</>;
}
```

### Error Handling Strategy

**Error Types:**

1. **Token Expired:**
   - Symptom: Token expiration time has passed
   - Handling: Attempt automatic refresh, redirect to login on failure
   - User feedback: Silent (no error shown if refresh succeeds)

2. **Token Invalid:**
   - Symptom: Token format is malformed or signature invalid
   - Handling: Clear auth state, redirect to login
   - User feedback: "Your session is invalid. Please log in again."

3. **Refresh Failed:**
   - Symptom: Refresh token is expired or revoked
   - Handling: Clear all auth state, redirect to login
   - User feedback: "Your session has expired. Please log in again."

4. **Network Error During Refresh:**
   - Symptom: Cannot reach auth server
   - Handling: Retry once, then fail
   - User feedback: "Connection error. Please check your internet and try again."

**Error Display Pattern:**

```typescript

  showToast('Session expired. Please log in again.');
```
