# Task Plan: 1.2.5 - Implementar prefixação automática por portal

## Context and Objective

This task implements automatic route prefixing for modules based on the portal they are activated in. Modules define routes relative to their scope (e.g., `/chat/:id`), and the platform must automatically inject the portal prefix to generate the final route.

**Why it's needed:**
- Ensures route isolation between portals
- Allows modules to be reusable across different portals without code changes
- Maintains the declarative nature of module route definitions

**How it integrates:**
- Builds on task 1.2.4 (route registration function)
- Enables proper module loading in future tasks
- Critical for portal isolation (SPEC-C-P-009 to 013)

**Business value:**
- Same module can be activated in multiple portals with different routes
- Module developers don't need to know about portal structure
- Simplifies module development and configuration

**User impact:**
- Portal "main" routes: `/chat/:id`
- Portal "sac" routes: `/sac/chat/:id`
- Portal "setup" routes: `/setup`

### Gotchas and Pitfalls

- Portal "main" must use `/` NOT `/main` as prefix (SPEC-R-PM-002)
- Empty prefix for main portal requires special handling in string concatenation
- Routes already starting with `/` must not get double slashes
- React Router path joining must preserve parameter syntax (`:id`, `*`, etc.)
- Route conflicts are NOT validated by platform (SPEC-R-PR-006)

### Existing Patterns to Follow

**Portal Identification:**
- Check if `portalId === 'main'` for special handling
- Use empty string as prefix for main portal
- Use `/${portalId}` for all other portals

**Route Joining:**
```typescript
// CORRECT approach
const prefix = portalId === 'main' ? '' : `/${portalId}`;
const finalPath = `${prefix}${route.path}`;

// WRONG approach (double slash for main)
const finalPath = `/${portalId}${route.path}`;
```

## Implementation Blueprint

### Ordered Steps

#### 1. Create routing utility functions

**File:** `src/prototype-2/frontend/src/core/routing/utils.ts`

**Details:** Create utility function to handle route prefixing logic

```typescript
/**
 * Prefixes a module route with the portal's base path
 *
 * @param route - Relative route from module (e.g., '/chat/:id')
 * @param portalId - Portal identifier (e.g., 'main', 'sac', 'setup')
 * @returns Prefixed route (e.g., '/sac/chat/:id' for portal 'sac')
 *
 * @example
 * prefixRoute('/chat/:id', 'main')  // Returns: '/chat/:id'
 * prefixRoute('/chat/:id', 'sac')   // Returns: '/sac/chat/:id'
 * prefixRoute('/setup', 'setup')    // Returns: '/setup'
 */
export function prefixRoute(route: string, portalId: string): string {
  // SPEC-R-PM-001, SPEC-R-PM-002: Portal "main" uses root, no prefix
  if (portalId === 'main') {
    return route;
  }

  // SPEC-R-PO-001, SPEC-R-PO-003: Other portals use /:portalId prefix
  // Remove leading slash from route if present to avoid double slash
  const cleanRoute = route.startsWith('/') ? route.slice(1) : route;
  return `/${portalId}/${cleanRoute}`;
}

/**
 * Prefixes an array of route definitions with portal base path
 *
 * @param routes - Array of route definitions from module
 * @param portalId - Portal identifier
 * @returns New array with prefixed routes
 */
export function prefixRoutes<T extends { path: string }>(
  routes: T[],
  portalId: string
): T[] {
  return routes.map(route => ({
    ...route,
    path: prefixRoute(route.path, portalId)
  }));
}
```

**Pattern Reference:** Pure utility functions, similar to lodash/ramda style

#### 4. Update PortalRouter to use prefixed routes

**File:** `src/prototype-2/frontend/src/core/routing/PortalRouter.tsx`

**Details:** Ensure PortalRouter receives and uses prefixed routes correctly

```typescript
import { Routes, Route } from 'react-router-dom';
import { registerRoutes } from './registerRoutes';
import type { RouteDefinition } from '../../types/routing';

interface PortalRouterProps {
  portalId: string;
  moduleRoutes: RouteDefinition[];
}

/**
 * Router component for a specific portal
 * Handles route registration with automatic prefixing
 *
 * SPEC-R-CA-007, SPEC-R-CA-008: Manages routes for single portal
 */
export default function PortalRouter({ portalId, moduleRoutes }: PortalRouterProps) {
  // Get prefixed routes for this portal
  const routes = registerRoutes(portalId, moduleRoutes);

  return (
    <Routes>
      {routes.map((route) => (
        <Route
          key={route.path}
          path={route.path}
          element={<route.component />}
        />
      ))}
    </Routes>
  );
}
```

**Pattern Reference:** Standard React Router pattern with dynamic route mapping

#### 5. Write unit tests for prefixing logic

**File:** `src/prototype-2/frontend/src/core/routing/__tests__/utils.test.ts`

**Details:** Ensure prefixing works correctly for all portal types

```typescript
import { describe, it, expect } from 'vitest';
import { prefixRoute, prefixRoutes } from '../utils';

describe('prefixRoute', () => {
  it('should not prefix routes for "main" portal', () => {
    expect(prefixRoute('/chat/:id', 'main')).toBe('/chat/:id');
    expect(prefixRoute('/dashboard', 'main')).toBe('/dashboard');
  });

  it('should prefix routes for non-main portals', () => {
    expect(prefixRoute('/chat/:id', 'sac')).toBe('/sac/chat/:id');
    expect(prefixRoute('/dashboard', 'app')).toBe('/app/dashboard');
  });

  it('should handle routes without leading slash', () => {
    expect(prefixRoute('chat/:id', 'sac')).toBe('/sac/chat/:id');
  });

  it('should preserve route parameters', () => {
    expect(prefixRoute('/users/:userId/posts/:postId', 'admin'))
      .toBe('/admin/users/:userId/posts/:postId');
  });

  it('should handle wildcard routes', () => {
    expect(prefixRoute('/docs/*', 'help')).toBe('/help/docs/*');
  });
});

describe('prefixRoutes', () => {
  it('should prefix all routes in array', () => {
    const routes = [
      { path: '/chat/:id', component: () => null },
      { path: '/settings', component: () => null }
    ];

    const prefixed = prefixRoutes(routes, 'sac');

    expect(prefixed[0].path).toBe('/sac/chat/:id');
    expect(prefixed[1].path).toBe('/sac/settings');
  });

  it('should preserve route metadata', () => {
    const routes = [
      {
        path: '/admin',
        component: () => null,
        requiresAuth: true,
        permissions: ['admin']
      }
    ];

    const prefixed = prefixRoutes(routes, 'portal');

    expect(prefixed[0].requiresAuth).toBe(true);
    expect(prefixed[0].permissions).toEqual(['admin']);
  });
});
```

### Error Handling Strategy

**Error Types and Handling:**

1. **Invalid portal ID:**
   - Validation: Not enforced at prefixing level
   - Responsibility: Portal loader validates portal ID
   - Prefixing assumes valid input

2. **Empty route path:**
   - Current approach: Allow empty paths (React Router handles)
   - Alternative: Add validation if needed in future

3. **Malformed routes:**
   - React Router will throw error during rendering
   - Error boundaries (task 1.8) will catch
   - No specific handling in prefixing logic

**Error Display Pattern:**
- Errors during route registration surface in development via console
- Production errors caught by Error Boundaries (implemented in task 1.8)
- No user-facing errors expected from prefixing logic itself
