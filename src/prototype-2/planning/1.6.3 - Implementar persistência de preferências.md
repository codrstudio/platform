# Task Plan: 1.6.3 - Implementar persistência de preferências

## Context and Objective

This task implements persistence for theme preferences using localStorage, ensuring that user theme choices (mode and brand color) survive page reloads and browser sessions. It also implements cross-tab synchronization using the storage event, so theme changes in one tab are reflected in all other tabs of the same portal.

**Business Value:** Users expect their theme preferences to be remembered across sessions. This provides a seamless experience where the application maintains the user's visual preferences without requiring re-configuration on every visit. Cross-tab sync ensures consistency when users have multiple tabs open.

**Integration Point:** This functionality is integrated into the ThemeProvider created in Task 1.6.1 and enhanced in Task 1.6.2. The persistence layer uses the `themeStorage` service to save/load preferences and listens to the `storage` event for cross-tab synchronization.

  - Example: `default:theme`, `default:brand-color`
  - Pattern from themeStorage service

- **Error Handling:** Wrap ALL localStorage operations in try-catch

- **Cross-Tab Sync:** Use `storage` event to sync between tabs
  - Only fires in OTHER tabs (not the tab that made the change)
  - Check the `key` to determine which preference changed

### Gotchas and Pitfalls

- **Storage Event Behavior:** The `storage` event ONLY fires in OTHER tabs, not the tab that made the change. This is by design. The tab making the change already has updated state, so it doesn't need the event.

- **Event Filtering:** The storage event fires for ALL localStorage changes. You MUST filter by key to only respond to theme-related changes. Check `event.key` matches your theme keys.

- **Storage Event Data:** The event provides:
  - `event.key` - The key that changed
  - `event.newValue` - New value (string or null)
  - `event.oldValue` - Previous value
  - `event.storageArea` - Reference to localStorage

- **Null Values:** If a key is removed, `event.newValue` will be `null`. Handle this gracefully by reverting to defaults.

- **Settings Key Scope:** Different portals with different `settings-key` values have separate localStorage keys. A change to `default:theme` should not affect `sac:theme`.

- **Initial Load vs Sync:** Two different use cases:
  1. **Initial load** (mount) - Read from localStorage ONCE to restore preferences
  2. **Cross-tab sync** (runtime) - Listen for changes and update state

- **Infinite Loop Prevention:** Don't save to localStorage inside the storage event handler. The event handler should ONLY update React state. The state update will trigger the existing save logic elsewhere.

- **Effect Cleanup:** Remember to remove the storage event listener in the cleanup function to prevent memory leaks.

       // Only respond to localStorage changes
       if (event.storageArea !== localStorage) return;

       const themeKey = `${settingsKey}:theme`;
       const colorKey = `${settingsKey}:brand-color`;

       // Handle theme change from another tab
       if (event.key === themeKey) {
         const newTheme = event.newValue as ThemeMode | null;
         if (newTheme && (newTheme === 'light' || newTheme === 'dark' || newTheme === 'system')) {
           console.log(`[Cross-tab] Theme changed to: ${newTheme}`);
           setRawTheme(newTheme); // Update state (don't save again!)
         }
       }

       // Handle brand color change from another tab
       if (event.key === colorKey) {
         const newColor = event.newValue;
         console.log(`[Cross-tab] Brand color changed to: ${newColor}`);
         setBrandColorState(newColor); // Update state (don't save again!)
       }
     };

     // Add listener
     window.addEventListener('storage', handleStorageChange);

     console.log(`[Theme] Cross-tab sync enabled for key: ${settingsKey}`);

     // Cleanup listener
     return () => {
       window.removeEventListener('storage', handleStorageChange);
       console.log(`[Theme] Cross-tab sync disabled for key: ${settingsKey}`);

### Error Handling Strategy

**localStorage Errors:**
- All save/load operations wrapped in try-catch (already in themeStorage service)
- Log errors to console
- Fail silently - use default values if load fails
- Don't crash if save fails

**Invalid Stored Values:**
- Validate theme mode is one of: "light", "dark", "system"
- If invalid, ignore and use default "system"
- Log warning about invalid value

**Storage Event Errors:**
- Check `event.storageArea === localStorage` to filter out sessionStorage events
- Validate `event.newValue` before using
- Handle `null` values (key was removed)

**Cross-Tab Race Conditions:**
- Not a concern - localStorage is synchronous within a tab
- Storage event ensures all tabs eventually have same state
