# Task Plan: 2.2.2 - Implementar criação de portal

## Context and Objective

Implement the portal creation functionality within the Setup module, allowing administrators to create new portal configurations. This includes a form interface with validation, JQEL mutation integration with optimistic updates, and proper error handling.

**Business Value:** Enables platform administrators to expand the platform by creating new isolated sub-applications (portals) without manual JSON file editing.

**User Impact:** Provides a user-friendly interface to create portals with immediate validation feedback, preventing configuration errors and improving productivity.

**Integration:** Integrates with the existing portal listing (Task 2.2.1), uses JQEL mutations for persistence, and follows the form validation patterns established in the codebase.

```typescript
// This hook is already implemented with optimistic updates
export function useCreatePortal() {
  return useOptimisticMutation<Portal, CreatePortalVariables, Error, Portal[]>({
    mutationFn: createPortal,
    optimistic: {
      queryKeys: ['backend', 'portal'],
      updater: (portals: Portal[] | undefined, variables) => {
        const tempPortal: Portal = {
          portalId: variables.portalId,
          name: variables.name,
          description: variables.description || '',
          path: variables.path,
          activeModules: variables.activeModules || [],
          settings: variables.settings || {},
          removable: variables.removable ?? true
        };
        return addItemToList(portals, tempPortal, 'end');
      },
      invalidateOnSettled: true
    }
  });
}
```

- **Settings Key:** Default to "default" if not provided (SPEC-C-P-016)

```
    ↓

    ↓

    ↓

    ↓

Optimistic update (UI shows new portal immediately)
    ↓
JQEL mutation sent to backend
{schema: 'backend', mutate: 'portal', action: 'insert', values: {...}}
    ↓
Backend writes to config/portals.json
    ↓
Success response received
    ↓
TanStack Query invalidates cache
    ↓
Navigate to portal list
    ↓
Toast notification shown
```

### Error Handling Strategy

**Error Types:**

**Validation Errors (Client-side):**
```typescript
// Handled by React Hook Form + Zod
const portalSchema = z.object({
  portalId: z.string()
    .min(1, 'Portal ID is required')
    .regex(/^[a-z0-9-]+$/, 'Only lowercase letters, numbers, and hyphens')
    .refine(async (id) => {
      // Check uniqueness (optional async validation)
      const existing = await checkPortalExists(id);
      return !existing;
    }, 'Portal ID already exists'),
  path: z.string()
    .min(1, 'Path is required')
    .startsWith('/', 'Path must start with /')
    .refine((path) => {
      const reserved = ['/health', '/api', '/assets'];
      return !reserved.some(r => path.startsWith(r));
    }, 'Path conflicts with reserved routes'),
});
```
