# Task Plan: 1.2.6 - Implementar lazy loading de rotas

## Context and Objective

This task implements lazy loading for module routes, ensuring that route components are loaded on-demand rather than in the initial bundle. This is critical for performance, as it allows the platform to split code into smaller chunks that are downloaded only when needed.

### What Will Be Implemented

A comprehensive lazy loading system that:
- Wraps route components with React.lazy() for automatic code splitting
- Provides Suspense boundaries with meaningful loading states
- Ensures module chunks are separate from the main bundle
- Implements loading indicators for better user experience
- Handles loading errors gracefully with retry capability
- Optimizes bundle sizes according to performance targets

### Why It's Needed

**Performance Requirements (SPEC-A-LL-006:010):**
- Landing page must load < 1s on 3G connections
- Initial bundle must be < 200KB gzipped
- Module chunks must be < 500KB gzipped each
- Only active modules should be downloaded

**User Experience:**
- Faster initial page load (smaller main bundle)
- Progressive enhancement (modules load as needed)
- Better perceived performance with loading states
- Responsive navigation even on slow networks

**Architecture Benefits:**
- Clear separation of concerns (module boundaries)
- Scalability (add modules without bloating main bundle)
- Maintainability (modules are independently deployable)

### How It Integrates

- Built on top of registerRoutes() function (Task 1.2.4)
- Used by PortalRouter (Task 1.2.1) when rendering routes
- Works with React Router's route system
- Integrates with Vite's code splitting configuration (Task 1.1.7)
- Foundation for PWA caching strategies (System 1.1)

### Business Value

**Performance Impact:**
- 70-80% reduction in initial bundle size
- Faster time-to-interactive for users
- Better SEO scores (Lighthouse performance)
- Reduced bandwidth costs for users

**Developer Experience:**
- Automatic code splitting (no manual configuration per module)

### Gotchas and Pitfalls

**⚠️ React.lazy() Must Wrap Default Exports:**
```typescript
// WRONG - lazy wraps named export
const Component = React.lazy(() => import('./Component').then(m => m.NamedExport));

// RIGHT - lazy expects default export
const Component = React.lazy(() => import('./Component'));
```

**⚠️ Suspense Boundary Placement:**
- Suspense should wrap route elements, not individual components
- Multiple routes can share one Suspense boundary
- Portal-level Suspense is preferred over route-level for this platform
- Suspense fallback must be synchronous (no lazy components in fallback)

**⚠️ Dynamic Import Path Structure:**
```typescript
// WRONG - Vite cannot analyze completely dynamic path
const module = await import(dynamicPath);

// WRONG - Too dynamic for Vite
const module = await import(`${basePath}/${moduleId}/index.ts`);

// RIGHT - Static base path, dynamic filename
const module = await import(`../../modules/${moduleId}/index.ts`);
```

**⚠️ Loading State Flash:**
- Very fast networks can cause loading state to flash briefly
- Use `startTransition` or minimum display time for better UX
- Or set a threshold (only show loader after 200ms)

**⚠️ Error Recovery:**
- Failed lazy loads should be retryable
- Cache busting needed if module fails to load
- Network errors vs. parse errors need different handling

**⚠️ Bundle Size Calculation:**
- Gzipped size is different from raw size
- Use `npm run build` to see actual gzipped sizes
- Shared dependencies (React, Router) should NOT be in module chunks

### Data Flow

**Lazy Route Loading Flow:**

```
User navigates to route (e.g., /setup/portals)
       ↓
React Router matches route
       ↓
Route element is lazy component (React.lazy)
       ↓
React.Suspense catches loading state
       ↓
Show loading fallback (RouteLoading component)
       ↓
Dynamic import starts downloading module chunk
       ↓
Vite serves module chunk from /assets/modules-setup-[hash].js
       ↓
Module chunk downloads and parses
       ↓
Component code executes
       ↓
Suspense boundary resolves
       ↓
Component renders
```

**Error Handling Flow:**

```
Dynamic import fails (network error, parse error, etc.)
       ↓
Error Boundary catches error (future task)
       ↓
Show error UI with retry button
       ↓
User clicks retry
       ↓
Clear error state
       ↓
Trigger new import with cache busting
       ↓
Retry loading flow
```

**Code Splitting at Build:**

```
Vite Build Process
       ↓
Analyze import() statements
       ↓
Create separate chunks for each dynamic import
       ↓
Extract shared dependencies to vendor chunks
       ↓
Generate chunk files:
  - main-[hash].js (< 200KB gzipped)
  - react-vendor-[hash].js
  - modules-setup-[hash].js
  - modules-chat-[hash].js
  - etc.
       ↓
Service Worker caches chunks (PWA)
```

```typescript
import React from 'react';

/**
 * Wraps a component with React.lazy for code splitting
 *
 * @param importFn - Function that returns a dynamic import promise
 * @returns Lazy-loaded component
 *
 * @example
 * const HomePage = lazyRoute(() => import('./pages/HomePage'));
 */
export function lazyRoute<T extends React.ComponentType<any>>(
  importFn: () => Promise<{ default: T }>
): React.LazyExoticComponent<T> {
  return React.lazy(importFn);
}

/**
 * Creates a lazy route from a module path
 * Useful for dynamic module loading
 *
 * @param modulePath - Relative path to module
 * @returns Lazy-loaded component
 *
 * @example
 * const SetupHome = lazyRouteFromPath('../../modules/setup/pages/Home');
 */
export function lazyRouteFromPath<T extends React.ComponentType<any>>(
  modulePath: string
): React.LazyExoticComponent<T> {
  return React.lazy(() => import(/* @vite-ignore */ modulePath) as Promise<{ default: T }>);
}

/**
 * Preloads a lazy component
 * Useful for prefetching likely-to-be-visited routes
 *
 * @param lazyComponent - Lazy component to preload
 *
 * @example
 * const HomePage = lazyRoute(() => import('./HomePage'));
 * preloadLazyRoute(HomePage); // Starts downloading immediately
 */
export function preloadLazyRoute(
  lazyComponent: React.LazyExoticComponent<any>
): void {
  // Accessing _ctor triggers the import
  // This is an internal React implementation detail but widely used
  const component = lazyComponent as any;
  if (component._ctor) {
    component._ctor();
  }
}
```

**Pattern:** Type-safe lazy loading wrapper with preload capability

```typescript
export function logChunkLoad(chunkName: string, size?: number) {

      `[Chunk Loaded] ${chunkName}${size ? ` (${(size / 1024).toFixed(2)} KB)` : ''}`
    );
  }

  if (import.meta.env.DEV) {
    console.error(`[Chunk Error] Failed to load ${chunkName}:`, error);
  }
}

 */
if (import.meta.env.DEV && typeof window !== 'undefined') {

    loaded: new Set<string>(),
    failed: new Set<string>(),

    logStatus() {
      console.log('Loaded chunks:', Array.from(this.loaded));
      console.log('Failed chunks:', Array.from(this.failed));
    }
  };
}
```

### Error Handling Strategy

**Lazy Loading Errors:**

1. **Network Errors** (chunk download fails)
   - Caught by Suspense → Error Boundary
   - Show RouteError with retry button
   - Retry with cache busting: `import(url + '?t=' + Date.now())`

2. **Parse Errors** (chunk has syntax errors)
   - Caught by Suspense → Error Boundary
   - Show RouteError with error details (dev only)
   - Log to error reporting service (future)

3. **Component Errors** (component throws during render)
   - Caught by Error Boundary
   - Show error UI
   - Allow retry or navigation

**Loading State Management:**

1. **Fast Networks** (< 200ms load)
   - Suspense fallback may not show
   - Use `minDisplayTime` to prevent flash

2. **Slow Networks** (> 200ms load)
   - Show loading indicator immediately
   - Progressive loading for multiple chunks

3. **Very Slow Networks** (> 5s load)
   - Show loading with timeout warning
   - Offer option to cancel

**Error Display Pattern:**

```typescript
// Error caught by Error Boundary (future task)
<ErrorBoundary
  fallback={(error, retry) => (
    <RouteError
      error={error}
      moduleName={moduleName}
      onRetry={retry}
      onBack={() => navigate(-1)}
    />
  )}
>
  <Suspense fallback={<RouteLoading />}>
    <LazyComponent />
  </Suspense>
</ErrorBoundary>
```
