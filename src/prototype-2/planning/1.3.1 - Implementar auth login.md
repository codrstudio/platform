# Task Plan: 1.3.1 - Implementar /api/1/auth/login

## Context and Objective

This task implements the `/api/1/auth/login` endpoint, the primary authentication entry point for the platform. This endpoint receives user credentials (username and password), proxies them to the n8n Backbone for validation, and returns JWT access tokens and refresh tokens to the client.

### Why It's Needed

Authentication is the foundation of the platform's security model. The login endpoint establishes user sessions by issuing cryptographically secure tokens that enable subsequent authenticated requests. Without this endpoint, users cannot access protected resources or establish authenticated sessions.

### How It Integrates

The login endpoint integrates with:
- **n8n Backbone**: Delegates credential validation and user data retrieval to the `auth-login.json` workflow
- **JWT Service** (Task 1.3.6): Uses `jwtService.generateTokenPair()` to create access and refresh tokens
- **Token Rotation Service** (Task 1.3.7): Uses `tokenRotationService.storeRefreshToken()` to persist refresh tokens in Redis
- **Frontend Auth Context** (Task 1.3 - future): Provides the authentication API that the frontend will consume

### Business Value

- **User Authentication**: Enables users to authenticate and access protected platform features
- **Security Foundation**: Establishes the first layer of platform security through JWT-based authentication
- **Session Management**: Creates token families that enable secure token rotation and breach detection

### User Impact

Users can log in to the platform by providing credentials. On success, they receive tokens that grant access to protected resources. The system detects and prevents unauthorized access through credential validation, rate limiting, and token security measures.

### Data Flow

```
1. Frontend POST /api/1/auth/login
   ├─ Body: { username, password, realm?, schema? }
   └─ Headers: Content-Type: application/json

2. Backend: Route Handler (auth.routes.ts)
   ├─ Validate request body (username, password required)
   ├─ Call n8nProxyService.login(credentials)
   └─ Handle response or error

3. n8nProxy.service.ts
   ├─ POST to n8n: {N8N_BASE_URL}/webhook/auth/login
   ├─ Headers: X-Platform-Key: {PLATFORM_SHARED_SECRET}
   ├─ Timeout: 10 seconds
   └─ Return user data or throw error

4. Backend: Generate Tokens
   ├─ Extract user data from n8n response
   ├─ Generate JWT: jwtService.generateAccessToken({ sub: userId, ...userData })
   ├─ Generate refresh token: tokenRotationService.generateRefreshToken()
   ├─ Generate NEW familyId: crypto.randomUUID()
   └─ Store refresh token: tokenRotationService.storeRefreshToken(token, options)

5. Backend: Return Response
   └─ 200 JSON: { access_token, refresh_token, token_type, expires_in, payload }

Error Flow:
   ├─ Invalid credentials → n8n returns 401 → Backend returns 401 with code/message
   ├─ Network error → Backend returns 500 with code: 'n8n_unavailable'
   ├─ Timeout → Backend returns 500 with code: 'request_timeout'
   └─ Internal error → Caught by error handler → 500 with generic message
```

### Error Handling Strategy

#### Error Types

**Network Errors** (fetch failures):
- **Cause**: n8n unreachable, DNS failure, network timeout
- **Handling**: Catch in n8nProxyService, throw descriptive error, log with console.error
- **Response**: HTTP 500 with `{ code: 'n8n_unavailable', message: 'Authentication service is unavailable' }`

**Validation Errors** (missing fields):
- **Cause**: Client sent incomplete request (missing username or password)
- **Handling**: Check in route handler before calling n8n
- **Response**: HTTP 400 with `{ code: 'missing_field', field: 'username', message: 'Username is required' }`

**Authentication Errors** (invalid credentials):
- **Cause**: n8n returns 401 (user not found or password mismatch)
- **Handling**: Check response status from n8n, parse error message
- **Response**: HTTP 401 with `{ code: 'invalid_credentials', message: 'Invalid username or password' }`

**Timeout Errors** (slow n8n response):
- **Cause**: n8n workflow takes longer than 10 seconds
- **Handling**: AbortController triggers abort signal, catch AbortError
- **Response**: HTTP 500 with `{ code: 'request_timeout', message: 'Authentication request timed out' }`

**Redis Errors** (token storage failure):
- **Cause**: Redis connection lost or write failure
- **Handling**: tokenRotationService throws error, caught by route handler
- **Response**: HTTP 500 with `{ code: 'internal_error', message: 'Failed to store session' }`

#### Error Display Pattern

**Console Logging** (Development):

### Success Criteria

- [ ] Login endpoint responds at `POST /api/1/auth/login`
- [ ] Valid credentials return HTTP 200 with `access_token`, `refresh_token`, `token_type`, `expires_in`
- [ ] Invalid credentials return HTTP 401 with `code: 'invalid_credentials'`
- [ ] Missing username or password returns HTTP 400 with `code: 'missing_field'`
- [ ] Refresh token is stored in Redis with correct metadata (userId, familyId, ipAddress, userAgent)
- [ ] Access token is valid JWT with correct payload (sub, iss, exp, iat)
- [ ] Family ID is generated as new UUID (not reused from rotation)
- [ ] Password is NEVER logged in console or error messages
- [ ] n8n communication includes `X-Platform-Key` header for authentication
- [ ] Network errors return HTTP 500 with appropriate error code
- [ ] TypeScript compilation succeeds with no errors
