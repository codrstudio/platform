# Task Plan: 1.6.9 - Implementar compartilhamento de tema por settings-key

## Context and Objective

This task implements the settings-key based theme sharing mechanism that allows multiple portals to share the same theme configuration. This is a core platform feature that enables flexible theme management - portals can either share a common theme or have independent themes based on their `settings-key` value.

**What will be implemented:**
- Portal settings-key retrieval from portal configuration
- Settings-key prefixed localStorage keys for theme preferences
- Dynamic theme loading based on active portal's settings-key
- Portal switching detection and theme reloading
- Shared theme behavior (multiple portals with same settings-key)
- Independent theme behavior (portals with different settings-key)
- Migration from global theme storage to settings-key prefixed storage

**Why it's needed:**
- Enables multi-portal theme customization (core platform requirement)
- Allows portals to share branding (e.g., "sac" and "admin" portals use same theme)
- Provides flexibility for independent portal branding
- Follows SPEC-theming.md settings-key architecture

**How it integrates:**
- Extends ThemeProvider from task 1.6.8
- Reads portal configuration via usePortalConfig hook
- Uses portal's `settings-key` property to namespace theme preferences
- Updates when navigating between portals with different settings-keys

**Business value:**
- Multi-tenant branding capability
- Reduced configuration duplication (shared themes)
- Portal-specific customization when needed

**User impact:**
- Seamless theme transitions when switching portals
- Consistent branding across related portals
- Ability to customize independent portals differently

## Critical Context

### Documentation

**Settings-Key Architecture (SPEC-theming.md):**
- SPEC-TH-SK-001: Each portal MUST have a `settings-key` property
- SPEC-TH-SK-003: Default value is `"default"`
- SPEC-TH-SK-005: Portals with same settings-key share theme configuration
- SPEC-TH-SK-008: Storage keys use format `{settings-key}:{config}`

**Portal Configuration (SPEC-concepts.md):**
- Portals are isolated sub-applications
- Each portal has unique `portalId`
- Portal settings stored in `backend/config/portals.json`
- Accessed via JQEL query with schema="backend"

**Theme Isolation (SPEC-theming.md):**
- SPEC-TH-NP-001: Each portal applies its own theme
- SPEC-TH-NP-003: Portals sharing settings-key have same theme
- SPEC-TH-NP-004: Different settings-keys = independent themes

### Gotchas and Pitfalls

**⚠️ Portal Configuration Loading Race**
- ThemeProvider mounts before portal configuration loads
- Must handle `portal = null` case gracefully
- Fallback to 'default' settings-key during loading
- Re-apply theme once portal loads

**⚠️ Portal Switching Detection**
- URL changes but component may not remount
- Must detect settings-key changes in useEffect
- Compare previous vs current settings-key
- Reload theme only if settings-key actually changed

**⚠️ Storage Key Migration**
- Existing users may have old `platform:theme:mode` key
- Need migration logic to move to settings-key format
- Don't lose user's theme preference during migration

**⚠️ Settings-Key Not in Portal**
- Backend portal config may not have `settings-key` yet
- Must handle missing property gracefully
- Default to `"default"` if not present
- Type definition should make it optional initially

**⚠️ Multiple Portals Same Route**
- Main portal always at "/"
- Other portals at "/:portalId/*"
- Extract portal ID correctly from both patterns
- PortalLoader already handles this - reuse that logic

**⚠️ Cross-Tab Sync with Settings-Keys**
- Storage event contains key that changed
- Must parse settings-key from key format
- Only apply change if settings-key matches current portal

#### 2. Update Theme Storage with Settings-Key Support

**File:** `src/frontend/src/services/theme/themeStorage.ts`

**Complete rewrite with settings-key support:**
```typescript
/**
 * Theme persistence utilities with settings-key support
 * Based on SPEC-theming.md SPEC-TH-SK-001:014
 */

import type { ThemeMode } from '../../types/theme';

/**
 * Generate storage key with settings-key prefix
 *
 * @param settingsKey - Portal's settings-key
 * @param config - Configuration name (e.g., 'theme', 'brand-color')
 * @returns Prefixed storage key
 */
function getStorageKey(settingsKey: string, config: string): string {
  return `${settingsKey}:${config}`;
}

/**
 * Save theme mode to localStorage with settings-key prefix
 *
 * @param settingsKey - Portal's settings-key
 * @param mode - Theme mode to save
 */
export function saveThemeMode(settingsKey: string, mode: ThemeMode): void {
  try {
    const key = getStorageKey(settingsKey, 'theme');
    localStorage.setItem(key, mode);
  } catch (error) {
    console.error('Failed to save theme mode:', error);
  }
}

/**
 * Load theme mode from localStorage with settings-key prefix
 *
 * @param settingsKey - Portal's settings-key
 * @returns Saved theme mode or null if not found
 */
export function loadThemeMode(settingsKey: string): ThemeMode | null {
  try {
    const key = getStorageKey(settingsKey, 'theme');
    const stored = localStorage.getItem(key);

    // Validate stored value
    if (stored === 'light' || stored === 'dark' || stored === 'system') {
      return stored;
    }

    return null;
  } catch (error) {
    console.error('Failed to load theme mode:', error);
    return null;
  }
}

/**
 * Save brand color to localStorage with settings-key prefix
 *
 * @param settingsKey - Portal's settings-key
 * @param color - Brand color (HEX format)
 */
export function saveBrandColor(settingsKey: string, color: string): void {
  try {
    const key = getStorageKey(settingsKey, 'brand-color');
    localStorage.setItem(key, color);
  } catch (error) {
    console.error('Failed to save brand color:', error);
  }
}

/**
 * Load brand color from localStorage with settings-key prefix
 *
 * @param settingsKey - Portal's settings-key
 * @returns Saved brand color or null if not found
 */
export function loadBrandColor(settingsKey: string): string | null {
  try {
    const key = getStorageKey(settingsKey, 'brand-color');
    return localStorage.getItem(key);
  } catch (error) {
    console.error('Failed to load brand color:', error);
    return null;
  }
}

/**
 * Clear theme preferences for a settings-key
 *
 * @param settingsKey - Portal's settings-key
 */
export function clearThemePreferences(settingsKey: string): void {
  try {
    localStorage.removeItem(getStorageKey(settingsKey, 'theme'));
    localStorage.removeItem(getStorageKey(settingsKey, 'brand-color'));
  } catch (error) {
    console.error('Failed to clear theme preferences:', error);
  }
}

/**
 * Get storage key for theme mode
 * Exposed for cross-tab synchronization
 *
 * @param settingsKey - Portal's settings-key
 * @returns Full storage key
 */
export function getThemeModeKey(settingsKey: string): string {
  return getStorageKey(settingsKey, 'theme');
}

/**
 * Get storage key for brand color
 * Exposed for cross-tab synchronization
 *
 * @param settingsKey - Portal's settings-key
 * @returns Full storage key
 */
export function getBrandColorKey(settingsKey: string): string {
  return getStorageKey(settingsKey, 'brand-color');
}

/**
 * Migrate old global theme key to settings-key format
 * Called once on first load to preserve user preferences
 *
 * @param settingsKey - Target settings-key (usually 'default')
 */
export function migrateGlobalTheme(settingsKey: string): void {
  try {
    // Old global key (from task 1.6.8)
    const oldKey = 'platform:theme:mode';
    const oldValue = localStorage.getItem(oldKey);

    if (oldValue) {
      // Move to new settings-key format
      const newKey = getStorageKey(settingsKey, 'theme');

      // Only migrate if new key doesn't exist
      if (!localStorage.getItem(newKey)) {
        localStorage.setItem(newKey, oldValue);
        console.log(`Migrated theme from ${oldKey} to ${newKey}`);
      }

      // Remove old key
      localStorage.removeItem(oldKey);
    }
  } catch (error) {
    console.error('Failed to migrate theme:', error);
  }
}

/**
 * Extract settings-key from storage key
 * Used for cross-tab synchronization filtering
 *
 * @param storageKey - Full storage key (e.g., "default:theme")
 * @returns Settings-key or null if invalid format
 */
export function extractSettingsKey(storageKey: string): string | null {
  const parts = storageKey.split(':');

  if (parts.length >= 2) {
    return parts[0];
  }

  return null;
}
```

#### 3. Update ThemeProvider with Portal Awareness

**File:** `src/frontend/src/providers/ThemeProvider.tsx`

**Major changes to add settings-key support:**

```typescript
/**
 * ThemeProvider - Global theme management with settings-key support
 *
 * Based on SPEC-theming.md SPEC-TH-SK-001:014
 *
 * Features (from 1.6.8):
 * - Theme mode management (light/dark/system)
 * - System theme detection and watching
 * - localStorage persistence
 * - Dark class application
 * - CSS palette generation
 * - Cross-tab synchronization
 *
 * NEW (1.6.9):
 * - Portal settings-key awareness
 * - Per-settings-key theme isolation
 * - Automatic theme reload on portal switch
 * - Settings-key based storage keys
 */

import React, { createContext, useContext, useState, useEffect, useMemo, useCallback } from 'react';
import { useParams, useLocation } from 'react-router-dom';  // ADD
import type { ThemeMode, ThemeContextValue, HSL } from '../types/theme';
import { usePortalConfig } from '../hooks/usePortalConfig';  // ADD
import {
  saveThemeMode,
  loadThemeMode,
  saveBrandColor,
  loadBrandColor,
  getThemeModeKey,
  getBrandColorKey,
  extractSettingsKey,
  migrateGlobalTheme,  // ADD
} from '../services/theme/themeStorage';
import { detectSystemTheme, watchSystemTheme } from '../services/theme/systemTheme';
import { convertHexToHSL, generatePalette, applyPalette } from '../services/theme';

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

/**
 * ThemeProvider component with settings-key support
 */
export function ThemeProvider({ children }: { children: React.ReactNode }) {
  // Portal context from URL
  const params = useParams<{ portalId?: string }>();
  const location = useLocation();

  // Determine portal ID
  const portalId = useMemo(() => {
    if (params.portalId) return params.portalId;
    return location.pathname === '/' ? 'main' : 'main';
  }, [params.portalId, location.pathname]);

  // Load portal configuration
  const { portal, loading: portalLoading } = usePortalConfig(portalId);

  // Extract settings-key from portal (with fallback)
  const settingsKey = useMemo(() => {
    return portal?.settingsKey || 'default';
  }, [portal?.settingsKey]);

  // Track current settings-key to detect changes
  const [currentSettingsKey, setCurrentSettingsKey] = useState<string>('default');

  // Migration flag (run once per settings-key)
  const [migrated, setMigrated] = useState<Set<string>>(new Set());

  // Theme mode state
  const [mode, setModeState] = useState<ThemeMode>(() => {
    // Initial load from 'default' settings-key
    return loadThemeMode('default') || 'system';
  });

  // Resolved mode
  const [resolvedMode, setResolvedMode] = useState<'light' | 'dark'>(() => {
    if (mode === 'system') {
      return detectSystemTheme();
    }
    return mode;
  });

  // Brand color state
  const [brandColor, setBrandColorState] = useState<string | null>(() => {
    // Initial load from 'default' settings-key
    return loadBrandColor('default');
  });

  // Derived state
  const isDark = resolvedMode === 'dark';

  /**
   * Load theme for current settings-key
   */
  const loadThemeForSettingsKey = useCallback((key: string) => {
    // Run migration once per settings-key
    if (!migrated.has(key)) {
      migrateGlobalTheme(key);
      setMigrated(prev => new Set(prev).add(key));
    }

    // Load theme mode
    const savedMode = loadThemeMode(key) || 'system';
    setModeState(savedMode);

    // Resolve mode
    if (savedMode !== 'system') {
      setResolvedMode(savedMode);
    } else {
      setResolvedMode(detectSystemTheme());
    }

    // Load brand color
    const savedColor = loadBrandColor(key);
    setBrandColorState(savedColor);

    console.log(`Loaded theme for settings-key "${key}": mode=${savedMode}, color=${savedColor}`);
  }, [migrated]);

  /**
   * Detect settings-key changes and reload theme
   */
  useEffect(() => {
    if (settingsKey !== currentSettingsKey) {
      loadThemeForSettingsKey(settingsKey);
      setCurrentSettingsKey(settingsKey);
    }
  }, [settingsKey, currentSettingsKey, loadThemeForSettingsKey]);

  /**
   * Update theme mode (settings-key aware)
   */
  const setMode = useCallback((newMode: ThemeMode) => {
    setModeState(newMode);
    saveThemeMode(currentSettingsKey, newMode);  // Use current settings-key

    // Resolve immediately if not system
    if (newMode !== 'system') {
      setResolvedMode(newMode);
    } else {
      setResolvedMode(detectSystemTheme());
    }
  }, [currentSettingsKey]);

  /**
   * Update brand color (settings-key aware)
   */
  const setBrandColor = useCallback((color: string) => {
    setBrandColorState(color);
    saveBrandColor(currentSettingsKey, color);  // Use current settings-key
  }, [currentSettingsKey]);

  /**
   * Apply dark class to HTML element
   */
  useEffect(() => {
    const root = document.documentElement;

    if (isDark) {
      root.classList.add('dark');
    } else {
      root.classList.remove('dark');
    }
  }, [isDark]);

  /**
   * Apply CSS palette when brand color or mode changes
   */
  useEffect(() => {
    if (brandColor) {
      try {
        const hsl = convertHexToHSL(brandColor);
        const palette = generatePalette(hsl, resolvedMode);
        applyPalette(palette);
      } catch (error) {
        console.error('Failed to apply brand color:', error);
      }
    }
  }, [brandColor, resolvedMode]);

  /**
   * Watch system theme changes (when mode is 'system')
   */
  useEffect(() => {
    if (mode !== 'system') {
      return;
    }

    const cleanup = watchSystemTheme((systemTheme) => {
      setResolvedMode(systemTheme);
    });

    return cleanup;
  }, [mode]);

  /**
   * Cross-tab synchronization (settings-key filtered)
   */
  useEffect(() => {
    const handleStorageChange = (event: StorageEvent) => {
      if (!event.key) return;

      // Extract settings-key from changed key
      const changedSettingsKey = extractSettingsKey(event.key);

      // Only apply if it matches current settings-key
      if (changedSettingsKey !== currentSettingsKey) {
        return;
      }

      // Handle theme mode change
      if (event.key === getThemeModeKey(currentSettingsKey)) {
        const newMode = event.newValue as ThemeMode | null;
        if (newMode === 'light' || newMode === 'dark' || newMode === 'system') {
          setModeState(newMode);

          if (newMode !== 'system') {
            setResolvedMode(newMode);
          } else {
            setResolvedMode(detectSystemTheme());
          }
        }
      }

      // Handle brand color change
      if (event.key === getBrandColorKey(currentSettingsKey)) {
        setBrandColorState(event.newValue);
      }
    };

    window.addEventListener('storage', handleStorageChange);

    return () => {
      window.removeEventListener('storage', handleStorageChange);
    };
  }, [currentSettingsKey]);

  // Context value
  const value = useMemo<ThemeContextValue>(
    () => ({
      mode,
      resolvedMode,
      setMode,
      isDark,
      brandColor,
      setBrandColor,
    }),
    [mode, resolvedMode, setMode, isDark, brandColor, setBrandColor]
  );

  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}

/**
 * Hook to access theme context
 */
export function useTheme(): ThemeContextValue {
  const context = useContext(ThemeContext);

  if (context === undefined) {
    throw new Error(
      'useTheme must be used within a ThemeProvider. ' +
      'Wrap your component tree with <ThemeProvider>.'
    );
  }

  return context;
}
```

### Error Handling Strategy

**Portal Loading Errors:**
- Gracefully handle `portal = null` during loading
- Default to 'default' settings-key if portal not loaded
- Continue with default theme if portal query fails

**Settings-Key Missing:**
- If `portal.settingsKey` is undefined, default to 'default'
- Log warning but continue
- Backward compatible with portals without settingsKey property

**Storage Errors:**
- All localStorage operations wrapped in try-catch
- Log errors but continue with defaults
- Graceful degradation (theme works without persistence)

**Migration Errors:**
- Catch migration failures
- Log warning
- Don't block theme loading

**Error Pattern:**
```typescript
// Portal loading with fallback
const settingsKey = portal?.settingsKey || 'default';

// Storage with error handling
try {
  const mode = loadThemeMode(settingsKey);
  setMode(mode || 'system');
} catch (error) {
  console.error('Failed to load theme:', error);
  setMode('system'); // Safe fallback
}
```
