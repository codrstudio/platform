# Task Plan: 1.3.4 - Implementar /api/1/auth/logout-all

## Context and Objective

This task focuses on **validation and testing** of the `/api/1/auth/logout-all` endpoint, which was already implemented in task 1.3.9. The endpoint enables users to revoke all their active refresh tokens across all devices, terminating all sessions simultaneously.

**What has been implemented:**
- POST `/api/1/auth/logout-all` endpoint in `backend/src/routes/auth.routes.ts`
- JWT access token extraction from multiple sources (header > body > cookie)
- Token validation and user ID extraction
- Bulk token revocation via `tokenRotationService.revokeAllUserTokens()`
- Complete error handling for invalid/expired tokens
- Full SPEC compliance verified in task 1.3.9 (17/17 SPEC-AU-LA requirements met)

**Why validation is needed:**
This endpoint is a critical security feature. Comprehensive testing ensures:
- Users can securely terminate all sessions when device is lost/stolen
- No edge cases allow tokens to remain active after logout-all
- Error handling properly prevents unauthorized access
- Performance remains acceptable even with many active sessions

**How it integrates:**
- Used by frontend Auth Module for "logout all devices" functionality
- Used for security operations (password reset, account compromise)
- Integrates with JWT service for token validation
- Integrates with tokenRotationService for bulk revocation
- Works alongside `/logout` (single device) and `/refresh` (session renewal)

**Business value:**
- Enhanced security: users can remotely terminate all sessions
- Compliance: meets security audit requirements for session management
- User trust: provides control over account access across devices
- Risk mitigation: limits damage from token theft or device loss

**User impact:**
- Users can logout from all devices with one action
- Lost/stolen device tokens are immediately invalidated
- Account compromise can be quickly mitigated
- Peace of mind for security-conscious users

## Critical Context

### Documentation

- [RFC 6749 - OAuth 2.0](https://datatracker.ietf.org/doc/html/rfc6749#section-1.5) - Token revocation patterns

- [JWT RFC 7519](https://datatracker.ietf.org/doc/html/rfc7519) - JWT validation requirements

### Gotchas and Pitfalls

- **JWT Expiration**: Test with both valid and expired access tokens - expired should return 401
- **Missing Token**: All three sources (header/body/cookie) must be tested for proper priority
- **Invalid Signature**: Tampered tokens should be rejected before attempting revocation
- **No Active Tokens**: User with zero tokens should succeed with count=0 (not error)
- **Redis Failure**: If Redis is down, endpoint should fail gracefully with 500 error
- **Race Conditions**: Multiple simultaneous logout-all calls should all succeed
- **Token Priority**: Authorization header MUST take precedence over body and cookie (SPEC-AU-LA-004)
- **Partial Failures**: If some tokens fail to revoke, should still return success with partial count

## Technical Specification

### Architecture

```
Backend Routes (auth.routes.ts)
├── POST /api/1/auth/logout-all
│   ├── Extract access_token (header > body > cookie)
│   ├── Validate JWT (jwtService.verifyAccessToken)
│   ├── Extract userId from JWT payload
│   ├── Revoke all tokens (tokenRotationService.revokeAllUserTokens)
│   └── Return success with count
│
Services
├── jwtService.verifyAccessToken()
│   ├── Verify signature (HS256)
│   ├── Check expiration
│   └── Return payload with userId (sub)
│
└── tokenRotationService.revokeAllUserTokens()
    ├── Find all user tokens (SMEMBERS user_tokens:<userId>)
    ├── Mark each as revoked (SETEX with revoked=true)
    └── Return count of revoked tokens
```

### Data Flow

```
┌──────────────────────────────────────────────────────────────┐
│  Client → POST /api/1/auth/logout-all                        │
│  Authorization: Bearer <access_token>                        │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Backend: Extract Token (Priority: header > body > cookie)  │
│  - Check Authorization header first                          │
│  - Fallback to body.access_token                            │
│  - Fallback to cookie.access_token                          │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  JWT Service: Validate Access Token                          │
│  - Verify signature (HS256)                                  │
│  - Check expiration (iat/exp claims)                         │
│  - Extract userId from 'sub' claim                           │
│  ✓ Valid → Continue                                          │
│  ✗ Invalid/Expired → 401 Unauthorized                        │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Token Rotation Service: Revoke All User Tokens              │
│  1. Query Redis: SMEMBERS user_tokens:<userId>               │
│  2. For each token hash:                                     │
│     - GET refresh_token:<hash>                               │
│     - Update data.revoked = true                             │
│     - SETEX with remaining TTL                               │
│  3. Return count of revoked tokens                           │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Response: HTTP 200 OK                                       │
│  {                                                           │
│    "code": "success",                                        │
│    "message": "All sessions logged out successfully",        │
│    "tokens_revoked": 3                                       │
│  }                                                           │
└──────────────────────────────────────────────────────────────┘
```

### Modules and Responsibilities

**auth.routes.ts - /logout-all endpoint**
- Extract access token from request (header/body/cookie)
- Validate access token via jwtService
- Extract userId from token payload
- Call tokenRotationService to revoke all tokens
- Return success response with count

**jwtService.verifyAccessToken()**
- Verify JWT signature using secret
- Check expiration timestamp
- Return decoded payload or throw error

**tokenRotationService.revokeAllUserTokens()**
- Find all tokens for user in Redis
- Mark each token as revoked
- Handle Redis errors gracefully
- Return count of revoked tokens

### State Management

**Token State:**
- Active tokens stored in Redis: `user_tokens:<userId>` (SET)
- Each token data at: `refresh_token:<tokenHash>` (STRING with JSON)
- Revoked state: `data.revoked = true` in token data

**No Frontend State:**
- Endpoint is stateless (validates token on each request)
- No session management in backend memory
- All state in Redis (distributed, persistent)

**Error Types:**

1. **Missing Token** (No header/body/cookie)
   - HTTP 401 Unauthorized

   - Message: "Access token is required"

2. **Invalid Token** (Bad signature, malformed)

   - Code: `invalid_token`
   - Message: "Access token is invalid"

3. **Expired Token** (Past exp claim)
   - HTTP 401 Unauthorized
   - Code: `token_expired`
   - Message: "Access token has expired"

4. **Missing User ID** (No sub claim)

   - Code: `invalid_token`
   - Message: "Token does not contain user ID"

5. **Redis Failure** (Connection error)
   - HTTP 500 Internal Server Error
   - Logged but not exposed to client
   - Service should recover automatically

```bash
#!/bin/bash
# Automated test script for /api/1/auth/logout-all endpoint

API_URL="http://localhost:3000/api/1/auth"
LOG_FILE=".tmp/test-results.log"

echo "=== Logout-All Endpoint Test Suite ===" | tee "$LOG_FILE"
echo "Started: $(date)" | tee -a "$LOG_FILE"
echo "" | tee -a "$LOG_FILE"

# Colors for output
GREEN='\033[0;32m'
RED='\033[0;31m'
NC='\033[0m' # No Color

# Test counter
PASS=0
FAIL=0

# Helper function to run test
run_test() {
  local test_name="$1"
  local expected_status="$2"
  shift 2
  local curl_args=("$@")

  echo "Test: $test_name" | tee -a "$LOG_FILE"

  response=$(curl -s -w "\n%{http_code}" "${curl_args[@]}" "$API_URL/logout-all")
  status_code=$(echo "$response" | tail -n 1)
  body=$(echo "$response" | head -n -1)

  if [ "$status_code" = "$expected_status" ]; then
    echo -e "${GREEN}✓ PASS${NC} (HTTP $status_code)" | tee -a "$LOG_FILE"
    ((PASS++))
  else
    echo -e "${RED}✗ FAIL${NC} (Expected HTTP $expected_status, got $status_code)" | tee -a "$LOG_FILE"
    ((FAIL++))
  fi

  echo "Response: $body" | tee -a "$LOG_FILE"
  echo "" | tee -a "$LOG_FILE"
}

# Generate test token (requires Node.js script)
echo "Generating test tokens..." | tee -a "$LOG_FILE"
VALID_TOKEN=$(node .tmp/generate-token.js "test-user-1")
EXPIRED_TOKEN=$(node .tmp/generate-expired-token.js "test-user-1")

# Test 1: Valid token
run_test "Valid token in header" 200 \
  -X POST \
  -H "Authorization: Bearer $VALID_TOKEN" \
  -H "Content-Type: application/json"

# Test 2: Missing token
run_test "Missing token" 401 \
  -X POST \
  -H "Content-Type: application/json"

# Test 3: Invalid token
run_test "Invalid token signature" 401 \
  -X POST \
  -H "Authorization: Bearer invalid.token.signature" \
  -H "Content-Type: application/json"

# Test 4: Expired token
run_test "Expired token" 401 \
  -X POST \
  -H "Authorization: Bearer $EXPIRED_TOKEN" \
  -H "Content-Type: application/json"

# Test 5: Token in body
run_test "Token in body" 200 \
  -X POST \
  -H "Content-Type: application/json" \
  -d "{\"access_token\": \"$VALID_TOKEN\"}"

# Summary
echo "=== Test Summary ===" | tee -a "$LOG_FILE"
echo "Passed: $PASS" | tee -a "$LOG_FILE"
echo "Failed: $FAIL" | tee -a "$LOG_FILE"
echo "Completed: $(date)" | tee -a "$LOG_FILE"

exit $FAIL
```
