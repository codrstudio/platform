# Task Plan: 2.2.4 - Implementar color picker para brand color

## Context and Objective

This task implements a visual color picker interface within the Setup module that allows users to select and configure the brand color for a portal. The brand color is the primary color that defines the visual identity of the portal, affecting buttons, links, focus states, and other UI elements.

**Why it's needed:** Currently, the theming system (System 1.6) is fully implemented with brand color support at the infrastructure level (ThemeProvider, color conversion, palette generation, contrast validation), but there's no UI in the Setup module to actually configure it. This creates the user-facing interface for brand color management.

**How it integrates:** This component will be part of the Setup module's theme configuration page, working alongside the theme mode selector (light/dark/system). It directly uses the existing `useTheme()` hook and theme services.

**Business value:** Enables portal administrators to customize the visual identity of their portals without code changes, allowing brand consistency and multi-tenant customization.

**User impact:** Portal administrators can visually select colors and see real-time preview of how their brand color affects the UI across light and dark themes.

## Critical Context

### Documentation

- [react-colorful docs](https://github.com/omgovich/react-colorful) - Lightweight (2.5KB), accessible color picker with no dependencies
  - Provides `<HexColorPicker>` for direct HEX input
  - Fully accessible (keyboard navigation, ARIA labels)
  - Controlled component pattern (value + onChange)
  - Supports custom styling via CSS

- [WCAG 2.1 Contrast Guidelines](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)
  - Normal text: 4.5:1 minimum (AA), 7:1 preferred (AAA)
  - Large text (18pt+): 3:1 minimum (AA), 4.5:1 preferred (AAA)
  - UI components: 3:1 minimum (AA)

### Gotchas and Pitfalls

- ⚠️ **react-colorful uses lowercase hex without #**: Component expects format `"ff0000"`, not `"#FF0000"`. Need to strip/add `#` in conversion.

- ⚠️ **Contrast validation requires theme context**: Brand color needs different lightness values for light vs dark theme. Must validate against both backgrounds.

- ⚠️ **HSL storage vs HEX input**: Internal storage uses HSL format for easier manipulation, but users expect HEX input. Conversion must be bidirectional and lossless.

- ⚠️ **localStorage keys must use settings-key**: Theme storage uses format `{settings-key}:brand-color`. The `useTheme()` hook handles this automatically via `setBrandColor()`.

- ⚠️ **Color reset functionality**: Removing brand color (setting to `null`) must revert to Tailwind defaults. The theme system already handles this - just call `setBrandColor(null)`.

### User Journey

1. **Initial State** - User navigates to Setup module home page
   - ColorPicker displays current brand color (or default blue if none set)
   - Shows "Current Brand Color" label with color swatch
   - Displays HEX value in input field

2. **Color Selection via Picker** - User drags/clicks on color picker
   - Visual picker updates in real-time as user drags
   - HEX input field updates with selected color
   - Validation runs automatically on change
   - Warning appears if contrast insufficient

3. **Color Selection via Text Input** - User types HEX value
   - Validates format (#rrggbb or rrggbb)
   - Shows error message if invalid format
   - Updates visual picker if valid
   - Runs contrast validation

4. **Contrast Warning** - Color fails WCAG AA contrast check
   - Yellow warning banner appears with AlertTriangle icon
   - Message: "This color may have insufficient contrast. Suggested adjustment: [color]"
   - Two options: "Use Suggested" button or "Use Anyway" button
   - Preview shows both original and adjusted colors

5. **Applying Color** - User clicks "Apply" button
   - Brand color saves to localStorage via `setBrandColor()`
   - UI updates instantly with new color scheme
   - Success feedback (color swatch updates, checkmark animation)
   - Warning dismisses if it was showing

6. **Reset to Default** - User clicks "Reset to Default" button
   - Confirmation: "Reset to default blue color?"
   - On confirm: `setBrandColor(null)` reverts to Tailwind default
   - Visual picker resets to default blue (#3b82f6)
   - Success feedback shown

### Error Handling Strategy

**Error Types:**

1. **Invalid HEX Format**
   - Handling: Inline validation, show error message below input
   - Display: "Invalid HEX color format. Use format #rrggbb or rrggbb"
   - Recovery: Input remains editable, error clears on valid input

2. **Color Conversion Failure**
   - Handling: Try-catch around `convertHexToHSL()`
   - Display: Generic error toast: "Unable to process color"
   - Recovery: Revert to previous valid color, log error to console

3. **Contrast Validation Failure**
   - Handling: Try-catch around validation logic
   - Display: Warning banner with suggested color
   - Recovery: User can accept suggestion or proceed anyway

4. **localStorage Failure**
   - Handling: Caught by ThemeProvider, logs warning
   - Display: Toast: "Unable to save color preference"
   - Recovery: Color still applied to session (not persisted)

**Error Display Pattern:**
