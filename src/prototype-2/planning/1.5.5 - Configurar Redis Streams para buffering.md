# Task Plan: 1.5.5 - Configurar Redis Streams para buffering

## Context and Objective

This task implements Redis Streams as an event buffer to ensure reliable event delivery for offline clients. Redis Streams complements the Pub/Sub system (task 1.5.4) by persisting events that can be recovered when clients reconnect.

**Business Value:**
- Users never miss critical notifications or tasks, even when temporarily offline
- Provides recovery mechanism for connection drops, page refreshes, or network issues
- Creates audit trail of events for debugging and compliance

**User Impact:**
- Seamless experience across network interruptions
- No lost notifications when switching tabs or devices
- Reliable task delivery for time-sensitive operations

**Integration:**
- Works alongside Redis Pub/Sub for real-time delivery
- Integrates with SSE endpoint (task 1.5.2) for recovery on reconnect
- Supports n8n event publishing (task 1.5.3)

## Critical Context

### Documentation

#### Redis Streams Official Documentation
- **[Redis Streams Introduction](https://redis.io/docs/latest/develop/data-types/streams/)** - Core concepts and use cases
  - Streams are append-only log data structure
  - Each entry has unique ID (timestamp-sequence)
  - Supports consumer groups for distributed processing
  - MAXLEN option for automatic trimming

- **[XADD Command](https://redis.io/docs/latest/commands/xadd/)** - Add entry to stream
  - Syntax: `XADD key [MAXLEN ~ approximate_max_len] * field value [field value ...]`
  - Returns unique entry ID (e.g., "1526919030474-0")
  - `*` auto-generates ID based on server time
  - `MAXLEN ~` trims to approximate length (more efficient than exact)

- **[XREAD Command](https://redis.io/docs/latest/commands/xread/)** - Read entries from stream
  - Syntax: `XREAD [COUNT count] STREAMS key [key ...] id [id ...]`
  - Use `0` to read from beginning
  - Use last received ID to get only new entries
  - Supports blocking mode with BLOCK parameter

- **[XTRIM Command](https://redis.io/docs/latest/commands/xtrim/)** - Trim stream to specific length
  - Syntax: `XTRIM key MAXLEN ~ approximate_max_len`
  - Used for manual trimming (XADD handles automatic trimming)

- **[ioredis Streams API](https://github.com/redis/ioredis#streams)** - Node.js usage
  - Methods: `xadd`, `xread`, `xreadgroup`, `xtrim`, `xlen`, `xrange`
  - Returns arrays of entries: `[[id, [field1, value1, field2, value2]], ...]`
  - Full TypeScript support in ioredis 5.x

### Gotchas and Pitfalls

- **Entry ID Format**: Redis returns IDs as strings (e.g., "1526919030474-0"), not numbers
  - Always treat as opaque string, don't parse manually
  - Use `-` for special meaning (read all new), `+` (read until end), `0` (read from start)

- **MAXLEN Approximate (~)**: Using `~` is significantly faster than exact trimming
  - Redis may keep slightly more entries than specified
  - Tradeoff: ~10% extra entries vs. O(1) performance instead of O(N)
  - SPEC-EV-ST-008 requires approximate for performance

- **Field-Value Pairs**: XADD requires flat key-value pairs, not nested objects
  - Must serialize JSON objects to string before storing
  - Pattern: Store entire event as single `data` field with JSON string value
  - Example: `XADD events:user123 * data '{"type":"notification","id":"123"}'`

- **Memory Management**: Streams grow indefinitely without MAXLEN or TTL
  - SPEC-EV-ST-006 requires 1000 messages OR 24 hours retention
  - XADD with MAXLEN handles message limit automatically
  - Separate EXPIRE command needed for time-based expiration
  - Consider implementing both for safety

- **Consumer Groups vs. XREAD**: Two different consumption patterns
  - XREAD: Simple read for single consumer (our use case - SSE recovery)
  - XREADGROUP: Distributed processing with acknowledgment (future consideration)
  - For MVP, use XREAD without consumer groups

- **Connection Sharing**: ioredis client is thread-safe
  - Safe to use same `redisService.getClient()` for Pub/Sub, Streams, and key operations
  - Do NOT create separate Redis connections for Streams

```typescript
/**
 * Add entry to stream with automatic trimming
 *
 * Uses XADD with MAXLEN ~ (approximate) for O(1) performance.
 *
 * @param key - Stream key
 * @param maxLen - Maximum stream length (approximate)
 * @param fields - Field-value pairs to store
 * @returns Redis-generated entry ID
 *
 * @example
 * const id = await redisService.xadd(
 *   'events:user123',
 *   1000,
 *   { data: JSON.stringify(event) }
 * );
 */
async xadd(
  key: string,
  maxLen: number,
  fields: Record<string, string>
): Promise<string> {
  await this.connect();

  const args: (string | number)[] = [key, 'MAXLEN', '~', maxLen, '*'];

  for (const [field, value] of Object.entries(fields)) {
    args.push(field, value);
  }

  return this.client!.xadd(...args);
}

/**
 * Read entries from stream
 *
 * @param key - Stream key
 * @param fromId - Starting ID ('0' for all, '-' for new only, or specific ID)
 * @param count - Maximum number of entries to read
 * @returns Array of [entryId, [field, value, field, value, ...]]
 *
 * @example
 * const entries = await redisService.xread('events:user123', '0', 10);
 * // Returns: [['1234-0', ['data', '{"type":"notification"}']], ...]
 */
async xread(
  key: string,
  fromId: string,
  count?: number
): Promise<Array<[string, string[]]>> {
  await this.connect();

  const args: any[] = [];
  if (count) {
    args.push('COUNT', count);
  }
  args.push('STREAMS', key, fromId);

  const result = await this.client!.xread(...args);

  // XREAD returns [[streamKey, entries]] or null
  if (!result || result.length === 0) {
    return [];
  }

  return result[0][1];
}

/**
 * Get stream length
 *
 * @param key - Stream key
 * @returns Number of entries in stream
 */
async xlen(key: string): Promise<number> {
  await this.connect();
  return this.client!.xlen(key);
}

/**
 * Trim stream to maximum length
 *
 * @param key - Stream key
 * @param maxLen - Maximum length (approximate)
 * @returns Number of entries deleted
 */
async xtrim(key: string, maxLen: number): Promise<number> {
  await this.connect();
  return this.client!.xtrim(key, 'MAXLEN', '~', maxLen);
}
```

#### 4. Create RedisStreamsService
**Create**: `backend/src/services/redisStreams.service.ts`

**Details**:
```typescript
import { redisService } from './redis.service.js';
import { config } from '../config/env.js';
import type {
  PlatformEvent,
  StreamEvent,
  StreamInfo,
  AddEventResult,
} from '../types/events.types.js';

/**
 * RedisStreamsService
 *
 * High-level service for event buffering using Redis Streams.
 * Provides event persistence and recovery for offline clients.
 *
 * Refs:
 * - SPEC-EV-ST-001:016 - Redis Streams requirements
 * - SPEC-EV-AR-007 - Streams for event buffer
 */
export class RedisStreamsService {
  /**
   * Get stream key for user
   *
   * Pattern: events:{userId}
   */
  private getStreamKey(userId: string): string {
    return `events:${userId}`;
  }

  /**
   * Add event to user's stream
   *
   * Refs:
   * - SPEC-EV-ST-009 - XADD usage
   * - SPEC-EV-ST-010 - Include all metadata
   * - SPEC-EV-ST-006 - Retention policy (1000 messages OR 24h)
   *
   * @param userId - Target user ID
   * @param event - Event payload
   * @returns Stream entry ID and key
   */
  async addEvent(userId: string, event: PlatformEvent): Promise<AddEventResult> {
    const streamKey = this.getStreamKey(userId);

    try {
      // Serialize event to JSON string
      const eventJson = JSON.stringify(event);

      // Add to stream with automatic trimming (SPEC-EV-ST-008)
      const streamId = await redisService.xadd(
        streamKey,
        config.streamMaxLen,
        { data: eventJson }
      );

      // Set TTL on stream key (SPEC-EV-ST-006 - 24h retention)
      await redisService.expire(streamKey, config.streamTtlSeconds);

      console.log(`✅ Event added to stream: ${streamKey} (ID: ${streamId})`);

      return { streamId, streamKey };
    } catch (error) {
      console.error(`❌ Failed to add event to stream ${streamKey}:`, error);
      throw error;
    }
  }

  /**
   * Get events from stream since specific ID
   *
   * Refs:
   * - SPEC-EV-ST-013 - Recovery on reconnect
   * - SPEC-EV-ST-014 - Use last event timestamp
   *
   * @param userId - User ID
   * @param lastEventId - Last received event ID ('0' for all events)
   * @param limit - Maximum events to return (default: 100)
   * @returns Array of stream events
   */
  async getEventsSince(
    userId: string,
    lastEventId: string = '0',
    limit: number = 100
  ): Promise<StreamEvent[]> {
    const streamKey = this.getStreamKey(userId);

    try {
      const entries = await redisService.xread(streamKey, lastEventId, limit);

      return entries.map(([streamId, fields]) => {
        // Fields is array: ['data', '{...json...}']
        const eventJson = fields[1];
        const event = JSON.parse(eventJson) as PlatformEvent;

        return { streamId, event };
      });
    } catch (error) {
      console.error(`❌ Failed to read from stream ${streamKey}:`, error);
      throw error;
    }
  }

  /**
   * Get all events in stream
   *
   * @param userId - User ID
   * @param limit - Maximum events to return
   * @returns Array of stream events
   */
  async getAllEvents(userId: string, limit?: number): Promise<StreamEvent[]> {
    return this.getEventsSince(userId, '0', limit);
  }

  /**
   * Clear user's event stream
   *
   * Use case: Logout-all, user deletion, or explicit clear request
   *
   * @param userId - User ID
   */
  async clearUserStream(userId: string): Promise<void> {
    const streamKey = this.getStreamKey(userId);

    try {
      await redisService.delete(streamKey);
      console.log(`✅ Cleared stream: ${streamKey}`);
    } catch (error) {
      console.error(`❌ Failed to clear stream ${streamKey}:`, error);
      throw error;
    }
  }

  /**
   * Get stream information
   *
   * Useful for debugging and monitoring.
   *
   * @param userId - User ID
   * @returns Stream metadata
   */
  async getStreamInfo(userId: string): Promise<StreamInfo> {
    const streamKey = this.getStreamKey(userId);

    try {
      const length = await redisService.xlen(streamKey);
      const ttl = await redisService.ttl(streamKey);

      let oldestId: string | undefined;
      let newestId: string | undefined;

      if (length > 0) {
        // Get oldest entry
        const oldest = await redisService.xread(streamKey, '0', 1);
        if (oldest.length > 0) {
          oldestId = oldest[0][0];
        }

        // Get newest entry (read from '+' means read until end)
        const client = redisService.getClient();
        const newest = await client.xrevrange(streamKey, '+', '-', 'COUNT', 1);
        if (newest.length > 0) {
          newestId = newest[0][0];
        }
      }

      return {
        key: streamKey,
        length,
        ttl,
        oldestId,
        newestId,
      };
    } catch (error) {
      console.error(`❌ Failed to get stream info for ${streamKey}:`, error);
      throw error;
    }
  }
}

// Export singleton instance
```

#### 5. Create Event Recovery Endpoint
**Create**: `backend/src/routes/events.routes.ts`

**Details**:
```typescript
import { Router, type Request, type Response } from 'express';
import { redisStreamsService } from '../services/redisStreams.service.js';
import { jwtService } from '../services/jwt.service.js';

const router = Router();

/**
 * GET /api/events/recover
 *
 * Recover missed events from Redis Streams
 *
 * Query Parameters:
 * - since: Last received event ID (default: '0' for all events)
 * - limit: Maximum events to return (default: 100, max: 1000)
 *
 * Refs:
 * - SPEC-EV-ST-013 - Frontend recovery on reconnect
 * - SPEC-EV-ST-015 - Recovery via JQEL or dedicated endpoint
 */
router.get('/recover', async (req: Request, res: Response) => {
  try {
    // Extract JWT from Authorization header
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
      return res.status(401).json({
        success: false,
        error: {
          code: 'UNAUTHORIZED',
          message: 'Missing or invalid Authorization header',
        },
      });
    }

    const token = authHeader.substring(7);

    // Validate JWT and extract userId
    const payload = await jwtService.verifyAccessToken(token);
    const userId = payload.sub;

    // Get query parameters
    const since = (req.query.since as string) || '0';
    const limit = Math.min(
      parseInt(req.query.limit as string) || 100,
      1000 // Max 1000 events per request
    );

    // Fetch events from stream
    const events = await redisStreamsService.getEventsSince(userId, since, limit);

    // Return JResult envelope
    res.json({
      success: true,
      data: {
        events,
        count: events.length,
        since,
        hasMore: events.length === limit, // Hint that more events may exist
      },
    });
  } catch (error: any) {
    console.error('❌ Event recovery failed:', error);

    if (error.name === 'JsonWebTokenError') {
      return res.status(401).json({
        success: false,
        error: {
          code: 'INVALID_TOKEN',
          message: 'Invalid access token',
        },
      });
    }

    res.status(500).json({
      success: false,
      error: {
        code: 'RECOVERY_FAILED',
        message: 'Failed to recover events',
      },
    });
  }
});

/**
 * GET /api/events/stream-info
 *
 * Get stream information for debugging
 *
 * Requires authentication (admin only in production)
 */
router.get('/stream-info', async (req: Request, res: Response) => {
  try {
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
      return res.status(401).json({
        success: false,
        error: {
          code: 'UNAUTHORIZED',
          message: 'Missing or invalid Authorization header',
        },
      });
    }

    const token = authHeader.substring(7);
    const payload = await jwtService.verifyAccessToken(token);
    const userId = payload.sub;

    const info = await redisStreamsService.getStreamInfo(userId);

    res.json({
      success: true,
      data: info,
    });
  } catch (error) {
    console.error('❌ Stream info failed:', error);
    res.status(500).json({
      success: false,
      error: {
        code: 'INFO_FAILED',
        message: 'Failed to get stream info',
      },
    });
  }
});

export default router;
```

### Error Handling Strategy

#### Error Types

**Stream Operation Errors:**
- **XADD Failure**: Redis connection lost, disk full, invalid data
  - Handling: Log error, throw to caller, retry at application level
  - User Impact: Event not buffered, but Pub/Sub may still deliver if online

- **XREAD Failure**: Redis connection lost, stream doesn't exist
  - Handling: Return empty array, log warning
  - User Impact: No events recovered, graceful degradation

- **JSON Parsing Error**: Malformed event data in stream
  - Handling: Skip corrupted entry, log error, continue processing
  - User Impact: Single event lost, others still recovered

**Authentication Errors:**
- **Invalid JWT**: Expired, malformed, or missing token
  - Handling: Return 401 Unauthorized
  - User Impact: Cannot recover events, must re-authenticate

- **Missing Authorization Header**: Client didn't send token
  - Handling: Return 401 Unauthorized
  - User Impact: Cannot access recovery endpoint

**Backend Logging:**
