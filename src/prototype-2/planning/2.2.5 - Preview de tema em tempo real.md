# Task Plan: 2.2.5 - Preview de tema em tempo real

## Context and Objective

This task implements a real-time theme preview system within the Setup module that allows users to see how their brand color and theme mode selections affect the UI before applying changes. The preview shows the theme in both light and dark modes simultaneously, helping users make informed decisions about colors and ensure their brand maintains visual consistency across themes.

**Why it's needed:** Without live preview, users must apply a color, navigate to different pages, switch themes, and verify the result - a tedious trial-and-error process. Real-time preview dramatically improves the UX by showing immediate feedback and enabling confident color choices.

**How it integrates:** This component works alongside the ColorPicker (Task 2.2.4), receiving temporary color selections and displaying how they affect common UI elements. It uses the existing theme services to generate palettes but doesn't persist changes until the user explicitly applies them.

**Business value:** Reduces configuration time and errors by allowing visual validation before committing changes. Prevents accessibility issues by showing contrast problems in preview.

**User impact:** Users can experiment with colors confidently, seeing exactly how their choices affect buttons, cards, text, and other UI elements in both themes before saving.

## Critical Context

### Documentation

- [CSS Custom Properties (MDN)](https://developer.mozilla.org/en-US/docs/Web/CSS/--*) - How CSS variables work and scope
  - Can be scoped to any element, not just `:root`
  - Inherit down the DOM tree
  - Can be overridden at any level

- [WCAG 2.1 Visual Presentation](https://www.w3.org/WAI/WCAG21/Understanding/visual-presentation.html) - Guidelines for preview content
  - Text should be representative of actual usage
  - Previews should show common UI patterns

### Gotchas and Pitfalls

- ⚠️ **CSS variable scoping**: Preview must create isolated scope using container with inline styles. Cannot modify document root or it will affect actual UI.

- ⚠️ **Theme mode for palette generation**: `generatePalette(hsl, theme)` requires theme mode ('light' or 'dark'). Must call twice with different modes for dual preview.

- ⚠️ **Performance with rapid updates**: Color picker onChange fires rapidly during drag. Must debounce palette generation to avoid performance issues. Recommend 100-150ms debounce.

- ⚠️ **Semantic colors are theme-independent**: `generateSemanticColors()` returns same colors regardless of theme mode. These are platform-defined, not brand-color dependent.

- ⚠️ **Preview isolation**: Preview must not affect actual UI. Use shadow DOM or iframe for complete isolation, OR ensure CSS variables are scoped to preview container only.

### User Journey

1. **Initial State** - Preview shows default blue brand color
   - Two preview cards displayed side-by-side (desktop) or stacked (mobile)
   - Left card shows light theme preview
   - Right card shows dark theme preview
   - Both show common UI elements with current brand color

2. **User Adjusts Color Picker** - Real-time updates
   - As user drags color picker, preview updates after short debounce (150ms)
   - Both light and dark previews regenerate with new color
   - Smooth transition between colors (CSS transitions on color changes)
   - User can see how color looks in both themes simultaneously

3. **Contrast Issues Visible** - Preview highlights problems
   - If color has poor contrast, it's immediately visible in preview
   - Buttons may appear washed out or hard to read
   - User can adjust before applying

4. **User Types HEX Value** - Preview updates on valid input
   - As user types valid HEX code, preview updates
   - Invalid HEX codes don't trigger preview updates
   - Preview stays stable during typing

5. **User Applies Color** - Preview becomes actual theme
   - User clicks "Apply Color" in ColorPicker
   - Actual UI updates to match preview
   - Preview continues showing current state

### Error Handling Strategy

**Error Types:**

1. **HEX to HSL Conversion Failure**
   - Handling: Try-catch around `convertHexToHSL()`
   - Display: Error state in preview: "Invalid color format"
   - Recovery: Show fallback content, log error

2. **Palette Generation Failure**
   - Handling: Try-catch around `generatePalette()`
   - Display: Error state in preview: "Unable to generate palette"
   - Recovery: Show fallback content, log error

3. **Invalid previewColor Prop**
   - Handling: Validate prop format before processing
   - Display: No update to preview, keep previous valid preview
   - Recovery: Wait for valid color input

**Error Display Pattern:**
```typescript
// Error state component
function PreviewError({ message }: { message: string }) {

        <p className="mt-2 text-sm text-muted-foreground">{message}</p>
      </div>
    </div>
  );
}
```
