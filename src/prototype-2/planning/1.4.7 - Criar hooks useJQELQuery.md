# Task Plan: 1.4.7 - Criar hooks useJQELQuery

## Context and Objective

**What:** Create frontend React hooks that encapsulate JQEL SELECT queries using TanStack Query, providing a type-safe, consistent interface for data fetching across the application.

**Why:** Tasks 1.4.1-1.4.6 completed the backend JQEL endpoint infrastructure. The frontend already has TanStack Query configured (QueryClientProvider in main.tsx), but lacks standardized hooks for JQEL queries. Currently, components like `usePortalConfig` manually implement TanStack Query with JQEL, leading to code duplication and inconsistent patterns. This task creates reusable hooks that abstract the integration between JQEL (data language) and TanStack Query (state management), following SPEC-DA-TQ-001:015.

**How it integrates:** These hooks wrap the existing `jqelQuery` function (from `services/jqel/client.ts`) with TanStack Query's `useQuery` hook, providing automatic caching, refetching, loading states, and error handling. They enforce consistent query key patterns, retry logic, and type safety. The hooks integrate with the QueryClient configured in main.tsx and prepare the foundation for mutation hooks (task 1.4.8) and cache invalidation (task 1.4.9).

**Business value:** Developers can fetch data with a single hook call, getting loading states, error handling, caching, and automatic refetching without manual implementation. This reduces bugs, accelerates development, and ensures consistent data access patterns across all modules.

**User impact:** Faster page loads through intelligent caching, automatic background refetching for fresh data, optimistic UI updates during loading states, and graceful error recovery - all invisible to users but significantly improving perceived performance and reliability.

### Gotchas and Pitfalls

**1. JResult format mismatch:**
- ⚠️ Frontend types/jqel.ts currently uses `success/error` format
- ⚠️ Backend types/jqel.types.ts uses `code/message/data` format (correct per SPEC)
- **Solution:** Update frontend types to match backend before implementing hooks

**2. TanStack Query v5 breaking changes:**
- ⚠️ `cacheTime` renamed to `gcTime` (garbage collection time)
- ⚠️ `useQuery` return type changed - `isLoading` vs `isPending` vs `isFetching`
- **Solution:** Use `gcTime` in options, understand distinction:
  - `isPending`: No data yet (initial load)
  - `isFetching`: Query is running (could be background refetch)
  - `isLoading`: isPending && isFetching (loading for first time)

**3. Query key serialization:**
- ⚠️ Query keys must be JSON-serializable (no functions, Date objects as strings)
- ⚠️ Order matters: `{a: 1, b: 2}` ≠ `{b: 2, a: 1}` (use consistent ordering)
- **Solution:** Use `as const` for static keys, serialize complex objects

**4. WHERE operator format:**
- ⚠️ Backend expects `{ field: { $eq: value } }` (with $ prefix per SPEC-JQEL-WHE-004)
- ⚠️ Current portalQueries.ts uses `{ field: { $eq: value } }` (correct)
- **Solution:** Maintain $ prefix for all WHERE operators

**5. Data vs data array:**
- ⚠️ SPEC-JQEL-RES-013: `data` is ALWAYS array, even for single record
- ⚠️ Components expect single objects (Portal, not Portal[])
- **Solution:** Extract first item `data[0]` in query function, not in hook

**6. Error retry strategy:**
- ⚠️ Don't retry 4xx errors (client errors - won't succeed on retry)
- ⚠️ Do retry 5xx errors (server errors - might be transient)
- **Solution:** Custom retry function per SPEC-DA-ERR-004:005

```typescript
import type { JResult } from '../../types/jqel';

/**
 * JQEL Error - Wraps JResult errors with typed structure
 * Based on SPEC-DA-W-009:011
 */
export class JQELError extends Error {
  code: number;
  field?: string;
  jresult: JResult;

  constructor(jresult: JResult) {
    super(jresult.message || 'JQEL query failed');
    this.name = 'JQELError';
    this.code = jresult.code;
    this.field = jresult.field;
    this.jresult = jresult;

    // Maintain proper stack trace (V8 only)
    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, JQELError);
    }
  }

  /**
   * Check if error is validation error (400)
   */
  isValidationError(): boolean {
    return this.code === 400;
  }

  /**
   * Check if error is authentication error (401/403)
   */
  isAuthError(): boolean {
    return this.code === 401 || this.code === 403;
  }

  /**
   * Check if error is not found (404)
   */
  isNotFound(): boolean {
    return this.code === 404;
  }

  /**
   * Check if error is conflict (409)
   */
  isConflict(): boolean {
    return this.code === 409;
  }

  /**
   * Check if error is server error (5xx)
   */
  isServerError(): boolean {
    return this.code >= 500 && this.code < 600;
  }
}

/**
 * Type guard to check if error is JQELError
 */
export function isJQELError(error: unknown): error is JQELError {
  return error instanceof JQELError;
}

/**
 * Parse HTTP Response into JQELError
 * Handles both success and error responses
 */
export async function parseJQELResponse<T>(response: Response): Promise<T[]> {
  const jresult: JResult<T> = await response.json();

  // SPEC-JQEL-RES-003:005: Use code field to determine success/failure
  if (jresult.code >= 400) {
    throw new JQELError(jresult);
  }

  // SPEC-JQEL-RES-013: data is ALWAYS array
  return jresult.data || [];
}
```

#### Step 6: Implement useJQELQuery Hook
**File:** `frontend/src/services/jqel/hooks/useJQELQuery.ts` (NEW)

**Implementation:**
```typescript
import { useQuery } from '@tanstack/react-query';
import type { JQELQuery } from '../../../types/jqel';
import { jqelQuery } from '../client';
import { jqelKeys } from '../queryKeys';
import type { UseJQELQueryOptions, UseJQELQueryResult } from './types';
import type { JQELError } from '../errors';

/**
 * Smart retry function - don't retry client errors
 * Based on SPEC-DA-ERR-004:005
 */
function shouldRetry(failureCount: number, error: JQELError): boolean {
  // Don't retry client errors (4xx) - they won't succeed
  if (error.code >= 400 && error.code < 500) {
    return false;
  }

  // Retry server errors (5xx) up to 3 times
  if (error.code >= 500) {
    return failureCount < 3;
  }

  // Default: retry up to 3 times
  return failureCount < 3;
}

/**
 * Default options for JQEL queries
 * Based on SPEC-DA-PERF-003
 */
const DEFAULT_OPTIONS: Partial<UseJQELQueryOptions<any>> = {
  staleTime: 5 * 60 * 1000,        // 5 minutes
  gcTime: 10 * 60 * 1000,          // 10 minutes
  refetchOnWindowFocus: false,
  retry: shouldRetry,
};

/**
 * Execute JQEL SELECT query with TanStack Query
 *
 * Based on SPEC-DA-TQ-001:015
 *
 * @example
 * // Fetch single portal
 * const { data: portal, isLoading } = useJQELQuery<Portal>({
 *   schema: 'backend',
 *   select: 'portal',
 *   where: { portalId: { $eq: 'main' } },
 * }, {
 *   select: (data) => data[0], // Extract first item
 * });
 *
 * @example
 * // Fetch list of portals
 * const { data: portals, error } = useJQELQuery<Portal>({
 *   schema: 'backend',
 *   select: 'portal',
 *   output: ['portalId', 'name', 'activeModules'],
 * });
 *
 * @param query - JQEL query object
 * @param options - TanStack Query options (optional)
 */
export function useJQELQuery<T = any>(
  query: JQELQuery,
  options?: UseJQELQueryOptions<T>
): UseJQELQueryResult<T> {

  // Generate query key from query structure
  const queryKey = options?.queryKey || generateQueryKey(query);

  // Execute query with TanStack Query
  const result = useQuery<T[], JQELError>({
    queryKey,
    queryFn: () => jqelQuery<T>(query),
    ...DEFAULT_OPTIONS,
    ...options,
  });

  // Return simplified interface
  return {
    data: result.data?.[0] ?? null, // Extract first item by default
    isLoading: result.isLoading,
    isFetching: result.isFetching,
    error: result.error ?? null,
    refetch: result.refetch,
    isSuccess: result.isSuccess,
    isError: result.isError,
    isPending: result.isPending,
  };
}

/**
 * Generate query key from JQEL query structure
 * Based on SPEC-DA-TQ-005:009
 */
function generateQueryKey(query: JQELQuery): readonly unknown[] {
  const { schema, select, mutate, where, options: queryOptions } = query;

  const entity = select || mutate;
  const baseKey = jqelKeys.entity(schema, entity!);

  // Add where clause if present (for list queries)
  if (where) {
    return [...baseKey, 'list', where] as const;
  }

  // Add options if present (for pagination/sorting)
  if (queryOptions) {
    return [...baseKey, 'list', queryOptions] as const;
  }

  // Base entity key (all records)
  return baseKey;
}
```

**Pattern:** Wraps TanStack Query useQuery with JQEL-specific logic

**Key features:**
- Auto-generates query keys from query structure
- Smart retry (no retry on 4xx)
- Extracts first item by default (single record queries)
- Type-safe with generics

**Validation:**
```typescript

  schema: 'backend',
  select: 'portal',
  where: { portalId: { $eq: 'main' } },
});
// data should be Portal | null (not Portal[])
```

#### Step 7: Implement useJQELQueries Hook (Parallel Queries)
**File:** `frontend/src/services/jqel/hooks/useJQELQueries.ts` (NEW)

**Implementation:**
```typescript
import { useQueries } from '@tanstack/react-query';
import { jqelQuery } from '../client';
import type { JQELError } from '../errors';
import type { JQELQueryConfig, UseJQELQueryResult } from './types';

/**
 * Execute multiple JQEL queries in parallel
 * Based on SPEC-DA-TQ-014:015 (dependent queries)
 *
 * @example
 * const [portalsResult, modulesResult] = useJQELQueries([
 *   {
 *     query: { schema: 'backend', select: 'portal' },
 *   },
 *   {
 *     query: { schema: 'backend', select: 'module' },
 *   },
 * ]);
 *
 * @param queries - Array of query configurations
 */
export function useJQELQueries<T = any>(
  queries: JQELQueryConfig<T>[]
): UseJQELQueryResult<T>[] {

  // Execute all queries in parallel with useQueries
  const results = useQueries({
    queries: queries.map(({ query, options }) => ({
      queryKey: generateQueryKey(query),
      queryFn: () => jqelQuery<T>(query),
      ...options,
    })),
  });

  // Transform to simplified interface
  return results.map(result => ({
    data: result.data?.[0] ?? null,
    isLoading: result.isLoading,
    isFetching: result.isFetching,
    error: result.error ?? null,
    refetch: result.refetch,
    isSuccess: result.isSuccess,
    isError: result.isError,
    isPending: result.isPending,
  }));
}

/**
 * Generate query key (same as useJQELQuery)
 */
function generateQueryKey(query: any): readonly unknown[] {
  // Implementation identical to useJQELQuery
  // (Could be extracted to shared utility)
  const { schema, select, mutate, where, options } = query;
  const entity = select || mutate;

  if (where) return [schema, entity, 'list', where] as const;
  if (options) return [schema, entity, 'list', options] as const;
  return [schema, entity] as const;
}
```

**Pattern:** Wraps TanStack Query useQueries for parallel execution

**Use case:** Load multiple independent queries simultaneously (portals + modules + instances)

### Error Handling Strategy

**Error Types:**

1. **Network Errors** (fetch fails)
   - Cause: No internet, server down, CORS issues
   - Handling: TanStack Query retry with exponential backoff
   - Display: "Unable to reach server. Retrying..."

2. **Validation Errors** (400)
   - Cause: Invalid query structure, missing required fields
   - Handling: No retry (won't succeed)
   - Display: Show `error.message` and `error.field` inline

3. **Authentication Errors** (401/403)
   - Cause: Missing/expired JWT, insufficient permissions
   - Handling: No retry, redirect to login
   - Display: "Session expired. Please log in again."

4. **Not Found Errors** (404)
   - Cause: Entity/record doesn't exist
   - Handling: No retry
   - Display: "Record not found" or empty state

5. **Server Errors** (5xx)
   - Cause: Backend crash, n8n timeout, database unavailable
   - Handling: Retry up to 3 times with backoff
   - Display: "An error occurred. Retrying..." then "Service temporarily unavailable"

**Error Display Pattern:**

```typescript
// In component:
const { data, isLoading, error } = useJQELQuery<Portal>({ ... });

if (error) {
  if (error.isValidationError()) {
    return <InlineError message={error.message} field={error.field} />;
  }

  if (error.isAuthError()) {
    // Redirect to login (handled by AuthProvider)
    return null;
  }

  if (error.isNotFound()) {
    return <NotFound entity="Portal" />;
  }

  // Generic error
  return <ErrorState message={error.message} onRetry={refetch} />;
}
```

**Pattern:** See `frontend/src/components/common/ErrorState.tsx` for error display components
