# Task Plan: 1.10.4 - Implementar controle granular de permissões

## Context and Objective

This task implements granular permission control for JQEL queries as part of SISTEMA 1.10 (Canais e Acesso), integrating authorization checks into the data access layer to enforce fine-grained access control at the query level.

**What will be implemented:**
- JQEL authorization middleware that checks permissions before query execution
- Integration with existing `/api/1/auth/authorize` endpoint
- Schema-based permission requirements (backend, platform, application)
- Entity-level and operation-level permission checking
- Permission caching to minimize authorization overhead
- Context enrichment for permission validation (extract JWT from request)
- Bypass mechanism for public/unauthenticated queries (configurable per schema)
- Support for field-level permissions (output/except based on user permissions)
- Integration with existing parameter validation (task 1.10.3)

**Why it's needed:**
Currently, JQEL queries execute without authorization checks. Any authenticated user can query any schema/entity regardless of their actual permissions. This creates significant security gaps:
- Users can access sensitive data they shouldn't see (e.g., admin-only portals)
- Users can perform mutations (insert/update/delete) without proper authorization
- No audit trail of who accessed what data
- No enforcement of role-based access control (RBAC)

Granular permission control ensures:
- **Security:** Only authorized users can access specific data and operations
- **Compliance:** Audit trail of data access for regulatory requirements
- **Data governance:** Enforce organizational policies on data access
- **Multi-tenancy:** Users only see data relevant to their realm/organization

**How it integrates:**
- Runs AFTER parameter validation (task 1.10.3) but BEFORE query processing
- Uses existing auth system (SISTEMA 1.3 - task 1.3.5 /auth/authorize endpoint)
- Extracts JWT from Authorization header and validates with jwtService
- Builds permission string from JQEL query (schema, operation, entity, action)
- Calls /auth/authorize to check permission, leveraging Redis cache
- Enriches query context with userId for audit logging

**Business value:**
Protects sensitive business data from unauthorized access, reduces security incidents, and enables compliance with data protection regulations (GDPR, SOC2, etc.). Provides foundation for advanced features like row-level security and dynamic data masking.

**User impact:**
Users only see data they're authorized to access, preventing confusion and potential misuse. Clear error messages when access is denied help users understand permission boundaries. Administrators can grant/revoke granular permissions without code changes.

```typescript
function extractAndValidateJWT(req: Request): { userId: string; jwt: string } | null {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return null;

      jwt: token,
```

### Gotchas and Pitfalls

**Public vs Private Schemas:**
- ⚠️ NOT all schemas require authentication (e.g., public data)
- ⚠️ Configuration must specify which schemas require auth
- ⚠️ Backend schema ALWAYS requires authentication (platform config is sensitive)
- ⚠️ Application schemas may be public or private (configurable)

**Permission Granularity:**
- ⚠️ SELECT operations: Check `select.{entity}` permission
- ⚠️ MUTATE operations: Check `mutate.{entity}.{action}` permission
- ⚠️ Actions include: `insert`, `update`, `delete`, custom actions
- ⚠️ Schema-level wildcards: `*` means any entity in schema (admin permission)

**Internal HTTP Calls:**
- ⚠️ Middleware calls /auth/authorize internally (loopback HTTP call)
- ⚠️ Alternative: Direct service call (skip HTTP overhead)
- ⚠️ Consider: Extracting shared logic from auth route into service
- ⚠️ Avoid: Infinite loops (authorization middleware shouldn't check itself)

**Performance Optimization:**
- ⚠️ JWT validation is LOCAL (fast, <1ms)
- ⚠️ Permission check hits Redis cache first (fast, <5ms if cached)
- ⚠️ Only uncached permissions hit n8n (~50-100ms)
- ⚠️ Cache is shared with /auth/authorize endpoint (reuse)
- ⚠️ Middleware adds ~5ms overhead for cached permissions

**Token Expiration Handling:**
- ⚠️ Middleware should return 401 if token expired (frontend will refresh)
- ⚠️ Do NOT attempt token refresh in middleware (that's frontend's job)
- ⚠️ Clear error message: "Access token has expired"

**Context Enrichment:**
- ⚠️ Middleware MUST enrich request with userId before passing to processor
- ⚠️ Attach enriched context to req object (e.g., `req.jqelContext`)
- ⚠️ Processor uses context for audit logging and row-level security

**Bypass Mechanism:**
- ⚠️ System queries (health checks, internal operations) may need to bypass auth
- ⚠️ Use special header or internal flag to skip authorization
- ⚠️ Log bypass usage for security audit

### Existing Patterns to Follow

**Authorization Flow** (from /auth/authorize endpoint):
```typescript
// Pattern from backend/src/routes/auth.routes.ts

// 1. Extract and validate JWT
const authData = extractAndValidateJWT(req);
if (!authData) {
  return res.status(401).json({
    authorized: false,
    code: 'missing_token',
    message: 'Authentication required',
  });
}

// 2. Build permission string
const permission = buildPermissionFromQuery(query);

// 3. Check cache first
const cacheKey = `schema:{${schema}}:user:${authData.userId}:perm:${permission}`;
const cached = await redisService.get(cacheKey);
if (cached === 'GRANTED') {
  // Authorized - continue
  return next();
}
if (cached === 'DENIED') {
  return res.status(403).json({
    authorized: false,
    code: 'forbidden',
    message: 'Permission denied',
  });
}

// 4. Cache miss - validate permission
const result = await checkPermission(authData.jwt, schema, permission);

// 5. Cache result
await redisService.set(cacheKey, result.authorized ? 'GRANTED' : 'DENIED', 300);

// 6. Return or continue
if (!result.authorized) {
  return res.status(403).json({
    authorized: false,
    code: 'forbidden',
    message: 'Permission denied',
  });
}

// Enrich context and continue
req.jqelContext = {
  userId: authData.userId,
  jwt: authData.jwt,
  ipAddress: req.ip,
  userAgent: req.get('user-agent'),
};
next();
```

```typescript
// backend/src/config/permissionRules.ts

export interface PermissionRules {
  /** Whether this schema requires authentication */
  requireAuth: boolean;

  /** Optional: List of entities that are public even if schema requires auth */
  publicEntities?: string[];

  /** Optional: List of entities that always require authentication */
  protectedEntities?: string[];
}

/**
 * Schema-specific permission requirements
 *
 * SPEC References:
 * - SPEC-DA-AUTH-001:004: Queries can require authentication
 * - SPEC-DA-PERM-001:005: Queries can require specific permissions
 */
const permissionRules: Record<string, PermissionRules> = {
  /**
   * Backend schema: ALWAYS requires authentication
   * Contains platform configuration (portals, modules, instances)
   */
  backend: {
    requireAuth: true,
    // No public entities - all backend operations require admin permissions
  },

  /**
   * Platform schema: Requires authentication
   * General platform operations, user management, etc.
   */
  platform: {
    requireAuth: true,
    // Optional: Some entities might be public (e.g., public documentation)
    publicEntities: [],
  },

  /**
   * System schema: Requires authentication
   * System-level operations and configurations
   */
  system: {
    requireAuth: true,
  },

  /**
   * Default rules for application schemas
   * Application schemas are public by default unless overridden
   */
  default: {
    requireAuth: false,
    // Application-specific schemas may have protected entities
    // This can be overridden per schema in future
  },
};

/**
 * Get permission rules for a schema
 */
export function getPermissionRules(schema: string): PermissionRules {
  // Check for exact match first
  if (permissionRules[schema]) {
    return permissionRules[schema];
  }

  // Fall back to default
  return permissionRules.default;
}

/**
 * Check if schema requires authentication
 */
export function requiresAuthentication(schema: string): boolean {
  const rules = getPermissionRules(schema);
  return rules.requireAuth;
}

/**
 * Check if entity is public within a schema
 */
export function isPublicEntity(schema: string, entity: string): boolean {
  const rules = getPermissionRules(schema);

  // If schema doesn't require auth, all entities are public
  if (!rules.requireAuth) {
    return true;
  }

  // If schema requires auth, check public entity list
  if (rules.publicEntities && rules.publicEntities.includes(entity)) {
    return true;
  }

  // Otherwise, entity requires auth
  return false;
}

export default permissionRules;
```

#### Step 2: Create Permission Builder Utility
- Create: `backend/src/utils/permissionBuilder.ts`
- Implement permission string builder
- Follow auth/authorize permission format

**Implementation:**
```typescript
// backend/src/utils/permissionBuilder.ts

import type { JQELQuery } from '../types/jqel.types.js';

/**
 * Permission Builder Utilities
 *
 * Build permission strings from JQEL queries following the format:
 * {operation}.{entity}[.{action}]
 *
 * SPEC References:
 * - SPEC-AU-AZ-009:013: Permission format specification
 * - SPEC-DA-PERM-003: Permission based on schema, entity, action
 */

/**
 * Build permission string from JQEL query
 *
 * Format: "{operation}.{entity}[.{action}]"
 *
 * Examples:
 * - SELECT query: "select.users"
 * - MUTATE with action: "mutate.orders.approve"
 * - MUTATE insert: "mutate.orders.insert"
 *
 * @param query - JQEL query object
 * @returns Permission string
 */
export function buildPermissionFromQuery(query: JQELQuery): string {
  // Determine operation (select or mutate)
  const operation = query.select ? 'select' : 'mutate';

  // Get entity name
  const entity = query.select || query.mutate;
  if (!entity) {
    throw new Error('Query must have select or mutate field');
  }

  // Get action (for mutations only)
  const action = query.action;

  // Build permission string
  // Format: {operation}.{entity}[.{action}]
  if (operation === 'mutate' && action) {
    return `${operation}.${entity}.${action}`;
  }

  return `${operation}.${entity}`;
}

/**
 * Parse permission string into components
 *
 * Useful for debugging and logging.
 *
 * @param permission - Permission string (e.g., "select.users")
 * @returns Object with operation, entity, action
 */
export function parsePermission(permission: string): {
  operation: string;
  entity: string;
  action?: string;
} {
  const parts = permission.split('.');

  if (parts.length < 2) {
    throw new Error(`Invalid permission format: ${permission}`);
  }

  return {
    operation: parts[0],
    entity: parts[1],
    action: parts[2],
  };
}

/**
 * Check if permission is a wildcard (admin permission)
 *
 * @param permission - Permission string
 * @returns True if wildcard permission
 */
export function isWildcardPermission(permission: string): boolean {
  return permission === '*' || permission.endsWith('.*');
}
```

**Implementation:**
```typescript
// backend/src/middleware/jqelAuthorization.middleware.ts

import { Request, Response, NextFunction } from 'express';
import axios from 'axios';
import { jwtService } from '../services/jwt.service.js';
import { redisService } from '../services/redis.service.js';
import { config } from '../config/env.js';
import { requiresAuthentication } from '../config/permissionRules.js';
import { buildPermissionFromQuery } from '../utils/permissionBuilder.js';
import type { JQELQuery, JqelContext } from '../types/jqel.types.js';
import type { JwtPayload } from '../types/auth.types.js';

// Extend Express Request to include jqelContext
declare global {
  namespace Express {
    interface Request {
      jqelContext?: JqelContext;
    }
  }
}

/**
 * JQEL Authorization Middleware
 *
 * Enforces permission checks before JQEL query execution.
 *
 * SPEC References:
 * - SPEC-DA-AUTH-001:007: Queries can require authentication and authorization
 * - SPEC-DA-PERM-001:008: Permission validation based on schema, entity, action
 * - SPEC-AU-AZ-014:036: Authorization flow with caching
 *
 * Flow:
 * 1. Check if schema requires authentication
 * 2. Extract and validate JWT from Authorization header
 * 3. Build permission string from query
 * 4. Check Redis cache for permission decision
 * 5. If cache miss, validate permission via /auth/authorize
 * 6. Cache result and return authorization decision
 * 7. Enrich request context with userId for processors
 */
export const jqelAuthorizationMiddleware = async (
  req: Request,
  res: Response,
  next: NextFunction
): Promise<void> => {
  const query = req.body as JQELQuery;

  try {
    // STEP 1: Check if schema requires authentication
    if (!requiresAuthentication(query.schema)) {
      console.log(`ℹ️  Schema '${query.schema}' does not require authentication - skipping authorization`);

      // Still enrich context with request metadata (no userId)
      req.jqelContext = {
        ipAddress: req.ip,
        userAgent: req.get('user-agent'),
      };

      return next();
    }

    // STEP 2: Extract JWT from Authorization header
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
      res.status(401).json({
        code: 401,
        message: 'Authentication required. Please provide a valid access token.',
      });
      return;
    }

    const jwt = authHeader.substring(7);

    // STEP 3: Validate JWT locally (fast check)
    let payload: JwtPayload;
    try {
      payload = jwtService.verifyAccessToken(jwt);

      if (!payload.sub) {
        res.status(401).json({
          code: 401,
          message: 'Invalid access token: missing user ID',
        });
        return;
      }
    } catch (error: any) {
      // JWT validation failed
      if (error.message === 'Token expired') {
        res.status(401).json({
          code: 401,
          message: 'Access token has expired. Please refresh your token.',
        });
        return;
      }

      res.status(401).json({
        code: 401,
        message: 'Invalid access token',
      });
      return;
    }

    const userId = payload.sub;

    // STEP 4: Build permission string from query
    let permission: string;
    try {
      permission = buildPermissionFromQuery(query);
    } catch (error: any) {
      res.status(400).json({
        code: 400,
        message: `Failed to build permission from query: ${error.message}`,
      });
      return;
    }

    console.log(`🔒 Checking permission:`, {
      userId,
      schema: query.schema,
      permission,
    });

    // STEP 5: Check Redis cache for permission decision
    const cacheKey = `schema:{${query.schema}}:user:${userId}:perm:${permission}`;

    try {
      const cached = await redisService.get(cacheKey);

      if (cached === 'GRANTED') {
        console.log(`✅ Permission granted (cached):`, { userId, permission });

        // Enrich context and continue
        req.jqelContext = {
          userId,
          jwt,
          ipAddress: req.ip,
          userAgent: req.get('user-agent'),
        };

        return next();
      }

      if (cached === 'DENIED') {
        console.log(`❌ Permission denied (cached):`, { userId, permission });

        res.status(403).json({
          code: 403,
          message: 'Permission denied',
          required_permission: permission,
        });
        return;
      }
    } catch (error) {
      // Redis error - log but continue (don't block on cache failure)
      console.warn('⚠️  Redis cache read failed in jqelAuthorization:', error);
    }

    // STEP 6: Cache miss - validate permission via /auth/authorize
    try {
      // Internal HTTP call to /auth/authorize
      // Alternative: Direct service call (more efficient, but requires refactoring)
      const backendUrl = config.backendUrl || 'http://localhost:3000';
      const authResponse = await axios.post(
        `${backendUrl}/api/1/auth/authorize`,
        {
          access_token: jwt,
          schema: query.schema,
          permission,
        },
        {
          headers: {
            'Content-Type': 'application/json',
          },
          timeout: 5000, // 5 second timeout
        }
      );

      const isGranted = authResponse.data.authorized === true;

      // STEP 7: Cache the result
      try {
        await redisService.set(
          cacheKey,
          isGranted ? 'GRANTED' : 'DENIED',
          300 // 5 minutes TTL (SPEC-AU-AZ-036)
        );
      } catch (error) {
        // Redis error - log but don't fail request
        console.warn('⚠️  Redis cache write failed in jqelAuthorization:', error);
      }

      // STEP 8: Return authorization decision
      if (isGranted) {
        console.log(`✅ Permission granted:`, { userId, permission });

        // Enrich context and continue
        req.jqelContext = {
          userId,
          jwt,
          ipAddress: req.ip,
          userAgent: req.get('user-agent'),
        };

        return next();
      } else {
        console.log(`❌ Permission denied:`, { userId, permission });

        res.status(403).json({
          code: 403,
          message: 'Permission denied',
          required_permission: permission,
        });
        return;
      }
    } catch (error: any) {
      console.error('❌ Error calling /auth/authorize:', error);

      // Authorization service errors
      if (error.code === 'ECONNREFUSED') {
        res.status(500).json({
          code: 500,
          message: 'Authorization service is unavailable',
        });
        return;
      }

      if (error.code === 'ETIMEDOUT') {
        res.status(500).json({
          code: 500,
          message: 'Authorization request timed out',
        });
        return;
      }

      // Other errors
      res.status(500).json({
        code: 500,
        message: 'An unexpected error occurred during authorization',
      });
      return;
    }
  } catch (error) {
    console.error('❌ Unexpected error in jqelAuthorization:', error);
    res.status(500).json({
      code: 500,
      message: 'Internal authorization error',
    });
  }
};
```

### Error Handling Strategy

**Error Types:**
- **Missing Token:** No Authorization header → 401 Unauthorized
- **Invalid Token:** JWT signature invalid or malformed → 401 Unauthorized
- **Expired Token:** JWT expired → 401 Unauthorized (frontend should refresh)
- **Permission Denied:** Valid token but lacks required permission → 403 Forbidden
- **Auth Service Unavailable:** Cannot reach /auth/authorize → 500 Internal Error
- **Redis Error:** Cache read/write fails → Log warning, continue (degrade gracefully)

**Error Display Pattern:**
```typescript
// 401 - Unauthorized
{
  code: 401,
  message: string  // Specific reason (missing token, expired, invalid)
}

// 403 - Forbidden
{
  code: 403,
  message: "Permission denied",
  required_permission: string  // What permission was required
}

// 500 - Internal Error
{
  code: 500,
  message: string  // Service unavailable, timeout, unexpected error
}
```

**Graceful Degradation:**
- If Redis fails, continue without caching (don't block authorization)
- If /auth/authorize times out, return 500 (don't assume granted/denied)
- Log all errors for monitoring and debugging
